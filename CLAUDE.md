## Идея проекта
Я хочу написать приложение для ведение тренировок. Но это будет в игровом стиле.
С каждой проведенной тренировкой повышается уровень пользователя. 
Система ачивок. Уведомления.

### Упражнения
Пользотель должен иметь возможность добавлять редактировать и удалять упражнения
У каждого упраженения будут категории. На какую группу мышц они распространяются

### Тренировки
Перед тем как начать тренировку пользователья набирает перечень упражнений, которые он хочет выполнить за свой тренировочный день.
в упражнении указывается вес и кол-во повторений
и так несколько подходов, колличество подходов неогрниченно и можно его добавлять без ограничений.

Также после выбора набора упраженений пользователь должен запусти тренировку. И тем самым расчитывать сколько времени ушло на тренировку после завершении тренировки.

Также должен быть еще таймер динамически настраиваемый кторый можно заапускать после подхода

#### Таймер отдыха
- Между подходами (динамический, задаётся в упражнении).
- Обратный отсчёт с уведомлением (звук + вибрация + push).
- Работа в фоне / при заблокированном экране → Web Workers + Notification API или Service Worker.
- Возможность +15 сек / -15 сек / пропустить.

#### Шаблоны тренировок и переиспользование уже прошедших тренировок
Пользователь не должен каждый раз собирать тренировку с нуля.
«Моя тренировка на грудь» → сохранить как шаблон.
Запуск шаблона в один клик.
Добавить недостающие упражнения в выбранный шаблон, его можно также сохранить
Готовые программы (Push/Pull/Legs, Full Body, 5×5).

#### Группы мышц — детализация
Будет основная группа категорий мышц:
Грудь, ноги, плечи, предплечья, икры, трицепс, бицепс, спина, трапеция, пресс

#### Прогрессия и рекомендации
Личный рекорд (PR) по каждому упражнению — отдельно 1RM, макс. вес, макс. повторы.
Подсказка «Пора увеличить вес» — если N тренировок подряд делаешь одинаково.
График прогресса по каждому упражнению (вес × время).
1RM калькулятор (формула Эпли: 1RM = вес × (1 + повторы/30)).

#### Streak (режим «в ударе») — механика
Серия — **недели подряд с 3+ тренировками** (`STREAK_WEEK_TARGET`). Неделя — пн 00:00 … вс 24:00 в `User.timeZone`, ключ — дата понедельника (`User.lastStreakWeek`). Неделя засчитывается сразу на 3-й тренировке (`applyWeekCredit` при завершении); пропущенные недели между засчитанными закрываются заморозками, иначе серия = 1; текущая неделя пропуском не считается, пока не кончилась. Тренировка задним числом (офлайн) не пересчитывает прошлые недели. Логика — чистые функции `lib/progress/weekly-streak.ts`, БД — `lib/progress/streak-db.ts` (`countWeekWorkouts`, `recomputeStreak`), тексты — `lib/progress/streak-copy.ts`. Счётчик недели для шапки — `User.weekWorkouts`/`weekWorkoutsKey`.
Заморозки: плановая раз в 4 недели (пока < 2) + `freezeReward` у ачивок (`streakw:4`+, вход 30+), копятся до 3; использованные — `StreakCoverWeek(FREEZE)` (из них — ачивка «Второе дыхание»).
Восстановление streak за награду: `restoreOffer` — серия ≥ 2 недель, только в неделю сгорания (`lastStreakWeek + заморозки + 2`) до четверга 00:00, цена `min(500, 50 + 50·серия)` XP только из прогресса текущего уровня (уровень не падает), раз до следующей засчитанной недели (`streakRestoredAt`); выкуп ставит `lastStreakWeek` на прошлую неделю и пишет `StreakCoverWeek(RESTORE)`; `restoreStreakAction`, кнопка на дашборде.
Уведомление «Не потеряй streak!» — когда тренировок не хватает на оставшиеся дни недели, с 12:00 по местному времени, раз в день (`User.streakReminderDay`, `shouldRemindStreak` в `lib/notifications/reminders.ts`).
Пересчёт серий по истории — `npm run db:migrate-streak` (после перехода с дневного streak; без него серии начнутся с нуля).

### Авторизация

- Восстановление пароля (email).
- Валидация: сложность пароля, уникальность логина/email (Zod + Prisma unique).

- Статистика — `lib/stats/queries.ts` (агрегаты одним SQL, границы дней в поясе пользователя). Графики трендов (`getTrends`): недели с понедельника, преобразования рядов — чистые функции `lib/stats/series.ts`; графики на recharts через `components/ui/chart.tsx`, у каждого скрытая таблица для скринридеров (в обёртке `div.sr-only` — таблица не сжимается до 1px и раздвигает страницу). Одна метрика — одна ось (никаких двух шкал); линии силы — токены `--series-1..3` (проверены валидатором палитры для обеих тем) + форма точки как второй канал. «Пора увеличить вес» — `lib/progress/progression.ts`: если в последней тренировке был подход с RIR 0 — подсказки нет; если во всех рабочих подходах запас (RIR) 2+ — сразу; иначе 3 последние тренировки с одинаковым рабочим весом без падения повторов → +2,5 кг (+1 кг до 20 кг). RIR (`WorkoutSet.rir`, 0…4, 4 = «4+») выбирается под выполненным рабочим подходом в редакторе, показывается как «@RIR 2» (`formatSet` в `lib/format.ts`); показывается в редакторе тренировки и на `/stats/exercises/[id]`
- Уведомления (`lib/notifications/*`): лента в БД (`Notification`, колокольчик) + Web Push (VAPID, `web-push`, service worker `public/sw.js`). Push идёт через очередь `ScheduledPush`: `notify()` можно звать внутри транзакции, отправляет фоновый тик (`runNotificationTick`) — воркер из `instrumentation.ts` каждые 5 с (`NOTIFICATIONS_WORKER=off` — выключить) или `GET /api/cron/notifications` с `CRON_SECRET` (в e2e `E2E_TEST_CLOCK=1` разрешает `?now=` — тестовые часы для напоминаний по дням недели). Отложенный push таймера отдыха — одна строка на пользователя (`key = rest:<userId>`). Настройки — `/settings`
- Рейтинг (`/leaderboard`, `lib/social/*`): недельная лига друзей + анонимный процентиль. Публичный ник `User.nickname` (уникален без учёта регистра через `nicknameKey`; логин никому не показываем), личный `friendCode` (создаётся при первом заходе, ссылка `/leaderboard?invite=CODE`). Дружба взаимная (`Friendship` PENDING → ACCEPTED; встречная заявка = сразу дружба; отказ/удаление — удаление строки), принятая дружба = согласие показывать другу ник и XP. Очки лиги — только XP за тренировки и рекорды (`XpEvent` WORKOUT_COMPLETED + PERSONAL_RECORD), неделя с понедельника в поясе смотрящего. Процентиль — среди тренировавшихся за 28 дней, при < 10 атлетов не показывается. Глобального рейтинга по объёму нет намеренно (нечестно и легко накрутить)
- Друзья и лента (`/friends`): лента = завершённые тренировки (мои + друзей с `shareActivity`), без отдельной таблицы событий — сводка берётся из `XpEvent.meta` (рекорды, ачивки без `login:*`, новый уровень, веха серии), чистое преобразование `lib/social/feed.ts` (`toFeedEntry`). `hideWeights` вырезает объём, веса упражнений и значения весовых рекордов на сервере — в браузер не уходят. Приватность применяется при чтении (действует и на прошлые тренировки). 👊 — `Kudos` (уникален на пару тренировка–пользователь); уведомление автору группируется: пока не прочитано — обновляется одно (ключ — url `/friends#w-<id>`), push только на первый. Подгрузка страниц — курсор (finishedAt, id). Управление друзьями и приглашения — на `/friends` (старые ссылки `/leaderboard?invite=` переадресуются); на дашборде — «Друзья недавно»
- Календарь (`/calendar`, `lib/plans/*`, `components/calendar/*`): планы в местном времени пользователя (`date "YYYY-MM-DD"`, `time "HH:MM"`, `durationMin`). `PlanSeries` — повтор каждую неделю в `weekday` (0 = пн) с `startDate`/`endDate`; `PlanEntry` — разовая запись или исключение из серии (`seriesId` + `originalDate`: перенос или `cancelled`). Вхождения строит чистая `expandPlans` (ключи `s:<seriesId>:<originalDate>` и `e:<entryId>`), правки «Только эту / Эту и следующие» — `planEdit` (список операций, применяет `lib/plans/actions.ts`), статусы — `matchPlans` (тренировка с `Workout.planKey` закрывает своё вхождение, без него — первое невыполненное того же местного дня, остальные — «вне плана»). Вид — в URL `?view=week|month&date=`; неделя на ПК — сетка 30-минутных слотов с перетаскиванием (`week-dnd.tsx`, пробел — перенос с клавиатуры, Enter — карточка), на телефоне — полоска дней + день. Запуск из плана — `createWorkoutAction` с `source = "plan:<key>"`. «Пропустить» план на сегодня — `skipPlanAction` (кнопка в «Сегодня по плану» и в `/training`; одно вхождение, у серии — отменённое исключение); отмена тренировки из плана по умолчанию тоже пропускает его (галочка в диалоге, `cancelWorkoutAction(id, skipPlan)`). Мутации планов от имени userId — `lib/plans/mutations.ts` (server-only, не в "use server") Карточка «Сегодня по плану» на дашборде и вариант «По плану» в `/training` — `getTodayPlan`. Напоминание за `User.planReminderMin` минут (`NotificationType.PLAN`, одно на вхождение — `PlanReminder`, выбор — `duePlanReminders`). В e2e даты календаря — фиксированные в будущем (`/calendar?date=2030-01-10`), планы можно вставлять SQL в `PlanEntry`
- Итоги недели (`/recap`, `lib/recap/*`, `components/recap/*`): снимок `WeeklyRecap` (JSON `RecapData` с `version`, уникален на пользователя и неделю), создаёт тик в пн ≥ 09:00 местного (`processWeeklyRecaps` в `runNotificationTick`) или страница/дашборд на лету (`getOrCreateRecap`: с пн 00:00, не старше 8 недель). Push — только из тика по `pushedAt`, только в понедельник и не после просмотра (`seenAt`, `shouldPushRecap`); пустая неделя после активной — один «новый старт» (`User.recapNudgeWeek`). Блоки — чистая `buildRecap` (лига через `rankLeague`, лучший подход по Эпли), текст push — `recapPushBody`; переключатель `notifyRecap`; неделя — в `User.timeZone`, как у тика. В e2e неделю готовит `seedRecapWeek` (`e2e/db.ts`), понедельник — `runTick(request, now)`; фоновый воркер тикает по реальному времени, поэтому сценарии с тестовыми часами берут недели в прошлом и не пересекаются между собой
- В e2e друзей быстрее связывать через `makeFriends` (`e2e/db.ts`); переключатели Base UI искать по роли `switch` (у скрытого input та же подпись)
- e2e push: фейковый push-сервис `e2e/push-server.ts` (HTTPS с самоподписанным сертификатом, сервер доверяет ему через `NODE_EXTRA_CA_CERTS`). Настоящий FCM — `E2E_REAL_PUSH=1 npm run test:e2e -- push-real`
