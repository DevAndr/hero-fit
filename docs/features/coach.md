# Режим тренера

Подробности фич (перенесено из CLAUDE.md). Меняешь поведение области — обнови этот файл.

- Режим тренера (спека `docs/superpowers/specs/2026-10-09-coach-clients-design.md`, этап 1 из 4: связь и просмотр; дальше — программы, комментарии, тарифы): `User.isCoach` (включается в `/settings`, только с ником, или галочкой «Я тренер» при регистрации — тогда ник обязателен в форме, код приглашения создаётся сразу, после входа — `/coach`, цели `signup` + `coach_enabled`; значение галочки — скрытым полем, т.к. сброс формы после ошибки снимает input чекбокса), `User.coachCode` (как код друга), связь `CoachLink` — активная при `endedAt = null`, у клиента одна: частичный уникальный индекс `CoachLink_active_client` в миграции (Prisma его не видит — не удалять при `migrate dev`). Приглашение — `/coach/join/<код>` → экран согласия → `acceptCoachAction` (переход к другому тренеру закрывает прежнюю связь `endedBy = "switch"`); разрыв — клиент в `/settings` («Мой тренер»), тренер в карточке клиента. Доступ — только через `requireClientOf(clientId)` (`lib/coach/access.ts`; нет связи / режим выключен → 404). Кабинет: `/coach` (список — чистые `sortClients`/`clientFlags`/`lastWorkoutLabel`, `lib/coach/clients.ts`, пояс клиента), `/coach/clients/[id]?tab=overview|workouts|stats`, тренировка и упражнение клиента — те же `WorkoutSummaryView` (`readOnly`), `StatsView`, `ExerciseProgressView`, что у своих страниц. `hideWeights` к тренеру не применяется. Уведомления `NotificationType.COACH`. В e2e — `enableCoach`/`linkCoach`/`activeCoachLinks` (`e2e/db.ts`). Публичная страница (спека `docs/superpowers/specs/2026-10-10-coach-public-page-design.md`): `CoachProfile` (1:1, `publishedAt`), `/trainer/<ник>` в группе marketing (`PUBLIC_PREFIXES` + `/trainer/`; ник — по `nicknameKey`; видна при `publishedAt` и `isCoach`, иначе 404, тренеру — предпросмотр), цифры — `getCoachPublicStats` + чистая `visibleStats` (`lib/coach/profile.ts`: по клиентам — от 3 активных, «% плана» — от 5 назначений, тренер скрывает любую), «Заниматься» → `/trainer/<ник>/join` (цель `trainer_page_join`) → гостю `/register?next=/coach/join/<код>` (регистрация и вход несут `next`, проверка — `safeRedirectPath` в `lib/auth/redirect.ts`) → экран согласия. Редактор — `/coach/page` (публикация — `canPublish`: ник и «О себе» от 50 символов, цель `coach_page_published`), JSON-LD `Person` (`coachJsonLd`), страницы — в `sitemap.xml`. В e2e — `coachProfile`. Этап 2 — назначение тренировок (спека `docs/superpowers/specs/2026-10-09-coach-programs-design.md`): назначение — обычные `PlanSeries`/`PlanEntry` клиента с `coachId` (у исключения серии не читается — принадлежность по серии; `Occurrence.coachId`, `planEdit` переносит его в новую серию), библиотека — обычные шаблоны тренера, назначение ссылается, не копирует. Доступ к шаблону для запуска — только `templateAccessible` (`lib/coach/templates.ts`: свой, встроенный или назначенный активным тренером). Назначение нескольким (спека `docs/superpowers/specs/2026-10-11-coach-assign-many-design.md`): кнопка «Назначить нескольким» на `/coach` (при 2+ клиентах, `AssignManyButton`) → тот же `AssignDialog` в режиме `many` (группа «Клиенты» с «Выбрать всех»; одинаковые имена различаются датой начала работы — чистая `clientPickLabels`, логин не показывается) → `assignManyAction` (`requireCoach`, до 50 клиентов, только активные клиенты тренера — чистая `pickClients`, остальные пропускаются; одна транзакция, по очереди `assignToClient` — общая с одиночным `assignWorkoutAction`; тост `assignManyText`). У каждого клиента своё независимое назначение, групповой связи нет. Копирование плана (спека `docs/superpowers/specs/2026-10-11-coach-copy-plan-design.md`): «Скопировать план» во вкладке «План» (есть что копировать и другие клиенты) → `CopyPlanButton` (`components/coach/copy-plan-dialog.tsx`, общий `ClientPicker` — `components/coach/client-picker.tsx`, «перезапишется N заданий», галочка «С весами») → `copyPlanAction` (`requireClientOf` источника, получатели — `pickClients` без источника, одна транзакция). Что копировать — чистая `copyPlan` (`lib/coach/plan-copy.ts`, «сегодня» — пояс источника): серии тренера с `endDate` ≥ сегодня — правило с `max(startDate, сегодня)` (исключения не переносятся, серия без вхождений — нет), разовые с сегодня не отменённые, задания по шаблонам скопированного и упражнениям из шаблона; без «С весами» вес и шаг пустые, пустое задание пропускается. Добавляется к плану получателя; задания по тем же шаблон + упражнение — upsert (`fails` 0, `unloadedAt` null). Уведомление «Новый план от тренера» (текст — `copySummary`), цель `coach_copy_plan`. Источник — `getPlanCopySource`/`getCopyRecipients` (`lib/coach/plan-copy-queries.ts`). В e2e — `coachTargetFull`. Группы клиентов (спека `docs/superpowers/specs/2026-10-11-coach-groups-design.md`): метки тренера (`CoachGroup` — `nameKey` уникален у тренера, `CoachGroupMember`; клиент — в любом числе групп, клиенту не видны), до 20 (`COACH_GROUPS_MAX`), название 1…40 — чистые `lib/coach/groups.ts` (`groupSchema`, `groupKey`, `inGroup`, `addGroup`). Управление — диалог «Группы» на `/coach` (`GroupsButton`, `components/coach/groups-dialog.tsx`) → `saveGroupAction`/`deleteGroupAction` (`lib/coach/group-actions.ts`, `requireCoach`, участники — `pickClients` по активным, состав заменяется целиком, P2002 → «Такая группа уже есть»). Чтение — `getCoachGroups` (только активные клиенты). Фильтр `/coach` — `?group=<id>` (`GroupFilter`; нет такой — все), значки — `GroupBadges` в списке и карточке. Быстрый выбор — проп `groups` у `ClientPicker` (кнопка «Отметить группу «…»» добавляет участников из списка) в «Назначить нескольким» и «Скопировать план». Разрыв связи удаляет членство (`dropAssignments`). В e2e — `coachGroupMembers`. Клиент назначенное не меняет и не перетаскивает (`updatePlanAction`/`deletePlanAction` — «Назначено тренером — изменить может только он»), может пропустить: разовая от тренера при пропуске отменяется (`cancelEntry`), а не удаляется. Тренер — вкладка «План» в карточке клиента (`lib/coach/plan-actions.ts` через `requireClientOf`, статусы — `getClientPlan`: «пропущено клиентом» — отменённое без пометки тренера; своё «удалить только эту» тренер помечает `coachId` на исключении), «план N/M» в списке. Разрыв связи (в т.ч. переход к другому тренеру) удаляет назначения прежнего тренера. Уведомления: клиенту «Новый план от тренера», тренеру «Тренировка выполнена» (`notifyCoachOnFinish` в `finishWorkout`); цель Метрики `coach_assign`. У клиента — «от тренера · <ник>» в календаре и «План на сегодня», раздел «От тренера» в `/training`. В e2e — `coachTemplate`/`coachAssignOnce`/`idOf`. Этап 3 — комментарии (спека `docs/superpowers/specs/2026-10-09-coach-comments-design.md`): `CoachComment` к завершённой тренировке клиента — общий (`workoutExerciseId = null`, один на тренировку — частичный уникальный индекс `CoachComment_workout_general` в миграции, Prisma его не видит) и по одному на упражнение (`@unique workoutExerciseId`); место занято комментарием другого (бывшего) тренера — отказ. Пишет/правит/удаляет только активный тренер (`lib/coach/comment-actions.ts` через `requireClientOf`), тренер видит свои, клиент — все (и бывших тренеров; `coachId` → null при удалении тренера — «Тренер»), открытие сводки — `markCommentsRead`. Показ — слот `renderComment` в `WorkoutSummaryView` (тренеру `CoachCommentEditor`, клиенту `CoachExerciseNote`/`CoachCommentSection`), 💬 на вкладке «Тренировки». Уведомление клиенту группируется по url `/workouts/<id>`, пока не прочитано (как 👊), push — на первое; цель Метрики `coach_comment`. В e2e после «Сохранить» ждать, что поле ввода закрылось (до ответа сервера текст ещё в поле). Задания клиенту (спека `docs/superpowers/specs/2026-10-10-coach-targets-design.md`): `CoachTarget` — подходы/повторы/вес (каждое может быть пустым) на клиента + шаблон + упражнение (связь с упражнением, не со строкой шаблона: редактор шаблона пересоздаёт строки), действует во всех назначениях шаблона. Запуск (`fromTemplate`, источники `template:`/`plan:`) — чистая `plannedSets` (`lib/coach/targets.ts`): подходы — задание → шаблон, повторы — задание → шаблон → история, вес — задание → история → шаблон; задания только у шаблона активного тренера (`getTemplateTargets`). Тренер — раздел «Задания по шаблонам» во вкладке «План» (актуальные назначенные шаблоны, `assignedWhere`; диалог с «в прошлый раз»), `saveTargetsAction` (пустая строка — удалить), цель `coach_targets`. Упражнение своим весом — вес как отягощение: в диалоге «Доп. кг», в пометке «+10 кг», 0 не показывается. Клиент — пометка «от тренера: 4 × 8 · 60 кг» в редакторе (`formatTarget`), читается страницей `/training` по `templateId`, в тренировке не хранится. Разрыв связи удаляет задания (`dropAssignments`). Прогрессия (спека `docs/superpowers/specs/2026-10-10-coach-progression-design.md`): `CoachTarget.step` (кг, 0,5…20) и `fails`; работает при заданных весе и шаге. При завершении тренировки по шаблону активного тренера (как бы ни запустили) — `applyProgression` в транзакции `finishWorkout` (`lib/coach/progression-apply.ts`), правило — чистая `progressTarget` (`lib/coach/progression.ts`): не меньше N подходов с весом ≥ задания и повторами ≥ R — вес + шаг; иначе неудача, на 3-й подряд — разгрузка `floor(вес × 0,9 / 2,5) × 2,5` и уведомление тренеру «Разгрузка: …»; без выполненных рабочих подходов — не попытка. Итог — `FinishMeta.progression` → блок «План тренера» в сводке (`progressionLine`), его видит и тренер. Повтор (`repeat:`) тренировки по шаблону тренера накладывает текущие задания на прошлые подходы. Диалог отправляет только изменённые строки (прогрессия могла сдвинуть вес, пока он открыт). Смена веса или шага в диалоге сбрасывает `fails`; шаг без веса — «Для прогрессии нужен вес». В e2e — `coachTarget`/`coachTargetCount`/`coachTargetRow`. Сигналы риска клиентов (спека `docs/superpowers/specs/2026-10-11-coach-signals-design.md`): правила — чистые `lib/coach/signals.ts` (`clientSignals` в поясе клиента: `MISSED_PLAN` — две последние прошедшие назначения тренера не выполнены/пропущены, сегодняшнее и назначенное задним числом (`assignedAt` — `createdAt` серии/записи) не пропуск; `STALLED` — задание актуально назначенного шаблона (`assignedWhere`, упражнение есть в шаблоне) с `fails ≥ 2` или `CoachTarget.unloadedAt` за 14 дней (ставит `applyProgression` при разгрузке); `ACTIVITY_DROP` — связь ≥ 42 дней, среднее за 2 недели в днях 15…42 ≥ 2, за последние 14 дней ≤ половины; `INACTIVE` — 7 дней без тренировок от более поздней из последней тренировки и связи, гасит спад; метка «7+ дней без тренировок»), данные — `getSignalInput`/`getSignalInputs` (`lib/coach/signals-queries.ts`). Список `/coach` и карточка («Требует внимания» на «Обзоре», `SignalBadge`) считают сигналы на лету; порядок — `sortClients` (больше сигналов выше, «пора увеличить вес» не сигнал). Уведомление тренеру — `processCoachSignals` в `runNotificationTick` (`lib/coach/signals-tick.ts`): раз в день с 10:00 пояса тренера, день `User.coachSignalsDay` только растёт (условный `updateMany`), бюджет ~2 с на тик (новые тренеры первыми), новые сигналы — `CoachSignal` + одно уведомление `COACH` на клиента, пропавшие — `resolvedAt`; открытый сигнал один на тренер + клиент + тип — частичный уникальный индекс `CoachSignal_open` в миграции (Prisma его не видит — не удалять при `migrate dev`); разрыв связи закрывает сигналы (`dropAssignments`). В e2e — `coachTargetSet`/`coachNotifications`/`coachSignals`/`resetCoachSignalsDay`/`setTimeZone`; тики сигналов — в реальном времени (тестовые часы на будущий понедельник запускают сборку итогов недели всей базы) Ачивки тренера (спека `docs/superpowers/specs/2026-10-12-coach-achievements-design.md`): категория `COACH`, лестницы `coachclients` (1, 3, 5, 10, 25), `coachpage:1`, `coachcomments` (1, 10, 50, 200), `coachworkouts` (10…1000), `coachprs` (10…250), `coachprog` (5, 25, 100), `coachgoals` (1, 5, 25) — пороги `COACH_LADDERS`, XP от номера ступени (`40 + 20·i`), без `isCoach` не выдаются и не показываются целями (`coachMode`). Счётчики — один SQL `coachStats` (`lib/achievements/coach-stats.ts`) из истории по окнам `CoachLink` (`createdAt`…`endedAt ?? now`): клиент — от 3 тренировок в окнах (`COACH_ACTIVE_CLIENT_WORKOUTS`), тренировки по шаблонам тренера, рекорды и прогрессия `up` (без `own`) из `XpEvent.meta`, цели `ACHIEVED`; без `isCoach` SQL не идёт. Выдача — обычная (вход, своя тренировка) + новый комментарий, первая публикация страницы и открытие `/coach` (через `quietly` — сбой выдачи не ломает страницу и действие) (страница рисует свой `AchievementToaster`, тосты не задваиваются — `id` ачивки). Титулы `ach:coachclients:25` «Наставник», `ach:coachworkouts:1000` «Кузница чемпионов», `ach:coachprs:250` «Создатель рекордов». Публичная страница — блок «Награды тренера» (`publicAwards`: одна высшая ступень на лестницу, ближе к вершине — первыми, до 6, без `coachpage:1`), переключатель «Показывать награды» (`CoachProfile.showAwards`). Значки: `first_comment` (`coachcomments`), `publish_profile` (`coachpage`), `goal` (`coachgoals` и личные `goal:N`). В e2e — `seedWorkouts(..., { templateId })`, `coachProfile({ showAwards })`
- Заметки тренера о клиенте (без флага): `CoachNote` (PK `coachId`+`clientId`, текст до 5000 — `noteTextSchema`, `lib/coach/notes.ts`), карточка «Заметки» во вкладке «Обзор» (`components/coach/coach-note.tsx`) → `saveCoachNoteAction` (`lib/coach/note-actions.ts`, `requireClientOf`; пустой после обрезки текст — удалить). Видит только тренер; клиент — только в «Мои данные» (`coachNotesAboutMe`), тренер — `clientNotes`. Разрыв связи удаляет заметку (`dropAssignments`, предупреждение в «Удалить клиента»), удаление аккаунта — каскад. `/privacy` — в разделе «Кто ещё видит данные». e2e — `e2e/coach-notes.spec.ts`.
- Программы на несколько недель (спека `docs/superpowers/specs/2026-10-16-coach-mesocycles-design.md`; без фича-флага — флаг `coach_programs` убран до выпуска): библиотека `CoachProgram` + `CoachProgramDay` (день → свой шаблон, время; длительность 60) на `/coach/programs` (ссылка на `/coach`, редактор с предпросмотром на базе 100 кг, до 30 программ — `PROGRAMS_MAX`), правило — шаг % или кг в неделю, разгрузка каждая N-я неделя −X % и −1 подход. Чистые функции — `lib/coach/program.ts` (`programWeek`, `programPreview`, `programWeekIndex`, `applyProgramToTargets`, `seriesStarts`, `lastLoadedWeight`, `shouldRemindProgramEnd`; округление 2,5 кг, база < 20 кг — 0,5; обычная неделя не ниже базы; разгрузка — от прошлой обычной недели). Назначение — «Назначить программу» во вкладке «План» (`AssignProgramButton`, 2 шага: старт с этой/следующей недели, базы — задание → последний рабочий вес → шаблон) → `assignProgramAction` (строка клиента `FOR UPDATE`, прежняя программа закрывается, снимок `ProgramAssignment` + `ProgramBase`, серии `PlanSeries.programAssignmentId` без задним числом, уведомление «Новая программа от тренера», цель `coach_program_assign`). Запуск: `getTemplateTargets(clientId, templateId, day)` накладывает вес недели (`programForTemplate`; `plan:` — дата вхождения), пометка «от тренера: … (неделя 3/8)»; `applyProgression` по шаблонам программы не работает, в сводке — «Программа: неделя 3/8» (`FinishMeta.program`). Окончание (досрочно — `endProgramAction`, новая программа, срок — в тике `processProgramReminders`, запасной путь — при чтении заданий): `endAssignment` — будущие вхождения убираются, вес последней обычной недели → `CoachTarget.weight` (`basesToWrite`: только пары, что ещё есть в шаблонах тренера, неделя базы прошла; по сроку не затирает задание, правленное после конца — `targetEditedAfterEnd`; без тренера — не пишет). Удаление аккаунта тренера закрывает его назначения. Разрыв связи закрывает назначение без записи весов. Блок «Программа» (`ProgramProgress`: неделя, разгрузка, веса этой и финальной недели, «Изменить базу» — `ProgramBase.fromWeek`, рост заново от введённого; в разгрузку — `baseForWeekWeight`), «Нед. 3/8» в списке `/coach` (`programBadges`), метки недели в календаре и «Плане на сегодня» (`programWeekLabels`), тренеру «заканчивается через неделю» (`processProgramReminders` в `runNotificationTick`, `remindedAt`). «Мои данные» — `programs` и `coachPrograms`. e2e — `e2e/coach-programs.spec.ts` (`shiftProgramStart`), удаление — `account-data.spec.ts`.
