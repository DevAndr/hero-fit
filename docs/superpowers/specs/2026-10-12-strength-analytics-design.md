# Умная аналитика прогресса: «Ты стал сильнее»

## Цель

Наглядный ответ на вопрос «Я действительно становлюсь сильнее?». Графики, рекорды, объём по неделям и карта мышц уже
есть (`/stats`, `/stats/exercises/[id]`, `/recap`, карта мышц). Новое — ядро «тренд силы» и три места, где оно видно:
блок «Ты стал сильнее» в итогах недели (+ push), карточка «Месяц к месяцу» в `/stats`, прогноз целей по динамике.

Тон — без демотивации: в отчёт попадают только «сильнее» и «держишь уровень», слово «спад» и минусы не показываются.

## Решения

### Ядро: тренд силы

**Данные.** Один SQL `exerciseWeekBests(userId, timeZone, since)` (`lib/stats/strength-queries.ts`): по каждому
упражнению и неделе (понедельник, пояс пользователя, по `finishedAt` завершённых тренировок) — из рабочих выполненных
подходов (`isWarmup = false`, `completedAt` не null, `reps > 0`):
- `oneRm` — max Эпли (`reps = 1` → вес, иначе `weight × (1 + reps/30)`) среди подходов с `weight > 0` и `reps ≤ 12`;
- `maxWeight` — max веса, `maxReps` — max повторов в подходе;
- `sessions` — число разных тренировок; `bodyweight` — `Exercise.isBodyweight`; `name`.

Тип `WeekBest = { exerciseId; name; bodyweight: boolean; week: string; oneRm: number | null; maxWeight: number; maxReps: number; sessions: number }`.

**Сравнение** — чистая `strengthTrend(rows: WeekBest[], now: { recent: string[]; before: string[] })`
(`lib/stats/strength.ts`), окна — списки недель (ключи понедельников). Для недели: «сейчас» — 4 недели, заканчивающиеся
текущей, «раньше» — 4 перед ними (`trendWindows(weekKey)`).
- Значение упражнения в окне — лучшее недельное: `oneRm` (с весом), `maxReps` (свой вес; упражнение без `oneRm` во всех
  неделях окна — тоже по повторам).
- Участвует, если в каждом окне `Σ sessions ≥ 2` (`TREND_MIN_SESSIONS`) и значение есть в обоих окнах.
- Вердикт: с весом — `pct = (сейчас − раньше) / раньше`; «сильнее» при `pct ≥ 0,01`, «держишь» при `pct ≥ −0,03`,
  иначе «спад» (не показывается). Свой вес — «сильнее» при `+1` повтор и больше, «держишь» при `≥ −1`.
- Итог: `StrengthTrend = { stronger: number; of: number; top: TrendItem[] }`, `of` — число участвующих упражнений
  (включая «спад»), `top` — до 3 «сильнее» по убыванию `pct` (свой вес — `pct` от повторов), при равенстве — по имени.
  `TrendItem = { exerciseId; name; bodyweight; from; to; pct }` (`from`/`to` — 1ПМ в кг с округлением до 0,5 или повторы).
- `of = 0` — блоков нет (данных мало).

Тексты — чистые `trendHeadline(t)` («Ты стал сильнее в 4 из 6 упражнений»; `stronger = 0` — «Держишь уровень в 6
упражнениях»; склонения — `plural`) и `trendLine(item)` («Жим штанги лёжа · 1ПМ 82 → 85 кг · +4 %»; свой вес —
«Подтягивания · 9 → 11 повторов»).

### Итоги недели

- `RecapData.strength?: StrengthTrend` — `version` не меняется (поле необязательное, старые снимки без блока).
- `RecapInput.strengthWeeks: WeekBest[]` — недели с понедельника за 7 недель до недели итогов по неделю итогов
  (`loadRecapInput`); `buildRecap` вызывает `strengthTrend` с окнами недели итогов; `of = 0` — поля нет.
- `/recap`: блок «Сильнее» первым после шапки (`components/recap/strength-block.tsx`): заголовок `trendHeadline`, топ-3
  `trendLine`. Рекорды недели — существующий блок `records`, не дублируются.
- Карточка итогов на дашборде — строка «Сильнее в N из M», если `strength` есть и `stronger > 0`.
- `recapPushBody`: при `stronger > 0` — «Ты стал сильнее: жим +4 %, присед +2,5 кг. Смотри итоги недели» (до 2 из
  `top`: с весом — `+N %` с округлением до целого, если ≥ 1 %; свой вес — `+N повт.`); иначе — прежний текст. Telegram —
  тот же текст.
- `hideWeights` не влияет (итоги — личная страница). Тренеру итоги клиента не открываются.

### «Месяц к месяцу» в `/stats`

- Карточка вверху `/stats` (`components/stats/month-compare.tsx`) — «Октябрь против сентября».
- Количественные: тренировки, часы, объём, рекорды (число `meta.records` у `PERSONAL_RECORD`) — текущий месяц с 1-го
  по сегодня против **тех же дней** прошлого месяца (1…min(сегодня, длина прошлого месяца)); подпись «1–12 октября против
  1–12 сентября». Пара чисел и стрелка (рост / как было / меньше — нейтральным цветом, без красного).
- Сила: `strengthTrend` с окнами «недели, пересекающие текущий месяц до сегодня» против «недели, пересекающие прошлый
  месяц целиком»; `of = 0` — только количественные. Неделя на стыке месяцев попадает в оба окна — допустимо.
- Чистая `monthCompare(totals, trend, today)` (`lib/stats/month.ts`) — подписи и числа; данные — `getMonthCompare(userId,
  timeZone)` (`lib/stats/strength-queries.ts`).
- Та же карточка — у тренера во вкладке «Статистика» клиента (общий `StatsView`).

### Прогноз целей

- Только `STRENGTH` (метрики `ONE_RM`, `MAX_WEIGHT`, `MAX_REPS`) и `BODY_WEIGHT`; у остальных — прежний `paceStatus`.
- Ряд — 8 недель: силовая — лучшее недельное по метрике цели (`oneRm` / `maxWeight` / `maxReps` из `exerciseWeekBests`
  по упражнению цели); вес тела — `BodyWeightEntry` (последняя запись недели).
- Чистая `forecastGoal({ points: { week: string; value: number }[], current, target, deadline, today, tz })`
  (`lib/goals/forecast.ts`): линейная регрессия (МНК) по номеру недели; меньше 3 точек на 3 разных неделях — `null`
  (показывается `paceStatus`). Темп к цели > 0 — дата `сегодня + (цель − текущее) / темп` недель; темп ≤ 0 (или от цели)
  — `{ kind: "stalled" }`; дата дальше 2 лет — `{ kind: "far" }`. Со сроком: дата ≤ срока — `{ kind: "onTrack", date }`,
  позже — `{ kind: "late", date, need, pace }` (`need` = `(цель − текущее) / недель до срока`, единица — кг или повторы
  в неделю). Без срока — `{ kind: "eta", date }`.
- Тексты — `forecastText`: «Успеваешь: ≈ 14 ноября», «≈ 14 ноября», «Не успеваешь к сроку: нужно +1,2 кг в неделю,
  сейчас +0,5», «Пока без роста — прогноз появится, когда пойдёт прогресс» (вес тела — «Вес пока не движется к цели»),
  «Больше 2 лет при текущем темпе». Без рода.
- Показ: `GoalCard` на `/goals` (строка вместо «отстаёшь/опережаешь», если прогноз есть), коротко в `GoalsCard` на
  дашборде (дата или «не успеваешь»), «Цели клиента» у тренера; на `/stats/exercises/[id]` — строка прогноза под «Цель —
  X» (ось графика — тренировки, а не даты: пунктир до будущей даты на ней не построить), только если метрика цели совпадает
  с показателем графика.
- Данные — `getGoalForecasts(userId, goals)` (`lib/goals/forecast-queries.ts`), один SQL по упражнениям активных
  силовых целей + журнал веса.

## Вне рамок

Индекс силы в процентах, уведомления о прогнозе, сравнение с друзьями, прогноз целей по тренировкам/часам/серии,
отдельная страница аналитики.

## Тесты

- Unit: `strengthTrend` (окна, минимум 2 тренировки в каждом окне, пороги 1 % / −3 %, свой вес, «спад» в `of`, топ-3 и
  порядок, `of = 0`), `trendHeadline`/`trendLine` (склонения), `monthCompare` (неполный месяц — те же дни, короткий
  прошлый месяц, подписи), `forecastGoal` (мало точек, темп ≤ 0, от цели, срок — успеваешь / не успеваешь, без срока,
  больше 2 лет, вес тела вниз), `recapPushBody` (с силой и без).
- e2e (`e2e/strength-analytics.spec.ts`): история в БД за 8 недель (`seedWorkouts` с ростом веса) → `/recap` прошлой
  недели с «Ты стал сильнее в N из M» и строкой топа; `/stats` — карточка «Месяц к месяцу»; силовая цель с ростом
  (`createGoal`) → «≈ …» на `/goals`.
