# Режим тренера: прогрессия в заданиях клиенту — дизайн

Дата: 2026-10-10. Продолжение заданий тренера (`2026-10-10-coach-targets-design.md`). Пока идёт бета, функция бесплатна.

## Цель

Задание тренера сейчас статично: вес не меняется, пока тренер не поправит руками. Тренер хочет вести клиента по линейной прогрессии: сделал всё — в следующий раз тяжелее, не справился — повторяем, застрял — разгрузка.

Отдельной сущности «Программа» нет: шаг прогрессии — часть задания (`CoachTarget`). Длительность и дни — назначение (например, пн/ср/пт на 8 недель).

Критерии успеха:
- тренер ставит у упражнения шаг «+2,5 кг», клиент выполнил все подходы и повторы — следующий запуск подставляет вес на 2,5 кг больше;
- не справился — тот же вес; третья неудача подряд — вес −10 % и уведомление тренеру;
- клиент сразу после тренировки видит в сводке, что будет в следующий раз.

Вне этапа: история изменений веса задания (видна по тренировкам), прогрессия по повторам, проценты от 1ПМ, настраиваемые разгрузка и число неудач (фиксировано: 3 и −10 %), отдельная сущность программы с несколькими днями.

## Данные

В `CoachTarget`:

```prisma
  /// шаг прогрессии, кг (0,5…20); null — прогрессии нет
  step  Float?
  /// неудач подряд (прогрессия)
  fails Int    @default(0)
```

- Прогрессия включена, только если у задания есть и `weight`, и `step`.
- Миграция добавляет колонки; частичные индексы (`CoachLink_active_client`, `CoachComment_workout_general`) не трогать.

## Правило

Чистая функция `progressTarget` (`lib/coach/progression.ts`):

```ts
type ProgressInput = {
  target: { sets: number | null; reps: number | null; weight: number | null; step: number | null; fails: number };
  template: { sets: number; reps: number | null };
  /** Выполненные рабочие подходы упражнения в тренировке (разминка не входит). */
  done: { weight: number; reps: number }[];
};
type ProgressResult = { weight: number; fails: number; kind: "up" | "same" | "deload"; from: number; to: number };
function progressTarget(input: ProgressInput): ProgressResult | null;
```

- нет `weight` или `step` — `null`;
- `done` пустой (упражнение убрано из тренировки или не сделано ни одного подхода) — `null`, попыткой не считается;
- нужно подходов `N = target.sets ?? template.sets`, повторов `R = target.reps ?? template.reps` (нет нигде — любые > 0);
- **успех** — среди `done` не меньше `N` подходов с весом ≥ `target.weight` и повторами ≥ `R`: `weight + step`, `fails = 0`, `kind: "up"`;
- **неудача** — иначе: `fails + 1`; если стало `3` — **разгрузка**: `floor(weight × 0,9 / 2,5) × 2,5` (не меньше 0), `fails = 0`, `kind: "deload"`; иначе вес прежний, `kind: "same"`;
- вес округляется до 0,01 (дробные шаги не копят ошибку float).

Примеры: 60 → 62,5 при успехе с шагом 2,5; разгрузка 62,5 → 55 (56,25 вниз до 2,5), 60 → 52,5 (54 вниз до 2,5), 2,5 → 0.

Константы: `DELOAD_AFTER = 3`, `DELOAD_FACTOR = 0.9`, `DELOAD_ROUND = 2.5`, шаг — 0,5…20.

## Применение

`finishWorkout` (`lib/workouts/finish.ts`), в той же транзакции, после чистки невыполненных подходов:
1. `workout.templateId` — шаблон активного тренера клиента (`CoachLink.endedAt = null`, `template.userId = coachId`); иначе ничего;
2. задания клиента по шаблону с `weight` и `step` (только упражнения, которые сейчас в шаблоне — как `getTemplateTargets`);
3. для каждого упражнения тренировки с таким заданием — `progressTarget` по рабочим выполненным подходам (`isWarmup = false`); упражнение в тренировке дважды — подходы объединяются;
4. результат ≠ `null` — `coachTarget.update({ weight, fails })`;
5. итоги — в `FinishMeta.progression: { exercise: string; kind; from; to; fails; bodyweight: boolean }[]` (пусто — поле не пишется);
6. разгрузка — уведомление тренеру (см. ниже).

Считается любая завершённая тренировка по шаблону тренера, как бы её ни запустили: план, «От тренера», повтор прошлой — сравнивается сделанное с заданием. Офлайн-финиш приходит тем же `finishWorkout`.

`saveTargetsAction`: шаг — в схеме `targetSchema` (`step: 0.5…20 | null`); шаг без веса — отказ «Для прогрессии нужен вес»; изменились `weight` или `step` — `fails = 0`.

## Клиент

Сводка (`WorkoutSummaryView`, из `FinishMeta.progression`) — блок «План тренера», строка на упражнение (тексты — чистая `progressionLine` в `lib/coach/progression.ts`):
- `up`: «Приседания со штангой: в следующий раз 62,5 кг (+2,5)»;
- `same`: «Жим ногами: повторим 100 кг · неудача 2 из 3»;
- `deload`: «Румынская тяга: разгрузка — 52,5 кг (−10 %)»;
- своим весом — вес как отягощение: «+12,5 кг».

Тот же блок — у тренера в тренировке клиента (`readOnly`). Старые тренировки без поля — как раньше. Пометка «от тренера» в редакторе не меняется (вес в ней уже новый).

## Тренер

Диалог «Задания»: четвёртое поле «Шаг, кг» (подпись для скринридера «Шаг, кг: <упражнение>», дробное, пусто — без прогрессии); при прогрессии — строка «прогрессия: +2,5 кг за успешную тренировку · неудач подряд: 1». Список шаблонов — «… · прогрессия у N», если N > 0.

Уведомление тренеру только о разгрузке: `NotificationType.COACH`, «Разгрузка: <клиент>», текст «<упражнение>: 52,5 кг после 3 неудач», ссылка — тренировка клиента `/coach/clients/<id>/workouts/<wid>`, push. «Тренировка выполнена» — как было.

## Тесты

Unit (`lib/coach/progression.test.ts`): успех (+шаг, сброс неудач); подходов больше нужного; подход легче задания не засчитывается; повторов меньше — неудача +1; третья неудача — разгрузка 62,5 → 55, 60 → 52,5, 2,5 → 0; пустой `done` — `null`; нет шага или веса — `null`; повторы из шаблона и «любые > 0»; `progressionLine` для трёх видов и своего веса. `targetSchema` — пределы шага.

e2e (`e2e/coach-targets.spec.ts`):
1. задание присед 3 × 5 · 60, шаг 2,5; клиент делает 3 × 5 · 60 → в сводке «в следующий раз 62,5 кг (+2,5)», следующий запуск — 62,5;
2. 2 подхода из 3 → «повторим 60 кг · неудача 1 из 3»;
3. `fails = 2`, снова неудача → «разгрузка — 52,5 кг (−10 %)», у тренера уведомление «Разгрузка: …»;
4. шаг без веса в диалоге → «Для прогрессии нужен вес»; тренер меняет вес → `fails = 0`.
