# Клубы (цикл 1 из 2): клуб зала, рейтинг, лента достижений

Релиз `release/2026-11-assistant`. Согласовано 2026-10-12: (1) клубы — этот документ, (2) общие задания клуба —
отдельная спека на модели этого цикла. Под флагом `clubs`.

## Цель

Клуб — открытое сообщество одного фитнес-зала (город + адрес): «все, кто ходит в мой зал». Живёт рядом с гильдией
(маленькая команда друзей по приглашению) и не заменяет её. Клубы заводят представители залов (админы клубов), посетители
находят свой зал и вступают. В клубе — рейтинг по опыту и лента достижений участников.

## Решения

- **Создание** — заявка любого пользователя; в поиске клуб появляется после одобрения админом приложения
  (`ADMIN_LOGINS`). Заявитель — админ клуба.
- **Админ клуба** не обязан быть участником (сотрудник зала может не тренироваться). У одного человека до 5 клубов
  (`CLUB_ADMIN_MAX`, считаются `PENDING` + `APPROVED` + `HIDDEN`), заявок на рассмотрении — до 3 (`CLUB_PENDING_MAX`).
  Один админ на клуб, права передаются; соадминов нет.
- **Членство** — один клуб на человека, вступление сразу (поиск или ссылка/QR), нужен ник. Админ клуба исключает —
  исключение = бан в этом клубе до разблокировки.
- **Рейтинг** — опыт за тренировки и рекорды (как очки лиги), вкладки «Неделя» и «Месяц».
- **Лента** — только события (ачивки, уровень, рекорды, веха серии, босс, цели); сами тренировки незнакомцам не
  открываются.
- **Вступление = согласие** показывать участникам клуба ник, уровень, титул, опыт и достижения.
- **Без карт и геокодера:** город — текст с подсказками, поиск по тексту. Публичной (SEO) страницы клуба нет — всё в
  кабинете.

## Данные

```prisma
enum ClubStatus { PENDING APPROVED REJECTED HIDDEN }

model Club {
  id           String     @id @default(cuid())
  name         String     /// 3–60
  nameKey      String     /// clubKey(name) — для похожих; не уникален (сети залов)
  city         String     /// 2–40, как ввёл заявитель (модератор может поправить)
  cityKey      String     /// clubKey(city) — поиск и подсказки
  address      String     /// 5–120
  addressKey   String     /// clubKey(address) — похожие
  contact      String     /// 5–120: телефон/сайт/соцсеть зала — видит только админ приложения
  code         String     @unique /// приглашение, алфавит кода друга
  adminId      String
  status       ClubStatus @default(PENDING)
  rejectReason String?
  reviewedAt   DateTime?
  createdAt    DateTime   @default(now())

  admin   User         @relation("ClubAdmin", fields: [adminId], references: [id], onDelete: Restrict)
  members ClubMember[]
  bans    ClubBan[]

  @@index([status, cityKey])
  @@index([adminId])
}

model ClubMember {
  userId   String   @id /// один клуб на человека
  clubId   String
  joinedAt DateTime @default(now())
  user User @relation("ClubMember", fields: [userId], references: [id], onDelete: Cascade)
  club Club @relation(fields: [clubId], references: [id], onDelete: Cascade)
  @@index([clubId])
}

model ClubBan {
  clubId    String
  userId    String
  createdAt DateTime @default(now())
  club Club @relation(fields: [clubId], references: [id], onDelete: Cascade)
  user User @relation("ClubBan", fields: [userId], references: [id], onDelete: Cascade)
  @@id([clubId, userId])
}
```

`onDelete: Restrict` у админа: аккаунты в приложении не удаляются (удаление — по письму), при ручном удалении сначала
передать клуб.

## Правила (чистые, `lib/club/rules.ts`)

- `clubKey(s)` — нижний регистр, «ё» → «е», убрать кавычки и пунктуацию, схлопнуть пробелы, trim.
- `clubSchema` (Zod): название 3–60, город 2–40, адрес 5–120, контакт 5–120, `represent: true` (галочка «Я представляю
  этот зал»).
- `similarClubs(input, clubs)` — клубы того же `cityKey` (`APPROVED` и `PENDING`), у которых `nameKey` или
  `addressKey` совпадает или один содержит другой; до 5.
- `createBlock({ admined, pending })` — «Можно управлять не больше чем 5 клубами» / «Не больше 3 заявок на проверке».
- `joinBlock({ status, banned, hasNickname, sameClub })` — не одобрен → 404 (решает страница); бан — «Админ клуба
  ограничил вступление»; без ника — форма ника; уже в этом — переход на страницу клуба.
- `toClubEvents(row, viewerId)` (`lib/club/feed.ts`) — из `FeedRow` в `ClubEvent`: ник, титул, `finishedAt`, `me` и
  список событий: ачивки (без `login:*`), новый уровень, рекорды (`hideWeights` — `value: null` у весовых, как в ленте
  друзей), веха серии (`streakMilestone`), побеждённый босс недели, достигнутые цели (как `FeedEntry.goals`). Нет
  событий — `null` (строка не показывается). Название тренировки, упражнения, объём, длительность, id тренировки в
  результат не попадают.

## Запросы (`lib/club/queries.ts`)

- `searchClubs(city, text)` — только `APPROVED`; `cityKey` = `clubKey(city)` (пустой город — все), `text` — `ILIKE` по
  `nameKey`/`addressKey`; число участников; до 30, сортировка по участникам.
- `citySuggestions(prefix)` — `city` одобренных клубов по префиксу `cityKey`, до 8 уникальных.
- `getClubPage(clubId, viewerId)` — клуб, число участников, моё членство, бан, админ ли я.
- `getClubRating(clubId, viewerId, timeZone, period: "week" | "month")` — один SQL: `ClubMember` ⨝ сумма `XpEvent`
  (`WORKOUT_COMPLETED` + `PERSONAL_RECORD`) с начала недели (пн) или месяца (1-е) в поясе смотрящего до сейчас; опыт
  до вступления тоже считается; ник, титул, уровень (`levelProgress(User.xp)`); нули — отдельным числом. Ранжирование —
  `rankLeague`; топ-50 + своя строка. Не участнику — топ-3 недели.
- `getClubFeed(clubId, viewerId, cursor)` — общий `feedPage` с условием «автор — участник клуба, `shareActivity`,
  `finishedAt ≥ joinedAt`», затем `toClubEvents` и отбрасывание пустых; страница добирается до `FEED_PAGE` событий
  (не более 3 запросов на подгрузку).
- `getMyClubs(userId)` — клубы, где я админ (с заявками и статусами), и моё членство.
- `getClubsForReview()` — `PENDING` (старые первыми) с контактом, заявителем и `similarClubs`; вкладка одобренных и
  скрытых с поиском.

## Действия (`lib/club/actions.ts`, все проверяют флаг `clubs`; модерация — `requireAdmin`)

- `createClubAction` — `clubSchema` + `createBlock` → `PENDING`, `code` (повтор при коллизии).
- `reviewClubAction(id, "approve" | "reject", reason?)` — условный `updateMany` по `status: PENDING`; причина при отказе
  обязательна (5–200); уведомление заявителю `SOCIAL`: «Клуб «…» одобрен» → `/clubs/<id>/manage`, «Заявка на клуб «…»
  отклонена: <причина>» → `/clubs`.
- `setClubHiddenAction(id, hidden)` — `APPROVED` ↔ `HIDDEN`, условный `updateMany`.
- `updateClubAction` (админ клуба или админ приложения) — название, город, адрес; у одобренного применяется сразу.
- `joinClubAction(code | clubId)` — транзакция: `SELECT … FOR UPDATE` строки клуба, `APPROVED`, нет бана, есть ник;
  удалить прежнее членство, вставить новое. Уведомлений нет (клуб большой).
- `leaveClubAction`; `kickClubMemberAction(userId)` — удалить членство + `ClubBan`, уведомление «Вас исключили из
  клуба «…»»; `unbanAction(userId)`.
- `transferClubAction(nickname)` — новый админ — участник клуба с этим ником и с `createBlock` < 5; условный
  `updateMany` по `adminId`; уведомление новому админу.
- `regenerateClubCodeAction` — новый `code`, старая ссылка — 404.

## Интерфейс

- **`/clubs`**: есть клуб — переход на его страницу; иначе поиск (поле города с подсказками, текст, список карточек:
  название, адрес, участники, «Вступить»), «Создать клуб» и «Мои клубы» (заявки со статусами, причина отказа, ссылки
  на управление).
- **`/clubs/new`**: форма заявки; при вводе города и названия/адреса — блок «Возможно, ваш зал уже есть» со
  ссылками; после отправки — «Заявка отправлена, обычно проверка занимает до суток».
- **`/clubs/[id]`** (только `APPROVED`; `HIDDEN` — участникам и админу «Клуб скрыт модератором», остальным 404;
  `PENDING`/`REJECTED` — только админу клуба, с плашкой статуса): шапка (название, город, адрес, «N участников»),
  кнопки «Пригласить» (ссылка + QR), «Выйти» (подтверждение) или «Вступить»; вкладки «Рейтинг» (Неделя/Месяц, ник,
  титул, уровень, XP, «ты») и «Лента» (события, подгрузка курсором). Не участнику — шапка, топ-3 недели, «Вступить».
- **`/clubs/join/[code]`**: экран согласия: «Участники клуба увидят твой ник, уровень, опыт и достижения. Тренировки —
  нет». Уже в другом клубе — «Ты выйдешь из «…»». Без ника — `NicknameForm`. Гость — `/clubs/join/` в
  `PUBLIC_PREFIXES` не входит: `proxy.ts` отправит на вход, регистрация и вход несут `next` (`safeRedirectPath` уже
  пропускает любой внутренний путь). Неверный код или клуб не `APPROVED` — 404.
- **`/clubs/[id]/manage`** (админ клуба): правка названия/города/адреса; ссылка, QR (генерация на клиенте, без внешних
  сервисов), «Сменить ссылку»; участники с поиском по нику и «Исключить» (подтверждение: «Он не сможет вступить снова,
  пока вы не разблокируете»); «Заблокированные» — «Разблокировать»; «Передать клуб» по нику.
- **`/admin/clubs`** (`requireAdmin`): «На проверке» — карточки с контактом, заявителем (логин и ник), похожими
  клубами, «Одобрить» / «Отклонить» с причиной; «Одобренные» — поиск, «Скрыть»/«Вернуть», правка. Пункт «Клубы» в меню
  профиля у админов с числом заявок.
- **Меню**: «Клуб» в боковом меню и меню профиля рядом с «Гильдией» — только с флагом.

## Приватность

- `shareActivity = false` — нет в ленте клуба, но есть в рейтинге (согласие на рейтинг — вступление).
- `hideWeights` — весовые рекорды без значений (вырезается на сервере).
- В ленте клуба нет тренировок до вступления, ссылок на тренировки и 👊; `canSeeWorkout` клубы не расширяют.
- Выход и исключение сразу убирают из рейтинга и ленты — всё считается при чтении.
- Контакт зала видит только админ приложения.
- Ачивки, полученные вне тренировки (вход, сундук рейда), в цикле 1 в ленту не попадают — их нет в `XpEvent`
  тренировки.

## Флаг

`clubs` в `FLAGS` (срок — 2027-03-31). Флаг смотрящего: без флага — нет пунктов меню, `/clubs/**` — 404, действия
отказывают. `/admin/clubs` — без флага (модерация работает до раскатки). Заявку подаёт только пользователь с флагом: для раннего
запуска залов админ добавляет их представителей в список флага. Гость по ссылке-приглашению после входа без флага
получит 404 — пока флаг не на 100 %, ссылки раздаются только тем, кто в списке.

## Тесты

- Unit: `clubKey`, `clubSchema`, `similarClubs`, `createBlock`, `joinBlock`, `toClubEvents` (вырезание при
  `hideWeights`, `login:*`, пустая тренировка → null, нет названия/упражнений/объёма).
- e2e `e2e/clubs.spec.ts` (флаг — `addFlagUser`, сценарии с двумя игроками — `--workers=8`): заявка → видна в
  `/admin/clubs` с похожими → отказ с причиной (уведомление) → новая заявка → одобрение → поиск по городу → вступление
  по ссылке (экран согласия) → рейтинг недели с XP → лента: событие ачивки есть, названия тренировки и объёма нет →
  исключение и бан («ограничил вступление») → разблокировка → передача клуба → скрытие модератором (нет в поиске,
  участнику плашка). Без флага — 404. Хелперы в `e2e/db.ts`: `createClub`, `clubOf`, `clubMembers`.
