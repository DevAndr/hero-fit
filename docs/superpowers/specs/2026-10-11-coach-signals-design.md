# Режим тренера: сигналы риска клиентов

Первая из трёх фич для тренеров (дальше — самочувствие клиента после тренировки, назначение шаблона нескольким
клиентам).

## Цель

Тренер вовремя замечает клиента, который «отваливается» или застрял, — раньше, чем тот пропадёт на неделю. Сигналы
видны в списке клиентов и в карточке, а при появлении приходит уведомление (колокольчик, push, Telegram).

Сейчас в `/coach` две метки: «неактивен» (7 дней без тренировок) и число подсказок «пора увеличить вес»
(`clientFlags`, `sortClients` в `lib/coach/clients.ts`); уведомлений нет.

## Сигналы

Всё — в поясе клиента (`User.timeZone`), назначения — только этого тренера.

| Код | Горит | Гаснет |
|---|---|---|
| `MISSED_PLAN` | Две последние прошедшие (дата < сегодня клиента) назначенные тренировки обе не выполнены: `missed` или пропущены клиентом (`skipped`) | Последняя прошедшая выполнена |
| `STALLED` | Есть задание (`CoachTarget`) с `fails ≥ 2` или с `unloadedAt` за последние 14 дней | Ни того, ни другого |
| `ACTIVITY_DROP` | Связь ≥ 42 дней; среднее за 2 недели в днях 15…42 назад (тренировок / 2) ≥ 2; тренировок за последние 14 дней ≤ половины этого среднего | Условие не выполняется |
| `INACTIVE` | 7 дней без тренировок (от последней тренировки, без неё — от `linkedAt`), как сейчас | Новая тренировка |

- `INACTIVE` гасит `ACTIVITY_DROP` (оба не горят).
- Сегодняшнее назначение — не пропуск, даже если время прошло.
- `since` сигнала: `MISSED_PLAN` — дата первого из двух пропусков; `STALLED` — `unloadedAt` или день, когда стало
  `fails ≥ 2` (берётся `CoachTarget.updatedAt`); `ACTIVITY_DROP` — начало 14-дневного окна; `INACTIVE` — последняя
  тренировка (или `linkedAt`).
- «Пора увеличить вес» — не сигнал: отдельная зелёная метка, на порядок не влияет.

## Данные

- `CoachSignal`: `id`, `coachId`, `clientId`, `kind` (enum `CoachSignalKind`), `since` (DateTime), `createdAt`,
  `notifiedAt` (DateTime?), `resolvedAt` (DateTime?). Открытый — `resolvedAt = null`; один открытый на
  тренер + клиент + тип — частичный уникальный индекс `CoachSignal_open` в миграции (Prisma его не видит — не удалять
  при `migrate dev`). Удаление тренера/клиента — каскад.
- `User.coachSignalsDay` (`String?`, `YYYY-MM-DD` в поясе тренера) — день последней проверки.
- `CoachTarget.unloadedAt` (`DateTime?`) — ставит `applyProgression` при разгрузке; смена веса/шага в диалоге
  тренера его не трогает.
- Разрыв связи (`dropAssignments` и места закрытия `CoachLink`) закрывает открытые сигналы пары.

## Модули

- `lib/coach/signals.ts` — чистые:
  - `clientSignals(input: SignalInput, now: Date, tz: string): { kind: CoachSignalKind; since: Date }[]`, где
    `SignalInput = { linkedAt, lastWorkoutAt, workoutsAt: Date[] (за 42 дня), plan: { date, status }[]
    (назначения тренера за 28 дней), targets: { fails, unloadedAt, updatedAt }[] }`;
  - `signalsDiff(open: { kind }[], current: { kind }[])` → `{ open: kind[]; resolve: kind[] }`;
  - `signalLabel(kind)` — метка («Пропуски плана», «Застой на весе», «Спад активности», «Неактивен»);
    `signalText(kind, since, tz)` — пояснение для карточки; `signalsNotice(name, kinds)` — текст уведомления.
  - Тон меток: `MISSED_PLAN`, `INACTIVE` — тревожный (`destructive`), `STALLED`, `ACTIVITY_DROP` — предупреждение.
- `lib/coach/signals-queries.ts` — `getSignalInputs(coachId, now)` → `Map<clientId, SignalInput>` для всех
  активных клиентов тренера (назначения — через `getCalendar` клиента и отменённые записи, как в `getClientPlan`).
- `processCoachSignals(now)` — в `runNotificationTick`: тренеры (`isCoach`, есть активные связи), у которых
  местное время ≥ 10:00 и `coachSignalsDay` ≠ сегодня. Для каждого: посчитать, применить `signalsDiff` (новые —
  создать, пропавшие — `resolvedAt = now`), поставить `coachSignalsDay`, одно уведомление на клиента с новыми
  сигналами (`notify`, тип `COACH`, заголовок — `signalsNotice`, url `/coach/clients/<id>`), `notifiedAt`.
  Ошибка одного тренера не роняет тик (`try`/`console.error`, как у итогов недели).
- Список и карточка считают сигналы на лету (`clientSignals`), таблицу не читают — она только для уведомлений.

## Интерфейс

- `/coach`: метки сигналов вместо прежней «неактивен»; «пора увеличить вес» — зелёная. Порядок: сначала с
  сигналами — больше сигналов выше, при равенстве — давнее последняя тренировка выше (без тренировок — выше всех);
  потом остальные — свежие выше.
- Карточка клиента, вкладка «Обзор»: блок «Требует внимания» (только если есть сигналы) — метка, пояснение
  (`signalText`), ссылка: пропуски — `?tab=plan`, застой — `?tab=plan#targets`, спад и неактивность —
  `?tab=workouts`.

## Тесты

- Unit (`lib/coach/signals.test.ts`): каждое правило и границы — ровно два пропуска / один пропуск; сегодняшнее не
  пропуск; `fails` 1 и 2; разгрузка 14 и 15 дней назад; связь 41 и 42 дня; среднее 1,5 (нет сигнала) и 2;
  `INACTIVE` гасит спад; `signalsDiff`; порядок `sortClients`.
- e2e (`e2e/coach-signals.spec.ts`): клиент с двумя прошедшими назначениями без тренировок → метка «Пропуски
  плана» в `/coach` и блок в карточке; `runTick` с тестовыми часами → одно уведомление тренеру «<имя>: пропущены 2 тренировки подряд»
  (тексты без рода), повторный тик того же дня — без нового; клиент завершает тренировку по следующему назначению →
  метка пропала. `fails = 2` через SQL → «Застой на весе».

## Вне фичи

Настраиваемые пороги, «снять сигнал вручную», сигналы для не назначенных тренером тренировок, дайджест тренеру.
