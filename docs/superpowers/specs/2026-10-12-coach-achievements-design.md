# Ачивки тренера

Релиз `release/2026-10-raids`. Режим тренера — спеки `2026-10-09-coach-*`, `2026-10-10-coach-*`, `2026-10-11-coach-*`.

## Цель

Тренер получает ачивки и титулы за рост практики, работу с клиентами и результаты клиентов — как игрок за свои
тренировки. Награды мотивируют вести клиентов активно и служат социальным доказательством на публичной странице.
Упор — на работу и результаты: число клиентов легко накрутить пустыми аккаунтами, поэтому клиент считается, только если
тренировался.

## Решения

### Подсчёт — из истории на лету

Новых таблиц для счётчиков нет. Все тренерские счётчики — один SQL `coachStats(client, coachId)` в
`lib/achievements/coach-stats.ts`, результат — поле `coach` в `AchievementStats`. Работает задним числом: существующие
тренеры сразу получают заработанное.

**Окно связи** — каждая строка `CoachLink` тренера: `[createdAt, COALESCE(endedAt, now()))`. Событие клиента
засчитывается, если его время попало в окно этой связи. Окна одного клиента не пересекаются (у клиента одна активная
связь), поэтому событие не считается дважды; ушёл и вернулся — два окна.

| Счётчик | Что считаем |
|---|---|
| `clients` | Разные клиенты, у которых в окнах связи суммарно ≥ `COACH_ACTIVE_CLIENT_WORKOUTS` (= 3) завершённых тренировок (`finishedAt` в окне) |
| `comments` | `CoachComment` с `coachId` = тренер (общие и к упражнениям) |
| `workouts` | Завершённые тренировки клиентов с `finishedAt` в окне и `templateId` на шаблон тренера (`WorkoutTemplate.userId` = тренер) — как бы ни запустили |
| `prs` | Σ `jsonb_array_length(meta->'records')` у `XpEvent` `PERSONAL_RECORD` клиентов с `createdAt` в окне (тот же источник, что личный `prCount`) |
| `progressions` | Элементы `meta->'progression'` с `kind = 'up'` у `XpEvent` `WORKOUT_COMPLETED` клиентов в окне, без `meta->>'progressionSource' = 'own'` |
| `goals` | `Goal` клиентов со `status = ACHIEVED` и `achievedAt` в окне |
| `pagePublished` | `CoachProfile.publishedAt IS NOT NULL` |

Тип:

```ts
export type CoachAchievementStats = {
  clients: number; comments: number; workouts: number; prs: number;
  progressions: number; goals: number; pagePublished: boolean;
};
```

В `AchievementStats` добавляются `coach: CoachAchievementStats` и `coachMode: boolean` (= `User.isCoach`).
`EMPTY_COACH_STATS` — нули. SQL не выполняется, если у пользователя `isCoach = false` и нет ни одной строки `CoachLink`
как тренера (и нет `CoachComment`) — тогда пустые счётчики.

Граничные случаи:
- Режим выключен, а история есть — счётчики считаются (выданные ачивки и так остаются), но на будущее новые выдаются
  только при `isCoach = true`: лестницы `COACH` строятся, только если `stats.coachMode` = true.
- Клиент удалил аккаунт — его данные уходят каскадом, счётчики могут уменьшиться; выданные ачивки не отзываются.
- Свои тренировки тренера не входят: клиентом самого себя он быть не может.

### Лестницы (категория `COACH`)

Новое значение `AchievementCategory.COACH` (миграция `coach_achievements`). Лестницы — в `ladders()`
(`lib/achievements/definitions.ts`), `goalGroup` у всех свой (`coach-<имя>`), `goal` — только при `coachMode`.
XP — от номера ступени, не от порога: `xpReward = 40 + 20·i` (i = 0, 1, 2… — индекс порога в списке).

| Код | Пороги | Название (1-я / дальше) | Описание |
|---|---|---|---|
| `coachclients:N` | 1, 3, 5, 10, 25 | «Первый ученик» / «Ученики ×N» | «Клиент провёл с вами 3 тренировки» / «N клиентов провели с вами по 3 тренировки» |
| `coachpage:1` | 1 | «На виду» | «Опубликовать страницу тренера» |
| `coachcomments:N` | 1, 10, 50, 200 | «Первый разбор» / «Разборы ×N» | «Прокомментировать тренировку клиента» / «Оставить N комментариев клиентам» |
| `coachworkouts:N` | 10, 50, 100, 250, 500, 1000 | «По плану ×N» | «Клиенты провели N тренировок по вашим шаблонам» |
| `coachprs:N` | 10, 50, 100, 250 | «Рекорды учеников ×N» | «Клиенты побили N рекордов, занимаясь с вами» |
| `coachprog:N` | 5, 25, 100 | «Прогрессия ×N» | «Клиенты N раз подняли вес по вашим заданиям» |
| `coachgoals:N` | 1, 5, 25 | «Цель ученика» / «Цели учеников ×N» | «Клиент выполнил цель, занимаясь с вами» / «Клиенты выполнили N целей, занимаясь с вами» |

Числа во множественном числе — через `plural`. Значок — `default` (`achievementIconKey` без изменений; свои PNG можно
добавить позже в `assets/icons/achievements/`).

### Титулы

`ACHIEVEMENT_TITLES` (`lib/titles/catalog.ts`):
- `ach:coachclients:25` — «Наставник»
- `ach:coachworkouts:1000` — «Кузница чемпионов»
- `ach:coachprs:250` — «Создатель рекордов»

### Выдача

Отдельной машины нет — обычный `evaluateAchievements`/`evaluateAchievementsNow`. В транзакции тренировки клиента
ачивки тренера не считаются (как у рейдов). Тренеру — когда:
- ежедневный вход (`daily-visit.ts`) и завершение своей тренировки — уже есть;
- после действий тренера — `evaluateAchievementsNow(coachId)` в `saveCoachCommentAction`, `assignWorkoutAction`,
  `assignManyAction`, `publishCoachProfileAction(true)`; после `acceptCoachAction` — тренеру принятой связи;
- открытие `/coach` — `evaluateAchievementsNow` (результаты клиентов приходят без ожидания следующего дня).

Новые — тост через `seenAt`, как у всех. Отдельных уведомлений нет. XP-награда в лигу не входит (как у всех ачивок).

### `/achievements`

Секция «Тренер» в общем списке по категориям (подпись категории — рядом с остальными). Показывается, если режим
тренера включён или есть хоть одна ачивка `COACH`. Неполученные — серые, ближайшая цель — одна на семейство.

### Публичная страница `/trainer/<ник>`

Блок «Награды тренера»: полученные ачивки `COACH` — значок и название; сначала с наибольшей ступенью в своей лестнице
(вершины первыми), до 6, `coachpage:1` не показывается (страница и так опубликована). Нет наград — блока нет.
Выбор — чистая `publicAwards(codes)` в `lib/coach/profile.ts`.

Переключатель «Показывать награды» в редакторе `/coach/page` — `CoachProfile.showAwards Boolean @default(true)` (в той же
миграции), сохраняется через `saveCoachProfileAction`. Предпросмотр тренера учитывает переключатель.

## Вне рамок

- Свои значки PNG для тренерских ачивок.
- Отдельные уведомления о тренерских ачивках, лента друзей.
- «Выполненные планы» из таблиц планов (назначения удаляются при разрыве связи — счёт задним числом невозможен;
  их заменяет `coachworkouts`).
- Рейтинг тренеров.

## Тесты

- Unit (`definitions.test.ts`): лестницы `COACH` — коды, пороги, XP по ступеням, `goal` только при `coachMode`,
  `goalGroup`; титулы (`catalog`); `publicAwards` — порядок, лимит 6, без `coachpage:1`.
- e2e (`e2e/coach-achievements.spec.ts`, `--workers=8`): тренер + клиент, связь `linkCoach`, клиенту 3 тренировки
  в БД по шаблону тренера → тренер открывает `/coach` → тост «Первый ученик»; на `/achievements` секция «Тренер»;
  комментарий к тренировке клиента → «Первый разбор»; опубликованная страница показывает «Награды тренера»,
  с выключенным «Показывать награды» — блока нет. Окно связи: тренировки клиента до связи не засчитываются.
