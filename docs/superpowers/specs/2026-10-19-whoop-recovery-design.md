# WHOOP: сон, восстановление и советы по нагрузке

Второй шаг интеграции с WHOOP (первый — `2026-10-17-whoop-integration-design.md`: пульс и strain в сводке).
Под существующим флагом `whoop`.

## Цель

Человек с WHOOP открывает кабинет и сразу видит, насколько он восстановился и как спал. Перед тренировкой
приложение подсказывает, тренироваться ли тяжело, держать веса или облегчить день — и одной кнопкой снижает веса.
Советы учитывают не только цифры WHOOP, но и то, какие мышцы человек нагружал в Hero Fit.

Успех: владелец (есть WHOOP 5.0) обновляет доступ, видит карточку «Восстановление» с сегодняшними цифрами и советами;
в красный день нажимает «Облегчить» и получает веса −10 %; новые ночи подтягиваются вебхуками без ручных действий.

## Ограничения WHOOP API (v2, сверено 2026-10-19)

- Scope: `read:recovery` (восстановление), `read:sleep` (сон). `read:cycles` не запрашиваем — нагрузка за сутки не
  нужна (минимизация по 152-ФЗ).
- `GET /v2/activity/sleep?start&end&limit≤25&nextToken`, `GET /v2/activity/sleep/{sleepId}` (uuid). Поля: `id`,
  `cycle_id`, `start`, `end`, `nap`, `score_state`, `score.stage_summary.total_light_sleep_time_milli`,
  `…total_slow_wave_sleep_time_milli`, `…total_rem_sleep_time_milli`, `score.sleep_needed.baseline_milli`,
  `need_from_sleep_debt_milli`, `need_from_recent_strain_milli`, `need_from_recent_nap_milli`,
  `score.sleep_performance_percentage`.
- `GET /v2/recovery?start&end&limit≤25&nextToken`, `GET /v2/cycle/{cycleId}/recovery`. Поля: `cycle_id`, `sleep_id`,
  `score_state`, `score.user_calibrating`, `recovery_score`, `resting_heart_rate`, `hrv_rmssd_milli`.
- Вебхуки: `sleep.updated|deleted` — `id` = uuid сна; `recovery.updated|deleted` — `id` = uuid **связанного сна**
  (не цикла). Удаление сна удаляет и восстановление.
- Восстановление есть только у основного сна; у дневного (`nap: true`) его нет.
- Уже выданный токен расширить нельзя — для новых scope нужна повторная авторизация. Ответ токена содержит `scope`
  (строка через пробел) — сохраняем. Что приходит в `scope` при refresh, сверить на настоящем WHOOP; если поля нет —
  `scopes` не трогаем.

## Решения

- **Переподключение:** старые подключения продолжают работать (пульс в сводках). Если в `scopes` нет
  `read:recovery`, на дашборде и в `/devices` — плашка «Разрешить сон и восстановление» → окно согласия → OAuth.
- **Видимость:** сон и восстановление видит только сам пользователь. Не передаются тренеру и друзьям, не попадают в
  ленту, рейтинги, XP и ачивки. Показ тренеру — возможная отдельная фича с отдельным согласием.
- **152-ФЗ:** данные о здоровье, отдельное согласие при подключении (текст расширяется), удаление при отключении и
  удалении аккаунта, раздел в «Моих данных», `/privacy` раздел 8.
- **Хранение, а не запрос на лету:** дашборд и тренировка читают только из БД — WHOOP не тормозит кабинет и не ломает
  его при сбоях.
- **Советы по правилам**, без LLM. Решает человек: ничего не меняется автоматически.

## Данные

`WhoopConnection` — новое поле `scopes String @default("")` (выданные scope через пробел). Миграция ставит
существующим подключениям `"read:workout read:profile offline"`.

Новая модель, каскадом от `User`:

```prisma
model WhoopSleep {
  id                 String   @id // uuid сна WHOOP
  userId             String
  user               User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  cycleId            String // int64 строкой
  start              DateTime
  end                DateTime
  sleepScoreState    String // SCORED | PENDING_SCORE | UNSCORABLE
  sleepMs            Int? // лёгкий + глубокий + быстрый сон
  needMs             Int? // сумма sleep_needed
  performancePct     Int?
  recoveryScoreState String? // null — восстановления ещё нет
  recoveryPct        Int?
  restingHr          Int?
  hrvMs              Float?
  calibrating        Boolean  @default(false)
  updatedAt          DateTime @updatedAt

  @@index([userId, end])
}
```

Дневной сон не сохраняется.

## Синхронизация (`lib/whoop/sleep-sync.ts`)

- `toWhoopSleep(api)` и `toWhoopRecovery(api)` в `map.ts` — чистые нормализаторы как `toWhoopWorkout`: числа
  `Math.round` (кроме HRV), нечисловое — `null`, нет `id`/битые даты — `null` (запись пропускается), `nap: true` —
  `null`.
- `syncSleepRange(userId, from, to)`: страницы `/v2/activity/sleep` и `/v2/recovery` за период, сопоставление по
  `sleep_id`, upsert. Вызывается после подключения (30 дней, в `after()`) и из «Обновить» на карточке дашборда (3 дня), только если в
  `scopes` есть `read:sleep`/`read:recovery` соответственно.
- `syncSleepOne(userId, whoopUserId, sleepId)` (`sleep.updated`): сон по id; нет — удалить строку.
- `syncRecoveryOne(userId, whoopUserId, sleepId)` (`recovery.updated`): сон по id → `cycle_id` →
  `/v2/cycle/{cycleId}/recovery` → поля восстановления; строки сна нет — создаётся из ответа сна.
- `sleep.deleted` — удалить строку; `recovery.deleted` — обнулить поля восстановления.
- Запись — та же защита, что у активностей: транзакция с `FOR SHARE` по `WhoopConnection` и сверка `whoopUserId`.
  Ошибки в лог и мониторинг — только имя (у `WhoopUnavailableError` — статус).
- Вебхук `/api/whoop/webhook` принимает шесть типов событий вместо двух.
- Callback OAuth сохраняет `scopes` из ответа токена; `consentAt` обновляется при каждом подключении.

## Сегодняшний день и зоны (`lib/whoop/recovery.ts`, чистые функции)

- `todaySleep(sleeps, now, timeZone)`: последний сон, у которого `end` попадает в текущие сутки в `User.timeZone` и
  `end ≤ now`; иначе `null`. `yesterday` — то же за прошлые сутки (для «вчера: 64 %»).
- `recoveryZone(pct)`: `≥ 67` — `green`, `34…66` — `yellow`, `≤ 33` — `red`; `null` — нет зоны.
- `baseline(sleeps)`: средние HRV и пульса покоя за 7 предыдущих ночей с посчитанным восстановлением; меньше 4 ночей
  — `null`.

## Советы (`whoopAdvice`, чистая функция)

Вход: сегодняшний и прошлый сон, базовая линия, восстановление мышц (`getMuscleRecovery`). Выход —
список советов с приоритетом (предупреждения выше похвалы):

1. **Зона:** зелёная — «можно тяжёлую тренировку», жёлтая — «держи текущие веса», красная — «лёгкий день: −10 %
   веса или на подход меньше».
2. **Недосып:** `sleepMs < 0.7 · needMs` — «Недоспал 1 ч 40 мин — сократи тренировку и отдыхай дольше между
   подходами»; вторая ночь подряд — «Второй день недосыпа — лучше лечь пораньше».
3. **HRV ниже нормы:** ниже базовой на 15 %+ — «HRV ниже твоей нормы — организм ещё под нагрузкой».
4. **Пульс покоя выше нормы:** выше базового на 5+ уд/мин — «Пульс покоя выше обычного на N — бывает при усталости
   или начале простуды, не форсируй».
5. **Мышцы:** зона жёлтая/красная и группа мышц ещё восстанавливается (данные `BodyMap`) — «Ноги ещё
   восстанавливаются — сегодня лучше верх тела».
6. **Хороший день:** зелёная, сон ≥ 90 %, HRV выше базовой — «Отличное восстановление — хороший день для рекорда»
   + ссылка «Начать тренировку» (`/training`).

При `calibrating` или без базовой линии советы 3 и 4 не срабатывают.

## Интерфейс

**Карточка «Восстановление · WHOOP»** на дашборде — перед картой мышц, только при подключённом WHOOP и флаге:
кольцо процента цветом зоны (токены `recovery-green|yellow|red` в `globals.css` для обеих тем; анимация один раз,
с учётом «уменьшить движение»), HRV, пульс покоя, сон «7 ч 20 мин · 86 %», до двух советов. Состояния: посчитано;
сон есть, восстановление считается («WHOOP считает…»); калибровка (пометка, цифры показываем); за сегодня нет —
«Данных за сегодня пока нет · вчера: 64 %» или карточки нет; `needsReauth` — «Переподключи WHOOP»; нет scope —
плашка «Разрешить сон и восстановление»; кнопка «Обновить». Данные — одна выборка (2 последних сна + 7 ночей для базовой линии +
подключение) в параллельной загрузке дашборда.

**Экран тренировки** (старт и начатая): строка с кольцом — зона и самый важный совет. При жёлтой/красной зоне
редактор ведёт себя как при самочувствии «устал» (`TIRED`): значки «Пора увеличить вес» скрыты, помощник не
предлагает прибавку; явный выбор самочувствия пользователем важнее зоны.

**«Облегчить»** (красная зона) — действие редьюсера `lighten`: невыполненные рабочие подходы с весом > 0 —
`−10 %` с округлением вниз по шагу помощника (1 кг до 20 кг, дальше 2,5). Не трогает выполненные, разминку,
кардио/время и упражнения с весом тренера (`coachTargets`). Тост «Облегчено · Вернуть» (откат прежних весов). Один
раз за тренировку; меняет только черновик.

**Помощник** (`smart_coach`): сценарий «Как я восстановился?» — все сработавшие советы и цифры.

**`/devices`:** у подключения — перечень передаваемых данных («Тренировки, пульс[, сон, восстановление]»), у старых
подключений — «Разрешить сон и восстановление».

**«Обновить»** на карточке «Восстановление» (`refreshWhoopRecoveryAction`): сны и тренировки за 3 дня; ограничение
общее с «Обновить» в сводке — раз в 60 с (`lastSyncAt`).

## 152-ФЗ и данные пользователя

- Текст согласия: + «сон (длительность, потребность), восстановление, вариабельность пульса (HRV), пульс покоя»;
  цель — «советы по нагрузке в приложении»; не передаются тренеру и друзьям.
- `/privacy` раздел 8 — тот же перечень и цель.
- «Мои данные»: `whoop.sleeps` (без токенов, в CSV не входит).
- Отключение и удаление аккаунта удаляют сны (каскад; порядок как у активностей: сначала подключение, потом данные).

## Тесты

- Unit: `toWhoopSleep`/`toWhoopRecovery` (дневной сон, битые данные, нечисловые поля), `todaySleep` в поясе
  пользователя (граница суток, сон ещё не закончился), `recoveryZone` (границы 33/34, 66/67), `baseline` (< 4 ночей),
  все 6 правил `whoopAdvice` и приоритет, `lighten` (округление, исключения, откат).
- Фейковый WHOOP (`e2e/whoop-server.ts`): `/v2/activity/sleep`, `/v2/recovery`, `/v2/cycle/{id}/recovery`, `scope`
  в ответе токена, `/__control/sleeps`.
- e2e (`e2e/whoop.spec.ts`, serial, desktop): плашка у старого подключения → переподключение → загрузка снов;
  карточка в состояниях «посчитано», «считает», «нет данных»; вебхуки `recovery.updated` и `sleep.deleted`; строка
  зоны и «Облегчить»/«Вернуть», упражнение тренера не изменилось, значок прибавки скрыт; советы на дашборде;
  выгрузка «Мои данные» и удаление аккаунта (`e2e/account-data.spec.ts`).
