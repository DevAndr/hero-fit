# Совместная тренировка

Дата: 2026-10-26. Под фича-флагом `together` (по умолчанию выключен).

## Цель

Два друга тренируются одновременно, каждый в своём зале и по своей тренировке, и видят друг друга «как будто рядом»: что партнёр делает сейчас, его подходы и рекорды, могут прислать друг другу 👊. Если тренировки по-настоящему пересеклись, оба получают бонус XP. Цель — удержание: «друг уже в зале, а я ещё нет».

Вне этапа: больше двух человек; открытые сессии (присоединиться без приглашения); одинаковая тренировка и соревнование; ведение партнёра (запись подходов за другого); мгновенная доставка (SSE/WebSocket).

## Принципы

- Сессия — связка двух обычных тренировок `Workout`. XP, рекорды, серия, программа тренера, календарь, офлайн — у каждого свои и работают как раньше; модель `Workout` не меняется.
- Только принятые друзья (`Friendship.status = ACCEPTED`), и только те, у кого флаг `together` включён (`isEnabled("together", userId)` для обоих).
- У человека не больше одной открытой сессии (`INVITED` или `ACTIVE`, где он хозяин или гость).
- Никто не узнаёт, что человек в зале, пока тот сам не позовёт.

## Данные

`XpReason.TOGETHER_BONUS`. Ачивки — категория `SOCIAL`.

## Жизненный цикл

1. **Приглашение** — `inviteAction(workoutId, friendId)`: тренировка хозяина `IN_PROGRESS`, друг принят и с флагом, у обоих нет открытой сессии → `INVITED`. Проверка «одна открытая сессия» — в транзакции с `SELECT … FOR UPDATE` строк `User` обоих (в порядке id). Другу — уведомление `SOCIAL` (в приложении + push/Telegram): «<Имя> в зале — тренируйся вместе», ссылка `/together/<id>`. Хозяин может отменить (`cancelInviteAction` → `DECLINED`).
2. **Срок приглашения** — 15 минут (`INVITE_TTL_MIN`). Истечение ленивое: `INVITED` старше 15 минут на любом чтении считается `EXPIRED` (`sessionState`), при записи статус сохраняется. Тика нет.
3. **Принятие** — `acceptAction(sessionId)`: только гость, приглашение живо, у гостя нет другой открытой сессии → `ACTIVE`, `acceptedAt`. Если у гостя есть тренировка `IN_PROGRESS` — она становится `guestWorkoutId`; иначе `guestWorkoutId = null`, и гость попадает на обычный экран старта `/training` (баннер «Тренировка с <Имя>»): первая тренировка гостя, перешедшая в `IN_PROGRESS` (`startWorkoutAction`), пока сессия `ACTIVE` с пустым `guestWorkoutId`, привязывается к ней.
4. **Отклонение** — `declineAction` → `DECLINED`, хозяину — тихое уведомление в приложении (без push).
5. **Конец** — `ENDED`, когда:
   - обе тренировки в конечном состоянии (`COMPLETED` или отменены) — проверка `closeIfDone(sessionId)` в `finishWorkout` и в отмене тренировки;
   - кто-то нажал «Выйти из сессии» (`leaveAction`) — его тренировка продолжается как обычная, бонуса в этой сессии нет никому;
   - прошло 4 часа с `acceptedAt` (`SESSION_MAX_H`) — лениво, как истечение приглашения; бонус не выдаётся.
6. Гость принял, но так и не начал тренировку, а хозяин завершил — сессия `ENDED` при завершении хозяина, без бонуса.

## Бонус

Выдаётся в транзакции закрытия сессии (`closeIfDone`), обоим, кто удовлетворяет условиям:

- обе тренировки `COMPLETED`;
- пересечение `[startedAt, finishedAt]` двух тренировок ≥ 20 минут (`MIN_OVERLAP_MIN`);
- в каждой тренировке есть выполненные подходы (`totalSets > 0`);
- у получателя ещё нет `XpEvent` с `TOGETHER_BONUS` в его местных сутках (`User.timeZone`, сутки — по `finishedAt` его тренировки).

Размер — `max(5, round(0.1 × xpEarned))` своей тренировки. Начисление — как у сундуков (`XpEvent` + `User.xp`, пересчёт уровня). `bonusAt` ставится в той же транзакции — повтор невозможен. Кто завершил первым, в сводке видит «Бонус придёт, когда <Имя> закончит», затем — уведомление «+N XP — тренировка с <Имя>».

## Ачивки «Вместе»

Категория `SOCIAL`, лестница 1 / 10 / 50 — по числу `XpEvent` с `TOGETHER_BONUS`. Проверка — после выдачи бонуса, обычным движком ачивок; XP и монеты — по правилам существующих ступеней.

## Синхронизация

Опрос: `GET /api/together/<id>?since=<ISO>` раз в 5 секунд (`POLL_MS`), пока открыт экран тренировки и вкладка видима (`visibilitychange`), прекращается при `ENDED`/`DECLINED`/`EXPIRED`. Доступ — только участникам (иначе 404), флаг проверяется.

Ответ:

```ts
{
  status: "INVITED" | "ACTIVE" | "ENDED" | "DECLINED" | "EXPIRED";
  inviteExpiresAt?: string;
  partner: {
    name: string;
    startedAt: string | null;
    finished: boolean;
    current: { exercise: string; doneSets: number; totalSets: number } | null;
    exercises: { name: string; sets: { reps: number; weight: number | null; done: boolean }[]; record: boolean }[];
    hideWeights: boolean;
  } | null;
  cheers: { at: string }[];   // от партнёра после since
  events: { kind: "record" | "finished" | "left"; exercise?: string; at: string }[];
}
```

Срез строится чистой функцией `partnerSnapshot(workout, previousBests, hideWeights)` из сохранённого черновика партнёра (черновик уходит на сервер через 0,7 с после изменения, `use-workout-sync`). «Текущее упражнение» — первое упражнение с невыполненными подходами после последнего выполненного. Рекорд — выполненный подход тяжелее лучшего веса в упражнении по прошлым завершённым тренировкам (один агрегирующий запрос по упражнениям среза). При `hideWeights` веса — `null`, значок рекорда остаётся.

Способ доставки отделён от среза: переход на SSE позже не меняет формат.

## Экран тренировки

- **Нет сессии** — кнопка «Вместе» (иконка двух людей) в шапке активной тренировки. Открывает список друзей с флагом: сверху — с кем были совместные сессии, затем недавно активные; кнопка «Позвать».
- **Приглашение отправлено** — на месте кнопки «Ждём <Имя>… 14:32» (обратный отсчёт) и «Отменить».
- **Сессия активна** — закреплённая полоса партнёра под шапкой: аватар, имя, «Жим лёжа · 3 из 5 подходов», время в зале, кнопка 👊. Нажатие раскрывает панель (только просмотр): упражнения, выполненные подходы («8 × 80 кг» или «8 повторов»), значки рекордов. В меню полосы — «Выйти из сессии».
- **Всплывашки** (sonner): рекорд партнёра, 👊 от партнёра, партнёр закончил, партнёр вышел. Каждый подход отдельно не показывается.
- **Нет связи** — 30 секунд без успешного ответа: полоса блекнет, подпись «нет связи»; оживает при следующем ответе. Своя тренировка и офлайн-режим не затрагиваются.
- 👊 — `cheerAction(sessionId)`: не чаще раза в 10 секунд от одного человека в сессии; партнёру — через опрос, без push.

## Приглашённому

- `/together/<id>` (группа `app/(app)/`): карточка «<Имя> тренируется с 18:05», кнопки «Присоединиться» / «Отклонить». Приглашение истекло, отменено или чужое — понятный текст и ссылка на свою тренировку.
- Дашборд: пока приглашение живо — карточка «<Имя> зовёт тренироваться» сверху.

## Сводка тренировки

Блок «Вместе с <Имя>» на `/workouts/<id>`: длительность, подходы и рекорды партнёра, сколько минут тренировались одновременно, статус бонуса: «+N XP», «придёт, когда <Имя> закончит» или причина, почему нет («пересеклись меньше 20 минут», «бонус сегодня уже был»).

## Чистые функции — `lib/together/rules.ts`

- `sessionState(session, now)` — статус с учётом ленивого истечения (15 мин приглашение, 4 ч сессия);
- `overlapMinutes(a, b)`;
- `bonusEligible({ host, guest, hadBonusToday })` → для каждого: да / причина;
- `bonusXp(xpEarned)`;
- `partnerSnapshot(...)`, `currentExercise(...)`;
- `canCheer(lastCheerAt, now)`.

Запросы — `lib/together/queries.ts`, действия — `lib/together/actions.ts`, закрытие и бонус — `lib/together/close.ts`.

## Тесты

- **Unit** (`lib/together/rules.test.ts`): истечение на 15-й минуте и через 4 часа; пересечение 19/20 минут; без подходов; отменённая тренировка; второй бонус за сутки (граница суток в поясе пользователя); минимум 5 XP; срез со скрытыми весами; текущее упражнение; частота 👊.
- **e2e** (`e2e/train-together.spec.ts`; desktop, `mode: "serial"` из-за глобального флага, два контекста, `--workers=8`):
  - приглашение → push/уведомление → принятие с идущей тренировкой → полоса партнёра обновляется после подхода → 👊 доходит;
  - принятие без тренировки → экран старта → тренировка привязывается;
  - отклонение; истечение (время приглашения сдвигается в БД);
  - выход из сессии — у обоих нет бонуса;
  - бонус обоим после завершения второго (время старта сдвигается в БД на 30 минут назад), второй бонус в тот же день — нет;
  - без флага кнопки нет, `/together/<id>` — 404.
- **Аккаунт**: `e2e/account-data.spec.ts` — раздел выгрузки и удаление.
