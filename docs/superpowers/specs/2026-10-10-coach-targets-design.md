# Режим тренера: персональные задания клиенту в назначенном шаблоне — дизайн

Дата: 2026-10-10. Продолжение режима тренера после этапов 1–3 (`2026-10-09-coach-clients-design.md`, `…-coach-programs-design.md`, `…-coach-comments-design.md`). Оплаты нет: пока идёт бета, функция бесплатна, как и весь режим тренера.

## Цель

Шаблон тренера общий для всех клиентов, а нагрузка у каждого своя. Сейчас при запуске шаблона вес берётся из истории клиента (без истории — общий `targetWeight` шаблона), и тренер не может сказать «Маше присед 40 кг, Борису 80 кг» или поднять вес сверх прошлого раза.

Тренер задаёт клиенту по каждому упражнению назначенного шаблона «подходы × повторы × вес». Задание действует во всех назначениях этого шаблона клиенту, пока тренер его не изменит, и при запуске важнее собственной истории клиента. Любое поле можно оставить пустым — тогда как сейчас.

Критерии успеха:
- тренер за минуту выставляет клиенту задания по шаблону из вкладки «План»;
- клиент нажимает «Начать» (план, дашборд, «От тренера») и видит в подходах ровно задание, с пометкой «от тренера: …»;
- другой клиент по тому же шаблону получает своё задание или, без него, свою историю;
- после отключения тренера его заданий нет.

Вне этапа: проценты от 1ПМ, разные веса по подходам, автоматический рост веса (программы с прогрессией), «задано / сделано» в сводке, уведомление клиенту об изменении заданий.

## Модель данных

```prisma
/// Задание тренера клиенту по упражнению шаблона (режим тренера). Тренер — владелец шаблона.
model CoachTarget {
  id         String   @id @default(cuid())
  clientId   String
  templateId String
  exerciseId String
  sets       Int?
  reps       Int?
  weight     Float?
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt

  client   User            @relation(fields: [clientId], references: [id], onDelete: Cascade)
  template WorkoutTemplate @relation(fields: [templateId], references: [id], onDelete: Cascade)
  exercise Exercise        @relation(fields: [exerciseId], references: [id], onDelete: Cascade)

  @@unique([clientId, templateId, exerciseId])
}
```

- Связь — с упражнением, а не со строкой `TemplateExercise`: редактор шаблона при сохранении пересоздаёт строки (`deleteMany` + `createMany`), задания по строкам слетали бы при каждой правке. Упражнение убрали из шаблона — задание остаётся в таблице, но не читается (запуск и диалог идут по упражнениям шаблона); вернули — снова действует.
- Упражнение встречается в шаблоне дважды — задание применяется к обоим вхождениям.
- Тренера в строке нет: шаблон всегда его (назначать можно только свои шаблоны — `coachTemplate` в `lib/coach/plan-actions.ts`).
- Строки без единого заполненного поля не храним.

## Запуск тренировки

`fromTemplate` (`lib/workouts/actions.ts`): если шаблон принадлежит активному тренеру клиента (`CoachLink` с `endedAt = null`, `template.userId = coachId`), читаем задания клиента по шаблону и строим подходы чистой функцией `applyTargets` (`lib/coach/targets.ts`). По каждому упражнению:

| поле | порядок |
|---|---|
| число подходов | задание → `targetSets` шаблона |
| повторы | задание → `targetReps` шаблона → история клиента (того же подхода; лишний подход — 0, как сейчас) → 0 |
| вес | задание → история клиента (по номеру подхода, затем последний) → `targetWeight` шаблона → 0 |

Без задания поведение не меняется (та же функция, задания пустые) — это фиксируют unit-тесты на текущие правила.

Срабатывает при любом запуске шаблона: `template:<id>` («От тренера») и `plan:<ключ>` (дашборд, календарь, `/training`). `repeat:` и `recovery` задания не читают.

## Тренер: вкладка «План»

Раздел «Задания по шаблонам» под «Ближайшими 2 неделями» (`components/coach/client-targets.tsx`):
- список — шаблоны тренера в актуальных назначениях клиента, тот же отбор, что раздел «От тренера» у клиента (`assignedWhere` в `lib/coach/templates.ts`, вынести для тренера с явным `coachId`);
- строка: «Ноги — база · задано 3 из 5 упражнений» (или «заданий нет») и кнопка «Задания» (`aria-label` «Задания: <шаблон>»);
- нет актуальных назначений — раздела нет.

Диалог «Задания: <шаблон>»:
- строка на упражнение шаблона (в порядке шаблона, архивные пропускаются): название и поля «Подходы», «Повторы», «Вес, кг» (подписи с названием упражнения для скринридера);
- placeholder пустого поля — что подставится без задания: подходы и повторы шаблона, вес — «как в прошлый раз» (или вес шаблона);
- под строкой — последний результат клиента: «в прошлый раз: 62,5 × 6 · 3 подхода, 5 окт.» (`getLastPerformance` по клиенту, дата в поясе клиента) или «ещё не выполнялось» (без рода);
- «Сохранить» — все строки разом; строка со всеми пустыми полями удаляет задание.

Сервер — `saveTargetsAction(clientId, templateId, items)` в `lib/coach/target-actions.ts`:
- доступ — `requireClientOf(clientId)`; шаблон — тренера и в актуальных назначениях клиента, иначе «Шаблон не назначен клиенту»;
- `items: { exerciseId, sets, reps, weight }[]`, схема Zod (`targetSchema` в `lib/coach/targets.ts`): подходы 1…20, повторы 1…100, вес 0…1000 (дробный), каждое `null`; `exerciseId` — только упражнения шаблона, иначе отказ;
- в транзакции: `deleteMany` строк шаблона для клиента по упражнениям без значений, `upsert` остальных;
- цель Метрики `coach_targets` — при первом сохранении заданий по шаблону для клиента (до сохранения строк не было);
- `revalidatePath` карточки клиента и `/training`.

Чтение — `getClientTargets(clientId, coachId)` в `lib/coach/target-queries.ts`: для каждого актуального шаблона — упражнения шаблона, задания, последний результат клиента.

## Клиент

- Подходы при запуске заполнены по заданию; клиент правит их как обычно — это его тренировка.
- Пометка в редакторе под названием упражнения: «от тренера: 4 × 8 · 60 кг» (`formatTarget`: пустые поля пропускаются — «от тренера: 60 кг», «от тренера: 4 × 8»; вес — через `formatWeight`).
- Пометка не хранится в тренировке, а читается страницей `/training`: если `workout.templateId` — шаблон активного тренера, берём его текущие задания по шаблону (`getWorkoutTargets`). Почему: черновик при автосохранении пересоздаёт строки упражнений, хранить задание в тренировке значило бы протаскивать его через состояние редактора, офлайн-копию и схему черновика. Цена: изменение задания посреди тренировки меняет пометку, но не уже заполненные подходы. Без сети пометка — из сохранённой копии страницы.
- `hideWeights` клиента на задания не влияет (это настройка для друзей).

## Разрыв связи

Где сейчас при отключении/смене тренера удаляются назначения прежнего тренера (`lib/coach/actions.ts`), в той же транзакции — `coachTarget.deleteMany({ where: { clientId, template: { userId: coachId } } })`. Повторное подключение — с чистого листа.

## Тесты

Unit (`lib/coach/targets.test.ts`):
- `applyTargets`: без заданий — текущие правила (история по номеру подхода, затем последний; повторы шаблона важнее истории; вес шаблона — только без истории); полное задание — всё из него; частичное — только заданные поля; число подходов из задания больше/меньше шаблона; нет истории;
- `formatTarget`: все поля, только вес, только подходы × повторы, дробный вес;
- `targetSchema`: пределы, `null`.

e2e (`e2e/coach-targets.spec.ts`, хелпер `coachTarget` в `e2e/db.ts`):
1. тренер открывает «Задания» для назначенного шаблона, задаёт «Приседания со штангой» 4 × 8 · 60 кг; клиент запускает с дашборда — 4 подхода по 60 кг × 8 и пометка «от тренера: 4 × 8 · 60 кг»;
2. второй клиент того же тренера без заданий по тому же шаблону — вес из своей истории;
3. запуск из «От тренера» применяет задания;
4. тренер очищает все поля упражнения — задание удалено, пометки нет;
5. клиент отключает тренера — заданий в БД нет;
6. диалог показывает «в прошлый раз: …» по истории клиента.
