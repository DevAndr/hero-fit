# «Что нового»: страница релизов

Релиз `release/2026-11-assistant` (первая фича). Ветка релиза создана от `release/2026-10-raids` — тот ещё не влит в
`main`.

## Цель

Пользователи видят, что приложение развивается: публичная страница релизов (доверие, SEO, повод рассказать в Telegram)
и «Что нового» в кабинете с точкой, пока есть непросмотренный релиз (повод вернуться и попробовать новое).

## Решения

### Источник — файл в репозитории

`lib/changelog/releases.ts` — массив `RELEASES` (новые сверху), без БД и админки; запись добавляется в PR релиза
(шаг чек-листа релиза в CLAUDE.md).

```ts
type ChangeItem = { text: string; href?: string; flag?: FlagKey };
type Release = { id: string; date: string; title: string; summary: string; new: ChangeItem[]; improved?: ChangeItem[]; fixed?: ChangeItem[] };
```

- `id` — ключ релиза и якорь (`2026-10`), `date` — `YYYY-MM-DD` (дата выхода), `title` — человеческий заголовок
  («Гильдии, рейды и цели»), `summary` — одна-две фразы.
- `href` — ссылка внутри приложения (`/guild`, `/goals`); на публичной странице показывается только у публичных путей
  (`/`, `/#…`, `/tools/…`), иначе — текстом без ссылки.
- `flag` — пункт фичи под флагом: виден, только если флаг включён у смотрящего; на публичной странице — только при
  раскатке на 100 % (`flagOn(key, state, null)` — правило гостя).
- Чистые функции `lib/changelog/view.ts`: `visibleRelease(release, enabled: (flag) => boolean)` — пункты без скрытых
  флагом, раздел без пунктов не показывается, релиз без пунктов — тоже; `latestReleaseId(releases)`;
  `hasUnseen(releases, seenId: string | null)` — есть релиз новее просмотренного (по порядку в массиве; `seenId`
  неизвестен — считается, что новое есть).
- Unit-тест данных: `id` уникальны, даты убывают, у каждого релиза есть хотя бы один пункт, `flag` — из реестра.

Первая запись — текущий релиз `2026-10` («Гильдии, рейды и цели»): гильдии и рейд-босс, цели и журнал веса, ачивки
тренера и награды на его странице, «Ты стал сильнее» и прогноз целей (`flag: "strength_analytics"`), — тексты
человеческие, без внутренних терминов (флаги, админка — не упоминаются).

### Публичная страница `/changelog`

- `app/(marketing)/changelog/page.tsx` — «Что нового в Hero Fit»: релизы по порядку, у каждого — дата, заголовок,
  описание, разделы «Новое / Улучшено / Исправлено» (якорь `#<id>`).
- Публичная: `/changelog` в `PUBLIC_PAGES` (`proxy.ts`), в `PUBLIC_SITEMAP` (`priority 0.5`, `weekly`), metadata —
  заголовок и описание в `lib/seo.ts`, canonical `/changelog`.
- Флаги — по правилу гостя (только 100 %).

### Лендинг

- Ссылка «Что нового» в подвале (`components/marketing/site-footer.tsx`, колонка «Продукт») и в шапке
  (`site-header.tsx`, после «Тарифы»).
- На главной под героем — строка-плашка «Новое: <title последнего релиза> →» на `/changelog#<id>`
  (`components/marketing/whats-new-link.tsx`), только если последний релиз не старше 60 дней.

### В кабинете

- `User.changelogSeen String?` — `id` последнего просмотренного релиза (миграция `changelog_seen`; у существующих при
  миграции — `null`, т. е. увидят точку на первый релиз).
- Пункт «Что нового» в меню профиля (`components/app/user-menu.tsx`) с точкой, если `hasUnseen`; ведёт на `/whats-new`.
- `app/(app)/whats-new/page.tsx` — те же релизы, но флаги — по пользователю (`isEnabled`), ссылки — все внутренние;
  открытие помечает просмотренным: `markChangelogSeen(userId, latestId)` (условный `updateMany`, только если не равен).
- Точка на иконке меню профиля (аватар) — тоже, чтобы было видно без открытия меню. `CurrentUser.changelogSeen`.
- Новые пользователи (регистрация, Telegram) — `changelogSeen` = последний релиз сразу: для них всё новое, точка не нужна.
- В e2e — новые пользователи без точки; хелпер `setChangelogSeen(login, id | null)`.

### Процесс (CLAUDE.md)

Чек-лист релиза: в PR `release/…` → `main` добавить запись в `RELEASES` (черновик по спекам, человеческим языком, пункты
фич под флагом — с `flag`).

## Вне рамок

Рассылка о релизе (push/Telegram), RSS, комментарии и реакции, админка для записей, переводы.

## Тесты

- Unit: `visibleRelease` (флаг выключен — пункт скрыт, пустой раздел и пустой релиз скрыты, ссылка у непубличного пути
  на публичной странице — без ссылки), `hasUnseen` (`null`, последний, старый, неизвестный id), данные `RELEASES`.
- e2e (`e2e/changelog.spec.ts`): гость открывает `/changelog` из подвала лендинга — виден заголовок первого релиза;
  пункт под `strength_analytics` гостю не виден (флаг выключен); пользователь с `setChangelogSeen(login, null)` видит
  точку и «Что нового» в меню → `/whats-new` → точка пропадает после перезагрузки; новый пользователь без точки.
