# Режим тренера, этап 1: связь тренер ↔ клиент и просмотр — дизайн

Дата: 2026-10-09. Ветка `feat/coach-clients`.

## Зачем

Hero Fit как продукт для персональных тренеров: тренер видит тренировки и прогресс своих клиентов, клиент тренируется в привычном приложении с игровой мотивацией. Модель денег — платит тренер (этап 4), клиентов приводит он сам.

Режим тренера разбит на этапы, каждый со своей спекой:
1. **Связь тренер ↔ клиент и просмотр** — этот документ.
2. Назначение программ клиенту (шаблон → календарь клиента).
3. Комментарии тренера к тренировкам.
4. Тарифы и лимиты клиентов (после ИП и платёжки).

Критерии успеха этапа 1:
- тренер включает режим, приглашает клиента ссылкой, клиент явно соглашается;
- тренер видит список клиентов с метками внимания и по каждому — то же, что видит сам клиент: тренировки с подходами, статистику, рекорды, карту мышц;
- любая сторона разрывает связь в один клик, доступ пропадает сразу;
- без активной связи данные клиента недоступны (404).

Не входит: программы, комментарии, чат, несколько тренеров у клиента, группы, отдельный тип аккаунта тренера, оплата и лимиты, доступ тренера к календарю клиента.

## Роли и связь

- Тренер — обычный пользователь с включённым режимом (`User.isCoach`); свои тренировки, уровни и боссы у него остаются.
- Включить режим можно только с публичным ником (`User.nickname`): клиент видит тренера по нику, логин и почта никому не показываются. Выключение режима не разрывает связи, но скрывает раздел «Клиенты»; при повторном включении клиенты на месте.
- У клиента не больше **одного** активного тренера. Тренер не может быть клиентом сам себе.
- Связь создаёт клиент, нажав «Разрешить» на экране согласия; отдельного подтверждения тренера нет (ссылку раздал он).

## Модель данных

```prisma
model CoachLink {
  id        String    @id @default(cuid())
  coachId   String
  clientId  String
  createdAt DateTime  @default(now())
  endedAt   DateTime? // разрыв: клиент отключил, тренер удалил или клиент перешёл к другому
  endedBy   String?   // "client" | "coach" | "switch"

  coach  User @relation("CoachLinkCoach", fields: [coachId], references: [id], onDelete: Cascade)
  client User @relation("CoachLinkClient", fields: [clientId], references: [id], onDelete: Cascade)

  @@index([coachId, endedAt])
  @@index([clientId, endedAt])
}
```

- Активная связь — `endedAt IS NULL`. Одна активная на клиента — частичный уникальный индекс в миграции: `CREATE UNIQUE INDEX "CoachLink_active_client" ON "CoachLink"("clientId") WHERE "endedAt" IS NULL`.
- `User.isCoach Boolean @default(false)`, `User.coachCode String? @unique` — код приглашения (формат и генерация как у `friendCode`: `ABCD-1234`, создаётся при первом включении режима).
- Разорванные связи храним (история «клиент с … по …»), доступ даёт только активная.
- `NotificationType.COACH` — новые и ушедшие клиенты, отключение тренером.

## Сценарии

**Включение режима** (`/settings`, карточка «Режим тренера»): переключатель; без ника — подсказка и ссылка на форму ника, переключатель неактивен. `setCoachModeAction(on)`: проверка ника, `isCoach`, создание `coachCode` при необходимости.

**Приглашение**: на `/coach` — ссылка `${APP_URL}/coach/join/<код без дефиса>`, кнопка «Скопировать», код. Код — без учёта регистра и дефиса (как код друга).

**Согласие** (`/coach/join/[code]`, страница кабинета — без входа `proxy.ts` ведёт на вход/регистрацию и обратно через `next`):
- неизвестный код или режим тренера выключен — «Ссылка недействительна»;
- свой код — «Это ваша ссылка — отправьте её клиенту»;
- уже клиент этого тренера — «Вы уже занимаетесь с <ник>» и ссылка на дашборд;
- иначе: «Тренер **<ник>** просит доступ к вашим тренировкам», список: тренировки с подходами и весами, статистика и рекорды, карта мышц; строка «Доступ можно отозвать в любой момент в настройках»; если есть другой тренер — «Сейчас ваш тренер — <ник>. Перейти к <ник>?». Кнопки «Разрешить» и «Отказаться» (на дашборд).
- `acceptCoachAction(code)` в одной транзакции: закрыть текущую активную связь клиента (`endedBy = "switch"`, уведомление прежнему тренеру «<клиент> перешёл к другому тренеру»), создать новую, уведомление тренеру «Новый клиент: <клиент>». Гонка двух вкладок — частичный уникальный индекс; повтор с тем же тренером — без ошибки (уже связаны).

**Разрыв**:
- клиент: `/settings`, карточка «Мой тренер» (только при активной связи) — ник, «с <дата>», «Отключить тренера» с подтверждением → `endCoachLinkAction()`; уведомление тренеру «<клиент> отключил доступ»;
- тренер: карточка клиента, «Удалить клиента» с подтверждением → `removeClientAction(clientId)`; уведомление клиенту «Тренер <ник> завершил работу с вами».

**Имя клиента для тренера**: ник, иначе имя (`User.name`), иначе «Клиент». Логин и почту тренер не видит.

## Доступ

`lib/coach/access.ts` (server-only):
- `requireCoach(): CurrentUser` — вошёл и `isCoach`, иначе 404;
- `requireClientOf(clientId): { coach, client }` — активная связь `coachId = me`, иначе `notFound()`.

Каждая страница и действие тренера над данными клиента начинается с `requireClientOf`. Данные клиента читаются существующими запросами с `userId = clientId`. `hideWeights` к тренеру не применяется (согласие дано явно). Страницы тренера — `noindex` (как весь кабинет).

## Интерфейс

**`/coach` — «Клиенты»**: карточка приглашения; список клиентов. Строка клиента: имя, уровень, последняя тренировка («сегодня», «вчера», «N дней назад», «ещё не тренировался»), тренировок на этой неделе в поясе клиента («2 из 3»), серия, метки:
- **«7+ дней без тренировок»** — последняя завершённая тренировка 7+ дней назад (или ни одной и подключён 7+ дней назад);
- **«Пора увеличить вес: N»** — число упражнений с подсказкой прогрессии (`getProgressionHints` по упражнениям клиента за 30 дней).

Сортировка — чистая `sortClients`: сначала с метками (неактивные, затем с подсказками), внутри — по давности последней тренировки (давние выше); без меток — по свежести (свежие выше). Пустое состояние — подсказка «Отправьте ссылку клиенту».

**`/coach/clients/[id]`** — шапка: имя, «клиент с <дата>», «Удалить клиента». Вкладки (`?tab=`):
- **Обзор** — цифры (тренировок за 7 и 30 дней, объём за 30 дней, время в зале за 7 дней, серия, уровень), `BodyMap` (восстановление и баланс), подсказки прогрессии по упражнениям;
- **Тренировки** — завершённые тренировки клиента, новые сверху, подгрузка по 20 (курсор `finishedAt, id`); строка ведёт на `/coach/clients/[id]/workouts/[wid]` — сводка как у клиента, только чтение (без «Сохранить как шаблон», «Обновить шаблон», «Поделиться», сундука босса);
- **Статистика** — тренды и рекорды как на `/stats`; упражнение ведёт на `/coach/clients/[id]/exercises/[exId]` — график силы как на `/stats/exercises/[id]`.

**Навигация**: «Клиенты» (иконка `Users`/`ClipboardList`) — в `SidebarNav` и в меню профиля, только при `isCoach`. Нижнее меню не меняется.

## Переиспользование страниц

`/stats`, `/stats/exercises/[id]` и `/workouts/[id]` разделяются на загрузку (страница) и отображение (компонент, принимает данные и `basePath` для ссылок, флаг `readOnly` у сводки). Свои страницы и страницы тренера используют одни компоненты. Поведение своих страниц не меняется — защищают существующие e2e.

## Политика конфиденциальности

Раздел 4 «Кто ещё видит данные» — пункт: «Ваш тренер — только если вы сами подключили его по ссылке и разрешили доступ: тренировки с подходами и весами, статистику, рекорды и карту мышц. Доступ отключается в настройках в любой момент». Дата редакции — дата выпуска.

## Метрика

Цели: `coach_enabled` (включил режим), `coach_client_joined` (клиент разрешил доступ — ставится у клиента).

## Тесты

Unit:
- `sortClients` и метки (`clientFlags`): неактивный 7+ дней, без тренировок, с подсказками, порядок;
- `clientDisplayName`: ник → имя → «Клиент»;
- нормализация кода приглашения (регистр, дефис).

e2e (`e2e/coach.spec.ts`, desktop + mobile; связи можно готовить SQL-хелпером `linkCoach` в `e2e/db.ts`):
- без ника режим не включается; с ником — включается, есть ссылка и код;
- клиент по ссылке (не вошедший → вход → обратно) видит согласие, «Разрешить» → у тренера клиент в списке и уведомление;
- тренер открывает тренировку клиента и видит веса при включённом у клиента «Скрыть веса»; вкладки «Обзор» и «Статистика» открываются;
- тренер без связи (другой пользователь с режимом) — 404 на карточку клиента и на его тренировку;
- клиент отключает тренера → у тренера 404 и уведомление;
- переход к другому тренеру закрывает старую связь, старый тренер — 404 и уведомление;
- тренер удаляет клиента → карточка «Мой тренер» у клиента пропадает, клиенту уведомление;
- свой код и неизвестный код — соответствующие сообщения;
- существующие e2e `/stats` и сводки тренировки — без изменений.
