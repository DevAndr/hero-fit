# Питание, подпроект 2: дневник питания

Дата: 2026-10-31. Флаг: `nutrition` (тот же, что у подпроекта 1). Ветка: `feat/nutrition-diary` от `release/2028-01-stale-workouts`.

## Контекст

Подпроект 1 (`2026-10-31-nutrition-norm-design.md`) дал `/nutrition` с нормой ккал/БЖУ и расходом на тренировках. Здесь —
дневник: записи еды по приёмам пищи с ручным вводом ккал и БЖУ, итог дня против нормы. База продуктов — подпроект 3,
дашборд/XP/ачивки — подпроект 4.

Решения пользователя: 4 приёма пищи; быстрый ввод — «Недавние», «Повторить вчерашний приём», «Добавить сегодня» из истории.

## Данные

Модель `FoodEntry` (миграция `food_entries`):

| Поле | Тип | Правила |
|---|---|---|
| `id` | `String @id @default(cuid())` | |
| `userId` | `String` → `User` (`onDelete: Cascade`) | |
| `date` | `String` | местная дата `YYYY-MM-DD`, как `BodyWeightEntry` |
| `meal` | `Meal` (`BREAKFAST` · `LUNCH` · `DINNER` · `SNACK`) | |
| `name` | `String` | 1…80 символов, обрезка пробелов |
| `kcal` | `Int` | 0…5000 |
| `protein`, `fat`, `carbs` | `Float?` | 0…500 г, до 0,1; пусто → `null` |
| `createdAt` | `DateTime @default(now())` | порядок внутри приёма |

Индекс `@@index([userId, date])`.

## Чистые функции

- `lib/nutrition/food-schema.ts` — `foodEntrySchema` (Zod, из FormData): `meal`, `name`, `kcal`, `protein?`, `fat?`,
  `carbs?`; запятая как разделитель; пустые Б/Ж/У → `null`. Дата проверяется отдельно (`parseDiaryDate`).
- `lib/nutrition/diary.ts`:
  - `MEALS` (порядок) и `MEAL_LABELS` («Завтрак», «Обед», «Ужин», «Перекус»);
  - `defaultMeal(hour)`: `< 11` — завтрак, `< 16` — обед, `< 21` — ужин, иначе перекус;
  - `dayTotals(entries)` → `{ total: Macros; byMeal: Record<Meal, Macros> }`, `Macros = { kcal, protein, fat, carbs }`
    (Б/Ж/У без значения — 0, граммы округлены до 0,1);
  - `balance(totalKcal, normKcal)` → `{ left: number } | { over: number }`;
  - `parseDiaryDate(raw, today)` → дата: мусор, пусто и будущее → `today`; раньше `today − 365` → `today − 365`.

## Запросы и действия

- `lib/nutrition/food-queries.ts`:
  - `getDiaryDay(userId, date)` — записи дня (по `createdAt`) и `yesterdayMeals: Meal[]` — приёмы, в которых есть записи
    за `date − 1` (для «Повторить вчерашний»);
  - `getRecentFoods(userId, today)` — до 8 уникальных `lower(name)` за 30 дней, по частоте, затем по свежести; значения
    (ккал/БЖУ, исходное написание названия) — из последней записи с этим названием.
- `lib/nutrition/food-actions.ts` (все — `requireUser`, флаг → `notFound()`, только свои записи, `revalidatePath("/nutrition")`):
  - `addFoodEntryAction(date, _prev, formData)` и `updateFoodEntryAction(id, _prev, formData)` — состояние формы
    `{ ok?, errors?, values? }` (введённое возвращается при ошибке, как в анкете подпроекта 1); дата — через
    `parseDiaryDate` по местному «сегодня» пользователя, будущие даты не принимаются;
  - `deleteFoodEntryAction(id)`;
  - `copyFoodEntryToTodayAction(id)` — копия в тот же приём на местное «сегодня»;
  - `repeatYesterdayMealAction(date, meal)` — копирует записи приёма с `date − 1` на `date`, если в приёме `date` записей
    нет (иначе ничего).

## Интерфейс (`/nutrition`)

1. Навигация по дням: «‹» · «31 октября» (или «Сегодня») · «›», адрес `?date=YYYY-MM-DD`; «›» на сегодняшнем дне
   неактивна, «‹» на границе года — тоже.
2. «Итог дня» (`aria-label`): «1 450 / 2 760 ккал», полоса (`primary`, при перерасходе `destructive`), «Осталось 1 310» или
   «+120 сверх нормы»; полоски Б/Ж/У «съедено / норма, г». Без нормы — суммы без полос и ссылка «Посчитать норму»
   (открывает анкету).
3. Блоки приёмов (`region` с названием приёма): сумма ккал; строки — название, «Б 30 · Ж 10 · У 0» (только указанные),
   ккал; меню «⋯»: «Изменить», «Удалить», на прошлых днях — «Добавить сегодня». Внизу — «Добавить». У пустого приёма,
   если вчера в нём были записи, — «Повторить вчерашний».
4. Ниже — «Норма на день» и «Расход на тренировках» (подпроект 1, без изменений).

Диалог `FoodEntryDialog` («Добавить: Завтрак» / «Изменить запись»): приём (радио), название, ккал, белки, жиры, углеводы
(числа — `selectOnFocus`), над полями — чипы «Недавние» (заполняют поля). Приём по умолчанию — блок, где нажали
«Добавить».
