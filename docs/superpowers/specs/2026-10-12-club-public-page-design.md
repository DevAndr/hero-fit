# Публичная страница клуба и SEO

Релиз `release/2026-11-assistant` (6-я фича), под флагом `clubs`. Основа — клубы цикл 1 (`2026-10-12-clubs-design.md`)
и цикл 2 (`2026-10-12-club-tasks-design.md`); образец — публичная страница тренера
(`2026-10-10-coach-public-page-design.md`).

## Цель

Зал получает страницу, которую можно найти в поиске («тренажёрный зал <город>») и раздать в соцсетях: что за зал, сколько
людей в нём тренируется в Hero Fit, какие задания идут сейчас — и кнопка «Вступить». Публикует админ клуба. На странице
только общие цифры клуба, без ников: участники соглашались показывать себя клубу, а не интернету.

## Данные

Поля в `Club` (без отдельной таблицы):

- `about String @default("")` — «О зале», до 1000 символов (`CLUB_ABOUT_MAX`).
- `slug String?`, `citySlug String?` — транслит, ставятся при **первой** публикации и больше не меняются (правка названия
  или города модератором адрес страницы не двигает). `@@unique([citySlug, slug])`.
- `publishedAt DateTime?` — опубликована.
- `updatedAt DateTime @updatedAt` (миграция — `DEFAULT now()` для существующих строк) — для `sitemap.xml`.

Индекс `@@index([publishedAt, citySlug])`.

## Правила — `lib/club/public.ts` (чистые)

- `slugify(text)`: нижний регистр, `ё` → `е`, транслит кириллицы (таблица в коде, как в загранпаспорте: `ж` → `zh`,
  `х` → `kh`, `ц` → `ts`, `ч` → `ch`, `ш` → `sh`, `щ` → `shch`, `ы` → `y`, `ъ`/`ь` — пропуск, `э` → `e`, `ю` → `yu`,
  `я` → `ya`, `й` → `y`), всё кроме `a–z0–9` → `-`, повторы схлопываются, края обрезаются, до 60 символов; пусто → `club`
  (для города — `city`).
- `slugCandidates(name, address)`: `slugify(name)`, затем `slugify(name + " " + улица)` (улица — первая часть адреса до
  запятой без «ул.», «пр.», «д.»), затем `<slug>-2` … `<slug>-20`.
- `canPublish({ status, about })`: `status !== "APPROVED"` → «Клуб ещё на проверке» (для `HIDDEN`/`REJECTED` —
  «Клуб скрыт модератором» / «Заявка отклонена»), `about.trim().length < CLUB_ABOUT_MIN` (50) → «Напишите о зале хотя бы
  50 символов», иначе `null`.
- `aboutSchema` — zod: строка, trim, до 1000.
- `MIN_MEMBERS_FOR_STATS = 3`; `visibleClubStats(stats)`: при `members < 3` — только число участников, иначе ещё
  тренировки за неделю, за 30 дней и часы за 30 дней (часы округляются до целых).
- `clubPath(citySlug, slug)` → `/gym/<city>/<slug>`, `cityPath(citySlug)`.

## Видимость

Страница открыта всем, когда клуб `APPROVED`, есть `publishedAt` и флаг `clubs` на 100 % (`isEnabled("clubs", null)`).
Иначе:

- админ клуба (`Club.adminId`) и админ приложения (`isAdmin`) видят **предпросмотр** с плашкой «Страница пока не видна
  в поиске» и `robots: noindex` — если клуб `APPROVED` и есть slug (публиковался хоть раз; снятая с публикации — тоже);
- `HIDDEN` и `REJECTED` — 404 всем, и предпросмотра нет;
- всем остальным — 404.

Генерация метаданных у закрытой страницы ничего не раскрывает (как у тренера). Страница города `/gym/<city>` открыта по
тем же условиям при хотя бы одном открытом клубе в городе, иначе 404 (предпросмотра нет).

Флаг — по правилам фича-флагов, без исключений: пока `clubs` выдан списком, гости страниц не видят, в `sitemap.xml` их
нет. Включили на 100 % — все опубликованные страницы появляются разом.

## Страницы — `app/(marketing)/gym/`

`proxy.ts`: `/gym/` в `PUBLIC_PREFIXES`.

### `/gym/[city]/[slug]` — страница клуба

Запрос — `getPublicClub(citySlug, slug)` (`lib/club/public-queries.ts`, `cache` на запрос, как `findCoach`).

- **Шапка:** название (`h1`, `font-display`), город и адрес с `MapPin`. Действие: участнику этого клуба — «Вы в этом
  клубе» и ссылка «Открыть клуб» на `/clubs/<id>`; админу клуба — «Редактировать» → `/clubs/<id>/manage#public`;
  остальным (и гостям) — «Вступить» → `/gym/<city>/<slug>/join` (`prefetch={false}`). Участник другого клуба тоже видит
  «Вступить» (экран согласия предупредит о переходе — как сейчас).
- **«О зале»:** `whitespace-pre-line`, ссылки не превращаются в ссылки.
- **Цифры:** `getClubPublicStats(clubId)` — участников; завершённые тренировки текущих участников с `finishedAt ≥ joinedAt`
  за 7 и 30 дней (скользящие окна, без поясов — страница общая); сумма `durationSec` за 30 дней. Показ — `visibleClubStats`.
- **Задания:** `getClubTasks(clubId, viewerId ?? "", false, "UTC")` — активные (`active`): у «всем клубом» — название,
  полоса и `done / target`, у «каждому» — название; у обоих срок («осталось N дней» / «стартует …»). Без заданий блока нет.
  Компонент — `PublicClubTasks` (серверный, без сундуков).
- **«Как это работает»:** 3 шага — «Нажмите «Вступить» и создайте аккаунт — это бесплатно», «Тренируйтесь и поднимайтесь
  в рейтинге зала», «Выполняйте задания клуба вместе и открывайте сундуки».

### `/gym/[city]/[slug]/join` — route handler

Как `/trainer/[nick]/join`: открытая страница (те же условия видимости, без предпросмотра) → `queueGoal("club_page_join")`
→ вошедшему `/clubs/join/<code>`, гостю `/register?next=/clubs/join/<code>`. Дальше — существующий экран согласия
(гость после регистрации без флага получил бы 404, но страница открыта только при 100 %).

### `/gym/[city]` — залы города

`getCityClubs(citySlug)`: открытые клубы города, по числу участников (убывание), затем по названию. Название города —
`city` самого крупного клуба. Карточка: название, адрес, «N участников», от 3 участников — «N тренировок за неделю».
`h1` — «Залы в Hero Fit — <Город>».

## SEO — `lib/seo.ts`

- `coachDescription` → `shortDescription(text, max = 160)` (общая; вызов у тренера переименовывается).
- Клуб: `title` — «<Название> — тренажёрный зал, <Город> · Hero Fit», `description` — `shortDescription(about)`,
  `alternates.canonical` — `clubPath`, OpenGraph (title, description, url). Предпросмотр — `robots: { index: false }`.
- `clubJsonLd({ name, url, city, address, description })` — `@type: "ExerciseGym"`, `address` → `PostalAddress`
  (`addressLocality`, `streetAddress`, `addressCountry: "RU"`), через `jsonLd` (экранирует `<`).
- Город: `title` — «Тренажёрные залы — <Город> · Hero Fit», описание — «Залы <Города> в Hero Fit: рейтинг, общие
  задания и …» (одна строка), JSON-LD `ItemList` из `clubPath`.
- `sitemapEntries` получает ещё `clubs: { path, updatedAt }[]` и `cities: { path, updatedAt }[]` (город — максимальный
  `updatedAt` его клубов); `app/sitemap.ts` читает их только при `isEnabled("clubs", null)`.

## Редактор — `/clubs/[id]/manage`, раздел «Публичная страница» (`id="public"`)

Компонент `ManagePublicPage` (`components/club/manage-public-page.tsx`):

- «О зале» — textarea со счётчиком `N / 1000`, «Сохранить» (`saveClubAboutAction`).
- Не опубликована: «Опубликовать» (`publishClubPageAction`); если `canPublish` не пропускает — кнопка неактивна, под
  ней причина.
- Опубликована: ссылка на страницу (полный адрес, «Скопировать»), «Снять с публикации» (`unpublishClubPageAction`);
  пока флаг не на 100 % — строка «Страница появится в поиске, когда клубы откроются для всех».

Действия — в `lib/club/actions.ts`, доступ — как у `updateClubAction` (админ клуба, флаг `clubsAllowed`):

- `saveClubAboutAction(clubId, about)`: `aboutSchema`; у опубликованной — пустое или короче 50 не сохраняется
  («Чтобы убрать текст, снимите страницу с публикации»).
- `publishClubPageAction(clubId)`: `canPublish`; slug нет — перебор `slugCandidates` (`citySlug = slugify(city)`),
  каждая попытка — `update` с `slug`, `citySlug`, `publishedAt`; P2002 → следующий кандидат, кончились — «Не удалось
  подобрать адрес, напишите нам». Slug уже есть — только `publishedAt = now()`. Цель Метрики `club_page_published`.
  `revalidatePath` страницы клуба и manage.
- `unpublishClubPageAction(clubId)`: `publishedAt = null`, slug остаётся.

## Модерация — `/admin/clubs`

- В карточке клуба — «О зале» (свёрнуто до 3 строк) и, если опубликована, ссылка на страницу.
- «Снять с публикации» с причиной (обязательна, до 200) — `unpublishClubByModeratorAction` (`requireAdmin`): условный
  `updateMany` по `publishedAt: { not: null }`, уведомление админу клуба `SOCIAL`: «Страница клуба «…» снята с
  публикации: <причина>», ссылка `/clubs/<id>/manage#public`. Повторно опубликовать после правки можно.
- `HIDDEN` по-прежнему убирает и клуб, и страницу (видимость проверяет статус).

## Аналитика

Цели Метрики `club_page_published` (сервер, `queueGoal`) и `club_page_join` (route handler).

- e2e `e2e/club-public-page.spec.ts` — `mode: "serial"`, только проект desktop (глобальный флаг: `setFlag`/`resetFlag`,
  как `e2e/strength-analytics.spec.ts`):
  1. Флаг списком: админ клуба пишет «О зале» короче 50 → «Опубликовать» неактивна с причиной; дописывает → публикует →
     открывает страницу: плашка предпросмотра, `meta robots noindex`; гость (новый контекст) — 404.
  2. Флаг 100 %: гость видит название, адрес, «О зале», задание «всем клубом» с прогрессом; при 2 участниках цифр
     тренировок нет, при 3 — есть; JSON-LD `ExerciseGym`; `/gym/<city>` со списком; `sitemap.xml` содержит адрес клуба.
  3. Гость: «Вступить» → регистрация → экран согласия → вступил (членство в БД).
  4. Модератор снимает с публикации с причиной → гостю 404, админу клуба уведомление; повторная публикация — тот же адрес.
  5. `HIDDEN` → 404 гостю и админу клуба.
  6. Второй клуб с тем же названием в том же городе → адрес с улицей.

  Хелперы в `e2e/db.ts`: `publishClub(clubId, about?)` (SQL: slug и `publishedAt`), `clubSlug(clubId)`.
