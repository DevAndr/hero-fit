# Напоминания о приёмах пищи — дизайн

Дата: 2026-11-13. Ветка: `feat/meal-reminders` от `release/2028-11-meal-reminders`.

## Зачем

Дневник питания ведут те, кто не забывает записывать. Пользователь сам задаёт, когда ему напомнить про завтрак, обед, ужин или перекус, и получает уведомление в это время — если приём ещё не записан.

## Согласовано с пользователем

- Время напоминания задаёт пользователь.
- Свободный список: пользователь сам добавляет напоминания (время + приём пищи), до 6 штук; на один приём можно несколько.
- Если в этом приёме за сегодня уже есть запись — напоминание не приходит.
- Напоминания ежедневные, без дней недели.
- Общего тумблера в `/settings` нет — напоминание выключается в самом списке.
- Отдельного фича-флага нет: всё внутри `/nutrition` под флагом `nutrition`.
- Свой текст напоминания не задаётся.

## Поведение

### Окно «Напоминания»

В меню «⋮» «Итога дня» (`SummaryMenu`) — пункт «Напоминания…». Он есть всегда, когда открыта `/nutrition` (от нормы и вида шкалы не зависит). Открывает диалог `MealRemindersDialog`:

- Список напоминаний по возрастанию времени. В строке: время (`<input type="time">`), приём пищи (выбор из четырёх), тумблер «включено», кнопка удаления.
- Пустой список — текст «Напоминаний пока нет» и кнопка «Добавить напоминание».
- «Добавить напоминание» создаёт строку с приёмом и временем по умолчанию: первый приём по ходу дня, которого ещё нет в списке (завтрак 09:00, обед 14:00, перекус 17:00, ужин 20:00); если все четыре есть — перекус на ближайшее свободное время с шагом 30 минут после последнего напоминания. При 6 напоминаниях кнопка выключена, подпись «Не больше 6 напоминаний».
- Каждое изменение сохраняется сразу (как «Белки, жиры, углеводы» в том же меню), ошибка — уведомлением «Не удалось сохранить — проверьте связь», строка возвращается к прежнему значению.
- Два напоминания на одно время запрещены: сервер отвечает ошибкой, в окне — «На это время уже есть напоминание».
- Если у пользователя нет ни одной push-подписки и не привязан Telegram — под списком подсказка «Чтобы напоминания приходили на телефон, включите уведомления» со ссылкой на `/settings`. В колокольчик напоминания приходят в любом случае.

### Уведомление

- Тип `MEAL_REMINDER`. Заголовок — «Завтрак · 09:00» (название приёма и заданное время), текст — «Запишите завтрак в дневник» (для перекуса — «Запишите перекус в дневник»), ссылка — `/nutrition`.
- Каналы — как у остальных напоминаний: лента приложения, push, Telegram (`notify(…, { push: true })`).
- Иконка в колокольчике — `Utensils`, цвет `text-xp` (как у напоминания курса). Канал Android — `hero-fit-meal` в `lib/notifications/push.ts`.

### Когда приходит

Местное время пользователя (`User.timeZone`). Напоминание «пора», если одновременно:

1. оно включено;
2. местное время сейчас — от заданного включительно до заданного + 60 минут (не включая);
3. сегодня (местный день) по нему ещё не было решения (`remindedDay` ≠ сегодня).

Если «пора», в этом приёме за сегодня нет записей `FoodEntry` и у пользователя включён флаг `nutrition` — уведомление уходит. Если запись есть или флага нет — уведомление не уходит. Во всех случаях `remindedDay` ставится на сегодня: решение по напоминанию принимается один раз в день, в его время. Запись, добавленную и удалённую позже, не пересматриваем.

Следствия:

- Сервер простоял больше часа после времени напоминания — оно пропускается до завтра.
- Окно не переходит через полночь: напоминание на 23:30 действует 23:30–23:59. Это упрощение — тик идёт каждые 5 секунд, окно нужно только на случай простоя.
- Пользователь поменял время напоминания на более позднее в тот же день, когда оно уже сработало — сегодня второй раз не придёт. При смене времени `remindedDay` не сбрасывается.
- Напоминание, созданное или перенесённое на время, которое сегодня уже наступило, сегодня не приходит: при создании и при такой смене времени `remindedDay` ставится на сегодня. Первое срабатывание — завтра.
- Пояс пользователя в SQL-отборе не перепроверяется (как у напоминания о streak): пояс, которого не знает Postgres, остановит шаг.

## Данные

```prisma
/// Напоминание о приёме пищи: ежедневно в местное время пользователя, если приём ещё не записан.
model MealReminder {
  id          String   @id @default(cuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  meal        Meal
  minutes     Int // минуты от местной полуночи, 0…1439
  enabled     Boolean  @default(true)
  remindedDay String? // местный день последнего решения (YYYY-MM-DD)
  createdAt   DateTime @default(now())

  @@unique([userId, minutes])
  @@index([enabled, minutes])
}
```

`NotificationType` получает значение `MEAL_REMINDER`. Одна миграция; частичные индексы из «Сквозных правил» в её SQL не трогаются — проверить.

## Код

### Чистая логика — `lib/nutrition/reminders.ts`

- `MAX_MEAL_REMINDERS = 6`, `MEAL_REMIND_WINDOW_MIN = 60`.
- `mealReminderSchema` (Zod): `meal` — `Meal`, `minutes` — целое 0…1439.
- `parseTime("09:05") → 545 | null`, `formatTime(545) → "09:05"`.
- `localMinutes(now, timeZone) → number` — минуты от местной полуночи.
- `mealReminderDue({ now, timeZone, minutes, enabled, remindedDay }) → { day } | null` — пункты 1–3 из «Когда приходит».
- `mealReminderText(meal, minutes) → { title, body }`.
- `nextDefault(existing) → { meal, minutes }` — значения по умолчанию для «Добавить напоминание».
- Тесты — `lib/nutrition/reminders.test.ts`: границы окна (ровно в срок, +59, +60, до срока), смена суток в поясе пользователя, выключенное, уже решённое сегодня, разбор и вывод времени, тексты для всех четырёх приёмов, `nextDefault` (пустой список, часть приёмов занята, все заняты, занятое время).

### Действия — `lib/nutrition/reminder-actions.ts`

Только свои записи, `requireUser()`, флаг `nutrition` (без него — отказ, как у остальных действий питания).

- `addMealReminderAction({ meal, minutes })` — проверка лимита 6 и уникальности времени в транзакции с блокировкой строки `User` (как «Повторить вчерашний»: двойной клик не создаёт седьмое).
- `updateMealReminderAction(id, { meal?, minutes?, enabled? })`.
- `deleteMealReminderAction(id)`.

Результат — `{ ok: true } | { ok: false; error: string }`; занятое время (нарушение `@@unique`) — «На это время уже есть напоминание». При создании и смене времени `remindedDay` ставится на сегодня, если новое время сегодня уже наступило. После изменения — `revalidatePath("/nutrition")`.

### Запрос — `lib/nutrition/reminder-queries.ts`

`getMealReminders(userId)` → список по возрастанию `minutes` и признак `canPush` (есть push-подписка или привязанный Telegram). Вызывается на странице `/nutrition`, результат передаётся в `SummaryMenu`.

### Тик — `lib/nutrition/reminder-tick.ts`

`processMealReminders(now)`, шаг `"meals"` в `TICK_STEPS` и в `runNotificationTick` (после `course`, в своём `try/catch`, после отправки — `processDuePushes()`):

1. Кандидаты — одним SQL с грубым отбором по местному времени (как `processStreakReminders`): `enabled`, местные минуты в окне `[minutes, minutes + 60)`, `remindedDay` отличается от местного «сегодня». `LIMIT 500`, порядок — `minutes`, затем `id`.
2. Точная проверка — `mealReminderDue`.
3. Флаг `nutrition` по пользователю (`isEnabled`, кэш флагов): без флага `remindedDay` всё равно ставится, уведомление не уходит.
4. Записи дневника — одним запросом на всех кандидатов: `FoodEntry` по парам (пользователь, местная дата), сверка приёма в коде.
5. На каждого — транзакция: `updateMany` с условием по `remindedDay` (защита от параллельного тика), при `count = 1` и пустом приёме — `notify`.
6. Бюджет времени шага — 1 с, как у курса; не успевшие дойдут на следующих тиках (в пределах окна).

## Тесты

- Unit — см. «Чистая логика», плюс тест выгрузки.
- e2e — `e2e/nutrition-reminders.spec.ts` (флаг на пользователя через `addFlagUser`, время — через `E2E_TZ`/`localAt`, тик — `runTick(request, now, "meals")`):
  1. Добавить напоминание в окне, поменять время и приём, выключить, удалить — состояние переживает перезагрузку.
  2. Лимит: при 6 напоминаниях кнопка выключена.
  3. Занятое время — сообщение об ошибке.
  4. Тик в срок при пустом приёме — уведомление в колокольчике с верным заголовком; повторный тик — второго нет.
  5. Тик в срок при записанном приёме — уведомления нет.
  6. Тик до срока и через 60+ минут после — уведомления нет.
  7. Выключенное напоминание — уведомления нет.
- Хелперы в `e2e/db.ts`: `addMealReminder`, `mealReminderNotifications`.
