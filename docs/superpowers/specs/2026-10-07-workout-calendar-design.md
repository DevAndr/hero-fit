# Календарь тренировок — дизайн

Дата: 2026-10-07 · Ветка: `feat/workout-calendar` · Часть 2 из 2 (часть 1 — недельный streak, уже в `main`)

## Зачем

Пользователь сам планирует, когда тренироваться, и видит план и выполненное в одном месте — «как Google Календарь».
Напоминание «Сегодня по плану: Ноги» и карточка на дашборде помогают не пропускать тренировки (и держать недельный
streak: 3+ тренировки в неделю).

## Время

Планы хранятся в местном времени пользователя: дата `"YYYY-MM-DD"`, время `"HH:MM"`, длительность в минутах
(по умолчанию 60, шаг 15, 15…240). Отображение и напоминания — в `User.timeZone` (`safeTimeZone`). Смена пояса не
сдвигает план: 18:00 остаётся 18:00 местного времени.

## Данные (Prisma)

```prisma
/// Повторяющаяся тренировка: каждую неделю в день weekday (0 = пн … 6 = вс).
model PlanSeries {
  id          String    @id @default(cuid())
  userId      String
  templateId  String?
  title       String    // название шаблона на момент создания или своё
  weekday     Int
  time        String    // "HH:MM"
  durationMin Int       @default(60)
  startDate   String    // "YYYY-MM-DD", первое вхождение не раньше
  endDate     String?   // последнее возможное вхождение (включительно), null — бессрочно
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt
  user     User             @relation(fields: [userId], references: [id], onDelete: Cascade)
  template WorkoutTemplate? @relation(fields: [templateId], references: [id], onDelete: SetNull)
  entries  PlanEntry[]
  @@index([userId])
}

/// Разовая тренировка или исключение из серии (перенос / отмена одной даты).
model PlanEntry {
  id           String      @id @default(cuid())
  userId       String
  seriesId     String?     // исключение из серии
  originalDate String?     // дата вхождения серии, которое заменяет запись
  templateId   String?
  title        String
  date         String
  time         String
  durationMin  Int         @default(60)
  cancelled    Boolean     @default(false)
  createdAt    DateTime    @default(now())
  updatedAt    DateTime    @updatedAt
  user     User             @relation(fields: [userId], references: [id], onDelete: Cascade)
  series   PlanSeries?      @relation(fields: [seriesId], references: [id], onDelete: Cascade)
  template WorkoutTemplate? @relation(fields: [templateId], references: [id], onDelete: SetNull)
  @@unique([seriesId, originalDate])
  @@index([userId, date])
}

/// Напоминание по вхождению отправлено (одно на вхождение).
model PlanReminder {
  id      String   @id @default(cuid())
  userId  String
  planKey String
  sentAt  DateTime @default(now())
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@unique([userId, planKey])
}
```

`Workout.planKey String?` — ключ вхождения, из которого запущена тренировка.
`User.notifyPlan Boolean @default(true)`, `User.planReminderMin Int @default(60)` (15 | 30 | 60 | 120).

## Вхождения (чистые функции, `lib/plans/expand.ts`)

- Ключ вхождения: `s:<seriesId>:<originalDate>` — вхождение серии (в том числе перенесённое исключением),
  `e:<entryId>` — разовая запись.
- `expandPlans(series, entries, from, to)` → `Occurrence[]` в диапазоне дат `[from, to]` (включительно), отсортированы
  по дате и времени: для каждой серии — даты с её `weekday` в `[max(startDate, from), min(endDate, to)]`; если есть
  исключение с `originalDate` = этой дате — берутся его дата/время/длительность/шаблон/название, `cancelled` —
  вхождение пропадает; перенесённое исключение попадает в диапазон по своей новой `date`. Разовые записи
  (`seriesId = null`, не отменённые) — как есть.
- `Occurrence = { key, seriesId | null, date, time, durationMin, templateId | null, title, recurring: boolean }`.

## Статус и сопоставление с тренировками (`lib/plans/match.ts`)

- Тренировка с `planKey` закрывает своё вхождение.
- Завершённая тренировка без `planKey` закрывает первое (по времени) невыполненное вхождение того же местного дня;
  остальные такие тренировки — отдельные события «вне плана» по фактическому времени (`startedAt`–`finishedAt`).
- Статусы вхождения: `done` (есть тренировка, `workoutId` для ссылки на сводку), `missed` (день прошёл, тренировки нет),
  `today` (сегодня, не выполнено), `planned` (будущее). Отдельного статуса «идёт» нет: вхождение с активной
  (не завершённой) тренировкой показывается как `today`, а в карточке вместо «Начать» — «Продолжить» (→ `/training`).

## Правки повторяющихся (`lib/plans/edit.ts` — чистое планирование изменений, `lib/plans/actions.ts` — применение)

- `scope = "one"`: upsert `PlanEntry(seriesId, originalDate)` с новыми полями (перенос) или `cancelled = true` (удаление).
- `scope = "following"` для вхождения даты D серии S: `S.endDate = D − 1 день`; правка — новая серия с новыми
  параметрами, `startDate` = новая дата вхождения; исключения S с `originalDate ≥ D` удаляются; если `D = S.startDate`
  — серия удаляется целиком (правка = новая серия).
- Разовая запись (`e:`) — правка/удаление самой записи, `scope` не спрашивается.
- Перенос перетаскиванием = правка даты/времени с тем же выбором `scope`.

## Серверные действия (`lib/plans/actions.ts`, Zod, только свои планы и шаблоны)

- `createPlanAction({ templateId?, title, date, time, durationMin, repeatWeekdays: number[] })` — пустой список:
  разовая запись; иначе — по серии на каждый день недели, `startDate = date`.
- `updatePlanAction(key, scope, patch: { date?, time?, durationMin?, templateId?, title? })`.
- `deletePlanAction(key, scope)`.
- `startPlannedWorkoutAction(key)` — как запуск из шаблона (или пустая тренировка с названием плана), пишет
  `Workout.planKey`; правило «одна активная тренировка» — как сейчас (есть активная → переход в неё).

## Чтение (`lib/plans/queries.ts`)

`getCalendar(userId, from, to)` → `{ occurrences: (Occurrence & { status, workoutId? })[], extraWorkouts }`:
серии, пересекающиеся с диапазоном, исключения и разовые записи диапазона (с запасом на перенос), завершённые
тренировки диапазона (по местному дню). Шаблоны — имя и число упражнений для карточки.
`getTodayPlan(userId)` — для дашборда и `/training`: вхождения сегодня, следующее будущее, пропущенное вчера.

## Интерфейс

- Страница `/calendar` (группа `app/(app)/`), состояние в URL: `?view=week|month&date=YYYY-MM-DD`
  (по умолчанию неделя, сегодня). Навигация: на ПК — пункт «Календарь» после «Тренировка»; на телефоне — вместо
  «Шаблоны» (`components/app/nav.ts`: `Шаблоны.mobile = false`).
- Панель: «Сегодня», ‹ ›, заголовок («Октябрь 2026» / «5–11 окт 2026»), переключатель «Неделя / Месяц»,
  «+ Запланировать».
- **Неделя на ПК (`lg`+)**: 7 колонок × 24 ч, слот 30 мин, прокрутка к 7:00 (к текущему часу на текущей неделе),
  линия «сейчас». Событие — блок по времени и длительности: название, время, «N упр.», ✔ для `done`, бледное для
  `missed`. Пересечения — колонки рядом (чистая функция раскладки `layoutDay`). Клик по пустому слоту — форма
  создания с этим днём и временем. Перетаскивание (`@dnd-kit`, привязка к 30 мин, мышь и клавиатура) — перенос;
  для повторяющегося — вопрос «Только это / Это и следующие». `done`-события и тренировки вне плана не таскаются.
- **Неделя на телефоне**: полоска «Пн … Вс» с точками у дней с событиями, под ней выбранный день с часовой сеткой,
  свайп — соседний день. Без перетаскивания.
- **Месяц**: сетка 6×7, плашки «18:00 Ноги», больше двух — «+ ещё N»; клик по дню — неделя с этим днём.
  На телефоне — цветные точки и список событий выбранного дня под сеткой.
- **Форма** (поповер у слота на ПК, диалог на телефоне): шаблон или «Без шаблона» + название, дата, время,
  длительность, «Не повторять / Каждую неделю по: Пн…Вс» (текущий день отмечен).
- **Карточка события**: название, время, повтор, упражнения шаблона; план — «Начать» (или «Продолжить», если идёт
  тренировка), «Изменить», «Удалить»; `done` / вне плана — «Открыть сводку».
- **Цвет**: план с шаблоном — `chart-1…5` по стабильному хэшу `templateId`, без шаблона — `primary`; тренировки вне
  плана — нейтральные (`muted`) с ✔.
- **Дашборд**: карточка над серией: «Сегодня по плану: Ноги · 18:00 [Начать]»; если сегодня нет — «Следующая:
  Спина, чт 18:00»; если вчера пропущено — «Вчера были Ноги — сделать сегодня? [Начать]».
- **`/training`**: если на сегодня есть невыполненный план — первым вариантом «По плану: Ноги».
- **Доступность**: события — кнопки с подписью «Ноги, четверг 8 октября, 18:00–19:00, запланировано»; сетка
  с подписями дней; перетаскивание с клавиатуры.

## Напоминание «Сегодня по плану»

В `/settings`: переключатель «Тренировка по плану» (`notifyPlan`) и «За сколько минут» (`planReminderMin`).
В фоновом тике (`runNotificationTick`, тестовые часы `?now=` как у streak): один SQL отбирает кандидатов —
пользователи с `notifyPlan`, у которых есть серия с сегодняшним (в их поясе) `weekday` и активная по датам, или
`PlanEntry` на сегодня; в коде — `expandPlans` на сегодня и выбор вхождений с началом в окне
`(now, now + planReminderMin]`, не отменённых, без тренировки по ним, без активной тренировки у пользователя и без
строки `PlanReminder`. Отправка — `notify()` в транзакции с `PlanReminder` (уникальность — защита от дубля).
Текст: «Сегодня по плану: Ноги 💪» / «В 18:00 · 5 упражнений», url `/calendar?date=YYYY-MM-DD`.
Тип уведомления — новый `NotificationType.PLAN`.

## Тесты

- Unit: `expandPlans` (повторы, `startDate`/`endDate`, исключения перенос/отмена, перенос в/из диапазона, разовые);
  планирование правок `one`/`following` (в том числе `D = startDate`); сопоставление и статусы (тренировка с
  `planKey`, без него в тот же день, вне плана, `missed`/`today`/`planned`); `layoutDay` (пересечения); сетка месяца;
  выбор напоминаний (окно, отменённые, выполненные, активная тренировка, пояс).
- e2e (desktop + mobile, где применимо): клик по слоту → серия «Пн, Чт» видна в неделе и месяце; перетаскивание
  «Только это» (ПК); «Начать» из карточки → завершение → ✔ в календаре и ссылка на сводку; карточка на дашборде;
  push «Сегодня по плану» с тестовыми часами; вид дня на телефоне.
