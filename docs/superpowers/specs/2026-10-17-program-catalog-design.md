# Каталог программ тренеров

Дата: 2026-10-17. Релиз: `release/2026-11-coach-social`. Под фича-флагом `program_catalog`.

## Зачем

Программы тренера (`CoachProgram`: неделя-шаблон + правило роста веса) сейчас доступны только его клиентам. Человек без тренера собирает план сам или берёт встроенные шаблоны без прогрессии. Каталог даёт ему готовую программу от тренера с автопрогрессией, а тренеру — витрину: «занимаются N», ссылка на его публичную страницу (задел под платные программы, когда появится оплата).

## Решения (согласовано)

- Человек **сам занимается** по программе: без связи с тренером, тренер не видит его данных — только число «занимаются N».
- Каталог — **в приложении** для вошедших; **без модерации**; админ может снять программу с публикации. Публичные SEO-страницы — позже.
- Без оплаты: всё бесплатно (решение по бете — оплату не подключаем).
- Подход B: запуск — самостоятельное назначение `ProgramAssignment` с `coachId = null` и `catalogProgramId`. Тренерские запросы (клиенты, сводка, сигналы, напоминания тренеру) идут по `coachId` и такие назначения не видят по построению.
- Под фича-флагом `program_catalog` (новая сущность публикации + новый путь назначения).

## Публикация (тренер)

- В редакторе программы (`/coach/programs`) — переключатель «Опубликовать в каталоге» и поле «Описание для каталога» (до 300 символов, обязательно при публикации: «Для кого, цель, инвентарь»). Видны только при флаге.
- `CoachProgram`: `publishedAt DateTime?`, `catalogDescription String?`, `hiddenAt DateTime?` (снято админом), `hiddenReason String?`.
- Публиковать может только тренер (`isCoach`) с ником. Программа без дней не публикуется («Добавьте хотя бы один день»).
- Изменения программы — сразу видны в каталоге и действуют на новые запуски; уже начатые не меняются (снимок, как у назначений тренера).
- Снятие с публикации автором или удаление программы — из каталога пропадает; начатые продолжаются (`catalogProgramId` → `SetNull`, название — в снимке).
- Список программ тренера: значок «В каталоге · занимаются N».

## Каталог `/programs` (пользователь)

- Ссылка «Программы» в меню (при флаге). Только для вошедших.
- Карточка: название, автор (ник → `/trainer/<ник>`, если у тренера есть публичная страница, иначе текст), «N недель · M тренировок в неделю», правило: «+2,5 % в неделю» / «+2,5 кг в неделю» и «разгрузка каждую 4-ю неделю» (если есть), «занимаются N».
- Видны: `publishedAt` не null, `hiddenAt` null, автор `isCoach`. Сортировка — по «занимаются» (активные самостоятельные назначения), затем новые; фильтр «тренировок в неделю»: все / 2 / 3 / 4 / 5+. По 20 на страницу.
- «Занимаются N» — активные (`endedAt` null) назначения с этим `catalogProgramId`.
- Пусто — «Пока нет опубликованных программ».

## Страница программы `/programs/<id>`

- Описание, автор, правило, «занимаются N».
- Неделя: по дням — название тренировки, упражнения с подходами × повторами (из шаблонов автора).
- Предпросмотр весов на базе 100 кг по неделям (`programPreview`, как в редакторе тренера).
- Кнопка «Начать программу». Скрытая/неопубликованная — 404 (кроме автора).

## Запуск

- Два шага, как у тренера: старт «с этой недели» / «со следующей», затем базы рабочих весов по силовым упражнениям — по умолчанию последний рабочий вес пользователя, иначе из шаблона; можно поправить.
- Шаблоны дней **копируются** в собственные шаблоны пользователя (`WorkoutTemplate.userId` = пользователь, название — как у автора, `program` = название программы для группировки), с упражнениями, подходами и повторами. Свои упражнения автора остаются ссылками на упражнения автора (как у клиентов тренера); удаление аккаунта автора переносит их в архивные копии (`rehomeExercises` уже обрабатывает `TemplateExercise` других пользователей).
- Создаётся `ProgramAssignment` с `coachId = null`, `catalogProgramId`, снимком правила и `ProgramBase`, серии плана (`PlanSeries.coachId = null`, `programAssignmentId`) на копии шаблонов. Логика — общая с `assignProgram` (вынести создание снимка/баз/серий), без уведомления «Новая программа от тренера»; вместо него — переход в календарь с тостом «Программа начата».
- Ограничения:
  - активна программа от тренера (`coachId` не null, `endedAt` null) — запуск запрещён: «Сейчас идёт программа от тренера»;
  - активна программа из каталога — подтверждение «Заменить программу «…»?» → прежняя завершается (`endAssignment`, как при новой программе тренера).
- Тренер назначает программу клиенту, у которого идёт программа из каталога, — каталожная завершается (как сейчас любая активная), клиенту уходит обычное «Новая программа от тренера».

## Во время программы

- Всё как у клиента с программой: веса недели в тренировке, «Программа: неделя 3/8» в сводке, календарь.
- Подпись источника: вместо «от тренера» — «программа «…» (неделя 3/8)».
- «Завершить программу» — в календаре/плане у пользователя (только для каталожной): подтверждение → `endAssignment(…, { writeTargets: true, keepToday: true })`.
- Напоминание «Программа заканчивается через неделю» — самому пользователю (тик `processProgramReminders`: для `coachId = null` и `catalogProgramId` не null — уведомление `PLAN` пользователю «Программа «…» заканчивается через неделю» со ссылкой на `/programs`), а не тренеру. Назначения с `coachId = null` без `catalogProgramId` (тренер удалён) — как сейчас.

## Админ

- `/admin/programs` (по `ADMIN_LOGINS`, как `/admin/flags`): опубликованные программы (название, автор, «занимаются», дата), кнопка «Снять» с причиной → `hiddenAt`, `hiddenReason`; «Вернуть».
- Автору при снятии — уведомление `COACH`: «Программа «…» снята из каталога: <причина>»; в редакторе — пометка «Снята администратором: <причина>», переключатель публикации недоступен.

## Модель данных

```prisma
// CoachProgram: +
  publishedAt        DateTime?
  catalogDescription String?
  hiddenAt           DateTime?
  hiddenReason       String?
  catalogAssignments ProgramAssignment[] @relation("CatalogProgram")
  @@index([publishedAt])

// ProgramAssignment: +
  /// запущена из каталога (самостоятельно, coachId = null); null — назначил тренер
  catalogProgramId String?
  catalogProgram   CoachProgram? @relation("CatalogProgram", fields: [catalogProgramId], references: [id], onDelete: SetNull)
  @@index([catalogProgramId, endedAt])
```

## 152-ФЗ, аккаунт

- Автор видит только число; ни ников, ни данных занимающихся.
- «Мои данные»: пользователю — назначения уже выгружаются (`programAssignment` по `clientId`); к назначениям из каталога добавить `catalogProgram: { name, author: ник | null }` (id не выгружать); тренеру — опубликованные программы с описанием и `participants` (число).
- Удаление аккаунта автора — программа удаляется каскадом, у занимающихся `catalogProgramId` → null, назначения продолжаются (снимок), шаблоны — их копии.
- Удаление аккаунта занимающегося — его назначения и копии шаблонов — каскадом (как сейчас).
- `/privacy`: «Если вы начали программу из каталога, её автор видит только общее число занимающихся».

## Тесты

- Unit: `catalogRuleText` (%, кг, разгрузка/без), `daysPerWeek`, `canPublish` (не тренер, без ника, без дней, без описания), `startBlock`.
- e2e `e2e/program-catalog.spec.ts` (`mode: "serial"`, только desktop — глобальный флаг; два контекста — `--workers=8`):
  1. тренер публикует программу с описанием → пользователь видит её в `/programs` с правилом и «занимаются 0»;
  2. пользователь начинает со следующей недели с базами → в календаре серии, копии шаблонов у пользователя, в первой тренировке вес недели; в каталоге «занимаются 1»; тренер в списке клиентов и сводке его не видит;
  3. автор меняет программу → начатое назначение не изменилось; автор снимает с публикации → из каталога пропала, назначение идёт;
  4. при программе от тренера «Начать» запрещено с текстом; при каталожной — подтверждение замены, прежняя завершена;
  5. «Завершить программу» → будущие вхождения убраны, сегодняшняя осталась;
  6. админ снимает с причиной → автору уведомление, в каталоге нет, переключатель в редакторе недоступен;
  7. флаг выключен — `/programs` 404, переключателя нет.
- `account-data.spec.ts`: выгрузка обеих сторон; удаление автора — назначение занимающегося продолжается, `catalogProgramId` null.
- Тик: напоминание о конце — пользователю, не тренеру.
