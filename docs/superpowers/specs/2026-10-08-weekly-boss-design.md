# Босс недели — дизайн

## Цель

Добавить событие недели, которого ждёшь: у каждого пользователя свой босс, которого бьют рабочие подходы. Босс чуть сильнее обычной недели пользователя — победа требует поднажать, но достижима. Победа даёт сундук с XP, ачивку и запись в ленте друзей.

Не цели (сейчас): совместный рейд/отряды, отдельные спрайты «повержен», криты во время тренировки, влияние босса на лигу.

## Решения

| Вопрос | Решение |
|---|---|
| Кто сражается | Соло: у каждого свой босс. Победы друзей видны в ленте и лиге |
| Что наносит урон | Каждый рабочий подход |
| Хранение | Хранится только босс недели (`BossWeek`); урон всегда считается из подходов |
| Арт | PNG от пользователя в `assets/icons/game/`, до их появления — заглушка |

Почему урон не храним: один источник правды (подходы), нет двойного счёта, тренировка без сети засчитывается после синхронизации сама, правка или удаление подхода пересчитывает урон.

## Механика

### Неделя и ротация
- Неделя — пн 00:00 … вс 24:00 в `User.timeZone`, ключ — дата понедельника (`weekKey` из `lib/progress/weekly-streak.ts`), как у серии и лиги.
- Босс недели выбирается по номеру недели по кругу из списка `BOSSES` (код, имя, спрайт) в `lib/boss/bosses.ts`: `index = weeksSinceEpoch(week) % BOSSES.length`.
- Строка `BossWeek` создаётся лениво при первом обращении за неделю (`getOrCreateBossWeek`), уникальна на (userId, week). HP фиксируется при создании и не меняется до конца недели.

### HP
- `hp = max(3000, roundTo100(max(avgWeek, avgWorkout × 3) × 1.1))` по последним 4 прошедшим неделям, в которых был хотя бы один рабочий подход (недели без тренировок не тянут среднее вниз): `avgWeek` — средний урон недели, `avgWorkout` — урон этих недель / число тренировок в них с уроном.
- 3000 ≈ 3 тренировки по 10 подходов — порог для новичка. Множитель 3 = цель недели серии (`STREAK_WEEK_TARGET`): тот, кто ходит 1–2 раза в неделю, не валит босса одной тренировкой.
- Баланс 2026-10-14: было `max(1500, avgWeek × 1.1)` — новичок и тренирующийся редко побеждали за одну тренировку.

### Урон
- Рабочий выполненный подход (`isWarmup = false`, `completedAt` не null) завершённой тренировки недели (`finishedAt` в границах недели) — 100.
- RIR 0 или 1 — ещё +50.
- Крит: за каждое упражнение тренировки, в котором побит рекорд, +100 (удвоение одного подхода). Источник — `XpEvent` `WORKOUT_COMPLETED` → `meta.records` (только побитые рекорды, первый результат — не рекорд), число различных `exerciseId`. Берём из события, а не из `PersonalRecord`: тот хранит текущий лучший результат, и ссылка на подход переезжает при следующем рекорде — урон прошлых недель менялся бы задним числом.
- Разминка урона не наносит.
- Чистая функция `setDamage(rir)` и `workoutDamage({ sets, critExercises })` в `lib/boss/damage.ts`.

### Победа
- Проверяется в `finishWorkout` (та же транзакция): после завершения урон недели ≥ HP и `defeatedAt` пуст → `defeatedAt = now` (условный `updateMany` по `defeatedAt: null` — повтор не засчитает дважды).
- Неделя боя — неделя `finishedAt` тренировки, а не «сегодня»: тренировка без сети, завершённая задним числом, бьёт босса своей недели (`getOrCreateBossWeek` для неё; если строки не было — создаётся с HP по истории до той недели). Победа в прошлой неделе засчитывается так же, и сундук можно забрать, пока он показан (дашборд — текущая неделя; прошлая — в итогах недели и в сводке тренировки).
- Награда — сундук босса: `rewardXp = hp / 20` (3000 → 150 XP). Открытие — `openBossChestAction`: условный `updateMany` по `rewardOpenedAt: null`, `XpEvent` новой причины `BOSS_REWARD` (в лигу и ленту как XP не входит), уровень, `evaluateAchievements`.
- Уведомление `NotificationType.BOSS` «⚔ Босс повержен!» (push — по `notifyAchievements`, отдельного переключателя нет).
- Ачивки: категория `BOSS`, лестница `boss:N` — 1, 5, 10, 25, 50 побед (`ladders()` в `definitions.ts`), статистика — число `BossWeek` с `defeatedAt`.
- В `FinishMeta` добавляется `boss: { code, damage, crits, hpBefore, hpAfter, hp, defeated }` для сводки и ленты.

### Поражение
- Награды нет. В понедельник — следующий босс. Итог недели показывается в «Итогах недели» (`RecapData`: необязательный блок `boss` — код, HP, урон, победа и день победы; версия снимка не меняется — блоки и так необязательные, старые снимки показываются без него).

## Интерфейс

### Дашборд — карточка «Босс недели»
- Спрайт, имя, полоса HP (`1100 / 1500 HP`), «осталось ~4 подхода», «до конца недели 3 дня».
- Победа: спрайт серый и наклонён, «Повержен!»; пока награда не забрана — кнопка «Открыть сундук босса» (диалог как у ежедневного сундука, спрайты сундука те же, сумма — `rewardXp`).
- Неделя без урона: «Голем ждёт. Первый подход — первый удар».

### Редактор тренировки — полоса босса
- Под заголовком: маленький спрайт и HP = HP − (урон недели до этой тренировки) − (урон выполненных подходов текущей тренировки, считается на клиенте той же `setDamage`).
- Отметка подхода: босс вздрагивает, всплывает «−100»/«−150»; снятие отметки возвращает HP.
- HP дошло до 0 — «Босс на последнем издыхании — заверши тренировку, чтобы добить».
- Криты в редакторе не показываются (рекорды определяются при завершении).
- Без сети: урон недели до тренировки берётся из того, что было на странице при загрузке.

### Сводка после тренировки
- Блок «Урон боссу»: «−1100 (2 крита)», полоса HP анимируется от «до» к «после».
- Победа: салют (`celebration`) и кнопка сундука.

### Итоги недели
- Блок босса: «Победил Железного Голема во вторник» / «Голем ушёл: 1100 из 1500».

### Друзья
- Лента: в записи тренировки, которой босс повержен, — «⚔ Победил(а) <имя босса>» (из `FinishMeta.boss`, `toFeedEntry`).
- Лига: ⚔ рядом с другом, победившим босса этой недели.

### Анимации и доступность
- Web Animations API, конечные; «уменьшить движение» — сразу итоговые значения.
- HP и урон всегда есть текстом; полосы — `role="progressbar"` с `aria-valuenow`/`aria-valuemax`; всплывающие цифры — `aria-hidden`, текст HP обновляется в `aria-live="polite"`.

## Данные

```prisma
model BossWeek {
  id             String    @id @default(cuid())
  userId         String
  week           String    // дата понедельника, как lastStreakWeek
  bossCode       String
  hp             Int
  defeatedAt     DateTime?
  rewardOpenedAt DateTime?
  createdAt      DateTime  @default(now())
  user           User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@unique([userId, week])
}
```
- `XpReason.BOSS_REWARD`, `AchievementCategory.BOSS`, `NotificationType.BOSS`.

## Модули

- `lib/boss/bosses.ts` — список боссов (код, имя, имя в род./вин. падеже для текстов), выбор по неделе.
- `lib/boss/damage.ts` — чистые: `setDamage`, `workoutDamage`, `bossHp(history)`, `rewardXp(hp)`.
- `lib/boss/queries.ts` (server-only) — `getOrCreateBossWeek(userId, week, tz)`, `weekDamage(userId, week, tz, excludeWorkoutId?)`, `bossStats` для ачивок.
- `lib/boss/actions.ts` — `openBossChestAction`.
- `lib/workouts/finish.ts` — урон и победа в транзакции, `FinishMeta.boss`.
- `components/boss/*` — `BossCard` (дашборд), `BossBar` (редактор), `BossDamage` (сводка), `BossSprite` (статический импорт PNG, заглушка).

## Тесты

- Юнит: `setDamage` (обычный, RIR 0/1/2, null), `workoutDamage` с критами, `bossHp` (минимум, среднее ×1,1, недели без тренировок не считаются, округление), ротация по неделям, `rewardXp`.
- e2e:
  - подход в редакторе уменьшает HP на 100/150;
  - победа при завершении (история недели готовится SQL), сундук начисляет XP один раз, повторное открытие — отказ;
  - запись «⚔ Победил…» в ленте друга;
  - блок в итогах недели (`seedRecapWeek` + бой).

## Открытые вопросы
