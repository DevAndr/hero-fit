# Респект за рекорд

Дата: 2026-10-17. Релиз: `release/2026-11-coach-social`. Без фича-флага.

## Зачем

👊 в ленте — поддержка тренировки целиком. Побитый рекорд — главное событие тренировки, но отметить его отдельно нельзя: строка «Рекорд — Жим: 1RM 105» в ленте пассивна. Респект — реакция именно на рекорд в упражнении: автору приятнее («оценили твой жим»), у ленты появляется второй повод зайти.

## Решения (согласовано)

- Респект ставится на **упражнение с рекордом** в тренировке (не на каждый тип рекорда и не на тренировку): рекорды одного упражнения сворачиваются в одну строку с одной кнопкой.
- Поведение как у 👊: можно снять; уведомление `SOCIAL` автору группируется, push — только на первый, с учётом `notifySocial`.
- Лестница ачивок за **полученные** респекты: 5 «Заметили», 25 «Уважаемый», 100 «Легенда зала». XP за сам респект нет (иначе друзья фармят опыт друг другу).
- Отдельная таблица `RecordRespect`, а не поле в `Kudos`: уникальность с `null` и смешение счётчиков 👊.
- Попутно: 👊 (`Kudos`) сейчас не попадает в «Мои данные» — добавить в этой же фиче.
- Без фича-флага: та же механика, что у 👊.

## Правила

- Видимость — как у 👊: `canSeeWorkout` (друзья с `shareActivity`, согильдийцы). Свою тренировку — нельзя («Свой рекорд отметить нельзя»).
- Респект допустим, только если в `XpEvent WORKOUT_COMPLETED.meta.records` этой тренировки есть запись с этим `exerciseId` (`isFinishMeta`); иначе ошибка «Рекорд не найден». Подделать `exerciseId` нельзя.
- Повторное нажатие снимает респект (toggle, как `toggleKudosAction`); двойной клик (P2002) — уже поставлено.
- Работает и на старых тренировках из ленты — всё берётся из `meta`.
- `hideWeights` автора: значения весовых рекордов скрыты, как сейчас; название упражнения и кнопка остаются.

## Модель данных

```prisma
/// 🏆 от друга/согильдийца на рекорд в упражнении тренировки. Один на тройку «тренировка–упражнение–пользователь».
model RecordRespect {
  id         String   @id @default(cuid())
  workoutId  String
  exerciseId String
  userId     String   // кто поставил
  createdAt  DateTime @default(now())

  workout  Workout  @relation(onDelete: Cascade)
  exercise Exercise @relation(onDelete: Cascade)
  user     User     @relation(onDelete: Cascade)

  @@unique([workoutId, exerciseId, userId])
  @@index([exerciseId])
}

// AchievementCategory: + SOCIAL // социальное: респекты за рекорды
```

Свои упражнения удаляются мягко (`archivedAt`) — респекты остаются; каскад по `Exercise` — только при реальном удалении (перенос при удалении аккаунта — см. ниже).

## Лента

- `FeedEntry.records` группируется по упражнению: `respects: { exerciseId, exerciseName, records: {type, value}[], respect: { count, byMe, names } }[]` — чистая функция в `lib/social/feed.ts` (`groupRecords`), порядок — как первое появление в `meta.records`.
- Запрос ленты (`lib/social/queries.ts`, общий `feedPage` для `/friends` и `/guild`) добавляет агрегат респектов по `(workoutId, exerciseId)`: число, «мой», до 3 ников (как `kudosNames`).
- Строка в `ActivityFeed`: «🏆 Жим лёжа: 1RM 105, макс. вес 100» (тексты типов — `RECORD_LABEL`) + кнопка справа: иконка `Trophy`, счётчик (пусто при 0), `aria-pressed`, `aria-label` «Дать респект <ник> за <упражнение>» / «Убрать респект у <ник> за <упражнение>», `title` — `kudosLabel`-подобная подпись «Респект: Маша, Борис и ещё 1». Оптимистичное обновление (`useOptimistic`), при ошибке — откат и toast.
- На своей записи кнопки нет, но счётчик и подпись видны (если > 0).
- Строки «Рекорд — …» в списке событий записи заменяются сгруппированными строками (не дублируются).
- Лента клуба (`lib/club/feed.ts`) — свой тип событий, не меняется.

## Уведомление

- `notifyRespect(workoutId, exerciseId, ownerId, friend)` по образцу `notifyKudos`: заголовок «🏆 Респект за рекорд: <упражнение>», тело «<ник>, <ник> и ещё N» (последние сверху), url — `/friends#w-<id>` или `/guild#w-<id>`.
- Группировка: пока непрочитано уведомление `SOCIAL` с тем же url **и тем же заголовком** — обновляется оно (title/body/createdAt); иначе новое. Ключ группировки отличается от 👊 заголовком: 👊 и респекты одной тренировки — разные уведомления.
- Push — только когда респект один (первый) и `notifySocial`.
- Снятие респекта уведомление не трогает (как у 👊).

## Ачивки

- Статистика `respectsReceived` — `COUNT(*) FROM "RecordRespect" r JOIN "Workout" w ON w.id = r."workoutId" WHERE w."userId" = $user` в `getAchievementStats`.
- Лестница в `definitions.ts` (категория `SOCIAL`):
  - 5 — `respect:5` «Заметили» — «Получить 5 респектов за рекорды», XP 30;
  - 25 — `respect:25` «Уважаемый» — «Получить 25 респектов за рекорды», XP 60;
  - 100 — `respect:100` «Легенда зала» — «Получить 100 респектов за рекорды», XP 120.
- Выдача — сразу при постановке респекта: `evaluateAchievementsNow(ownerId)` после записи (ошибка не роняет действие — `quietly`). Ачивка не отзывается при снятии; счётчик — текущие записи (снять и поставить снова — не накрутка).
- Метка категории `SOCIAL` — «Социальное» в `components/achievements/category.ts`; иконка — по образцу соседних.

## 152-ФЗ, аккаунт

- «Мои данные»: `respectsGiven: { workoutDate, exercise, to: nickname | null }[]`, `respectsReceived: { workoutDate, exercise, from: nickname | null }[]`, `kudosGiven: { workoutDate, to }[]`, `kudosReceived: { workoutDate, from }[]` — новые разделы в `EXPORT_SECTIONS`; в CSV не входят (CSV — только тренировки и подходы).
- Удаление аккаунта — каскад по `User` и `Workout`. Перенос своих упражнений в архивные копии у других пользователей (`lib/account/delete.ts`) не затрагивает респекты на тренировках удаляемого — они уходят с его тренировками. Респекты удаляемого на чужих рекордах уходят каскадом по `userId`.
- Проверка — `e2e/account-data.spec.ts`.
- Миграция — только новая таблица и значение enum; частичные индексы `CoachLink_active_client`, `CoachComment_workout_general`, `CoachSignal_open` не трогать.

## Тесты

- Unit: `groupRecords` (несколько типов одного упражнения → одна строка, порядок, `hideWeights` → `value null`), `respectLabel`, лестница `respect:*` (пороги и тексты), текст уведомления.
- e2e `e2e/record-respect.spec.ts` (два контекста, `--workers=8`):
  1. друг видит рекорд друга, ставит респект → счётчик 1, `aria-pressed`; у автора — уведомление «🏆 Респект за рекорд: …» с push; второй друг — то же уведомление обновлено («…, … »), push один; снятие → счётчик убывает;
  2. свой рекорд — кнопки нет; тренировка без рекордов — кнопок нет; `hideWeights` — значения скрыты, кнопка есть;
  3. согильдиец (не друг) ставит респект в `/guild`, ссылка уведомления — `/guild#w-`;
  4. 5-й респект выдаёт ачивку «Заметили» (история респектов — в БД через `e2e/db.ts`, пятый — через UI);
  5. подделанный `exerciseId` (действие напрямую) — ошибка, записи нет;
  6. мобильный — без горизонтальной прокрутки ленты с длинным названием упражнения.
- `account-data.spec.ts`: респекты и 👊 в выгрузке обеих сторон; удаление аккаунта автора — респекты на его тренировках удалены.

## Не в этом цикле

Респекты в ленте клуба и на дашборде («Друзья недавно»); набор эмодзи-реакций; XP за респекты; ачивка за выданные респекты.
