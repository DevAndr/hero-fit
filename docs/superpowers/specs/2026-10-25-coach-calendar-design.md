# Календарь тренера по всем клиентам

Дата: 2026-10-25. Без фича-флага: только просмотр данных, которые тренер уже видит во вкладке «План» клиента.

## Цель

Тренер на одной странице видит, у кого из клиентов на какой день и время стоит назначенная им тренировка и что с ней (выполнено, пропущено, не выполнено, впереди). Править назначения — по-прежнему в плане клиента: клик по строке ведёт туда.

Вне этапа: назначение, перенос и отмена прямо из календаря, перетаскивание, собственные планы клиента и тренировки вне назначений, пересчёт времени в пояс тренера.

## Страница `/coach/calendar`

- Группа `app/(app)/coach/`, доступ — `requireCoach()` (не тренеру — 404). Пункт «Календарь» в навигации тренера сразу после «Клиентов» (рядом с `COACH_NAV_ITEM`; на телефоне — в меню профиля), ссылка «Календарь» на `/coach`.
- Параметры: `view=week|month` (по умолчанию `week`), `date=YYYY-MM-DD` (по умолчанию сегодня в поясе тренера; неверная — сегодня), `group=<id группы тренера>` (чужая или несуществующая — без фильтра). Диапазон — `viewRange(view, date)` из `lib/plans/view.ts` (неделя — 7 дней, месяц — сетка до 42 дней).
- Навигация «‹», «Сегодня», «›» и переключатель «Неделя / Месяц» — ссылками, сохраняя `group`. Фильтр группы — ссылки-чипы «Все» и группы тренера (показываются, если групп ≥ 1).
- Сводка над неделей: «N тренировок у M клиентов» и «выполнено X из Y прошедших» (в месяце — за весь видимый диапазон).

## Ячейка дня

Строка на каждое назначение: время, имя клиента (`clientDisplayName`), название тренировки, статус:

- `done` — выполнено (галочка);
- `skipped` — клиент отменил (зачёркнуто, «пропущено»);
- `missed` — день прошёл, не выполнено и не отменено («не выполнено»);
- `upcoming` — сегодня или впереди.

Порядок в дне — по времени, затем по имени клиента. В виде «месяц» в ячейке до 3 строк и «ещё N» (раскрывает список дня на месте). Неделя на телефоне — списком дней. Клик по строке → `/coach/clients/<id>?tab=plan`.

Дата и время — как у клиента (так хранится план). Если пояс клиента отличается от пояса тренера, к времени добавляется пометка «по его времени» (подсказка с поясом клиента).

## Данные

`lib/coach/plan-queries.ts`: из `getClientPlan` выделяется `coachOccurrences(coachId, clientId, from, to, tz, now): Promise<CoachPlanItem[]>` — назначения этого тренера из `getCalendar` клиента плюс отменённые клиентом (та же выборка `cancelled`, что сейчас). `getClientPlan` переходит на неё без изменения поведения.

`lib/coach/calendar-queries.ts` — `getCoachCalendar(coachId, from, to, opts: { groupId: string | null; now: Date }): Promise<CoachCalendarItem[]>`:

1. Активные клиенты тренера (`CoachLink.endedAt = null`), при `groupId` — только члены этой группы тренера; имя и пояс клиента.
2. Отбор клиентов, у которых в диапазоне есть что-то от тренера: серия `PlanSeries` с `coachId` (началась не позже `to`, не кончилась раньше `from`) или `PlanEntry` с `coachId` / из такой серии с датой в диапазоне. Остальные клиенты не загружаются.
3. `coachOccurrences` для отобранных — параллельно, не более 8 одновременно.
4. Результат — `CoachCalendarItem = { clientId, clientName, clientTz, date, time, title, status: "done" | "skipped" | "missed" | "upcoming" }` (`title` — как в плане клиента: название вхождения или шаблона).

Новых данных о клиенте тренер не получает — экран согласия и `/privacy` не меняются; в «Мои данные» ничего не добавляется (новых таблиц нет).

## Чистые функции — `lib/coach/calendar.ts`

- `statusOf(o: { status, date }, today): CoachCalendarItem["status"]` — `done`/`skipped` как есть, прошедший день без них — `missed`, иначе `upcoming`.
- `groupByDay(items): Map<string, CoachCalendarItem[]>` — по дате, внутри по времени, затем по `clientName` (`localeCompare("ru")`).
- `dayPreview(items, limit = 3): { shown; more: number }`.
- `calendarSummary(items, today): { workouts; clients; done; past }` — `past` — прошедшие дни без `upcoming`, `done` — из них выполненные.

## Интерфейс

`components/coach/coach-calendar.tsx` — свой компонент сетки (неделя — 7 колонок на ≥ md, список дней на телефоне; месяц — сетка 7 × N с днями чужого месяца приглушёнными). `CalendarView` клиента не меняется (он про действия клиента: «Начать», «Перенести»).

Пустые состояния: нет активных клиентов — «Пока нет клиентов» и ссылка на `/coach`; клиенты есть, назначений в диапазоне нет — «На эти дни ничего не назначено» и «Назначить нескольким» (существующий `AssignManyButton`, при 2+ клиентах).

## Тесты

Unit: `statusOf` (граница «сегодня»: сегодняшнее невыполненное — `upcoming`), `groupByDay` (порядок), `dayPreview`, `calendarSummary`.

e2e `e2e/coach-calendar.spec.ts` (связь — `linkCoach`, назначения — разовые `PlanEntry` с `coachId` через `e2e/db.ts`, даты — от `E2E_TZ`):

- два клиента с назначениями на разные дни недели — оба в своих днях, с именем и временем;
- выполненное назначение — «выполнено», отменённое клиентом — «пропущено», прошедшее без отметки — «не выполнено»;
- фильтр по группе оставляет одного клиента;
- клик по строке → `/coach/clients/<id>?tab=plan`;
- месяц: 4 назначения в один день — 3 строки и «ещё 1»;
- клиент другого тренера и бывший клиент (связь разорвана) не видны;
- не тренеру — 404; пункт «Календарь» есть в навигации тренера.
