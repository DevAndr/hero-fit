# Цели

Фича релиза `release/2026-10-raids`. Для всех пользователей; тренер видит цели клиента.

## Цель

Человек ставит себе конкретную цель — «Жим лёжа 100 кг», «50 тренировок», «Серия 12 недель», «Вес тела 80 кг» —
со сроком или без, видит прогресс и темп и получает награду за выполнение. Сейчас есть только ачивки (общие,
вычисляемые, без срока) и подсказка «Пора увеличить вес» — своей цели поставить негде.

## Решения

- **Типы** — сила, регулярность (тренировки, серия, часы), вес тела. Объём (тонны, подходы на группу) — не сейчас.
- **Срок необязателен.** Без срока цель висит, пока не выполнена или не удалена.
- **Прогресс не хранится**: цель хранит условие и стартовое значение, текущее значение каждый раз считается из
  существующих данных (рекорды, тренировки, серия, взвешивания). Не рассинхронизируется, офлайн-тренировки задним
  числом учитываются сами.
- **Тренировки и часы — с момента постановки** (за всё время — это ачивки).
- **Награда** — фиксированный сундук 100 XP (`XpReason.GOAL_REWARD`, не в лиге) + лестница ачивок `goal:N` и титул.
  XP по «сложности» отвергнут: легко накрутить.
- **Лимиты:** до 5 активных целей, цель по весу тела — одна активная; уже выполненная при постановке цель
  отклоняется («Уже достигнуто»).
- **Выполненная цель закрыта навсегда**: откат рекорда (удалили тренировку) её не снимает.
- **Правка активной цели** — только срок (перенести/убрать). Цель, тип, упражнение не меняются — удалить и
  создать заново (иначе цель подгоняется под результат). Удаление активной — строка удаляется, без сундука.
- **Лента друзей** — выполненные во время тренировки цели по силе и регулярности; вес тела — никогда.
- **Тренер** видит цели клиента (и по весу тела — `hideWeights` к тренеру не применяется), только чтение.
- **Отдельная страница `/goals`** — создание, активные, история, взвешивания.

## Данные

```prisma
enum GoalType {
  STRENGTH    // упражнение + метрика RecordType
  WORKOUTS    // завершённые тренировки с момента постановки
  STREAK      // недели серии (User.currentStreak)
  HOURS       // часы в зале с момента постановки
  BODY_WEIGHT // последнее взвешивание
}

enum GoalStatus {
  ACTIVE
  ACHIEVED
  FAILED
}

model Goal {
  id            String      @id @default(cuid())
  userId        String
  type          GoalType
  exerciseId    String?     // только STRENGTH
  metric        RecordType? // только STRENGTH
  target        Float
  startValue    Float       // значение при постановке (полоса «от старта к цели», направление веса)
  deadline      String?     // местная дата "YYYY-MM-DD" в User.timeZone
  status        GoalStatus  @default(ACTIVE)
  createdAt     DateTime    @default(now())
  achievedAt    DateTime?   // для STRENGTH/WORKOUTS/HOURS из тренировки — её finishedAt
  closedAt      DateTime?   // когда стала ACHIEVED/FAILED
  chestOpenedAt DateTime?
  reminderAt    DateTime?   // «7 дней до срока» отправлено

  user     User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  exercise Exercise? @relation(fields: [exerciseId], references: [id], onDelete: Cascade)

  @@index([userId, status])
}

model BodyWeightEntry {
  id        String   @id @default(cuid())
  userId    String
  date      String   // местная дата "YYYY-MM-DD"
  weight    Float    // кг, 30…300
  createdAt DateTime @default(now())

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, date])
}
```

- `User.notifyGoal Boolean @default(true)` — переключатель уведомлений о целях.
- `XpReason.GOAL_REWARD`, `AchievementCategory.GOAL`, `NotificationType.GOAL`.
- Миграция переносит текущий `User.bodyWeight` в `BodyWeightEntry` (дата — день миграции в поясе пользователя),
  чтобы у тех, кто его уже указал, был стартовый вес.
- `User.bodyWeight` остаётся и всегда равен последнему взвешиванию (ачивки «1ПМ к весу тела» не меняются).

## Типы и расчёт

Текущее значение — `getCurrentValues(userId, goals)` (`lib/goals/queries.ts`), одним набором запросов на все цели:

| Тип | Текущее значение | Выполнена, если |
|---|---|---|
| `STRENGTH` | `PersonalRecord.value` (упражнение + метрика); нет — 0 | ≥ цели |
| `WORKOUTS` | `COMPLETED` с `finishedAt` в [`createdAt`, конец срока] | ≥ цели |
| `STREAK` | `User.currentStreak` | ≥ цели |
| `HOURS` | сумма `finishedAt − startedAt` тех же тренировок, часы | ≥ цели |
| `BODY_WEIGHT` | вес последнего взвешивания | `startValue > target` (сбросить) — ≤ цели; иначе (набрать) — ≥ цели |

- Упражнение со своим весом (`isBodyweight`) — только `MAX_REPS`.
- Конец срока — `deadlineEnd(deadline, tz)`: начало следующего дня после `deadline` в поясе пользователя.
- Прогресс — `goalProgress(goal, current)`: доля пути от `startValue` к `target` (0…1, для веса — с учётом
  направления; старт не на пути — 0). Для `WORKOUTS`/`HOURS` старт — 0.
- Темп — `paceStatus(goal, progress, now, tz)`: при сроке — ожидаемая доля `(now − createdAt) / (конец − createdAt)`,
  «отстаёт», если прогресс меньше ожидаемого на 10+ п. п.; без срока — нет темпа.

### Постановка (`canCreate`, `goalSchema`)

- `goalSchema` (Zod): тип; для `STRENGTH` — существующее доступное упражнение (своё или встроенное, не в архиве) и
  метрика; цель — `STRENGTH` вес/1ПМ 1…500 кг (шаг 0,5), повторы 1…500; `WORKOUTS` 1…1000; `STREAK` 1…104;
  `HOURS` 1…2000; `BODY_WEIGHT` 30…300 (шаг 0,1); срок — не раньше завтра, не позже 2 лет.
- Отказы: «Максимум 5 активных целей»; «Цель по весу уже есть»; «Уже достигнуто» (текущее значение уже удовлетворяет
  условию); `BODY_WEIGHT` без взвешиваний — сначала нужно записать текущий вес (форма шлёт его вместе с целью);
  цель по весу, равная текущему, — «Уже достигнуто».

## Выполнение и провал

Перевод статуса — всегда условный `updateMany … where id, status = ACTIVE` (два пути не выдадут цель дважды).

1. **`finishWorkout`** — `applyGoals(tx, userId, workout)` (`lib/goals/apply.ts`) после рекордов и серии, в той же
   транзакции: активные `STRENGTH`/`WORKOUTS`/`STREAK`/`HOURS`, у которых `workout.finishedAt` < конца срока;
   выполненные → `ACHIEVED`, `achievedAt = finishedAt`. Возвращает данные для `FinishMeta.goals`:
   `{ id, type, exerciseName?, metric?, target }[]` и прирост по остальным активным этих типов
   (`{ id, before, after }` в долях) для сводки.
2. **Взвешивание** — `logBodyWeightAction` в транзакции: upsert записи за сегодня, `User.bodyWeight` = последняя
   запись, проверка активной `BODY_WEIGHT`; выполнена → `ACHIEVED` + уведомление.
3. **Тик** — `processGoals` (`lib/goals/tick.ts`) в `runNotificationTick`, бюджет ~1 с:
   - активные, ставшие выполненными вне тренировки (выкуп серии и т. п.) → `ACHIEVED` + уведомление;
   - срок через ≤ 7 дней, `reminderAt = null`, прогресс < 100 % → уведомление «До срока 7 дней: пройдено 82 %»,
     `reminderAt`;
   - `now ≥ конец срока + 24 ч` (фора на офлайн-тренировки: финиш с устройства принимается до 24 ч назад) и не выполнена → `FAILED` +
     уведомление «Срок вышел — пройдено 94 %. Поставить снова?» (ссылка — `/goals?again=<id>`).
4. После перевода в `ACHIEVED` — `evaluateAchievements` (в `finishWorkout` — вместе с остальными; во взвешивании и
   при открытии сундука — `evaluateAchievementsNow`; из тика — при следующем входе или тренировке).

Уведомления — тип `GOAL`, переключатель `notifyGoal` в `/settings`, push и Telegram — как у остальных типов.
Выполнение во время тренировки отдельного push не шлёт — человек видит сводку.

## Награды

- **Сундук** — `openGoalChestAction(goalId)`: только своя `ACHIEVED` с `chestOpenedAt = null` (условный
  `updateMany`), `XpEvent` `GOAL_REWARD` 100 XP с meta `{ goalId }`, пересчёт уровня; общий `ChestDialog`.
  Не в лиге и не в ленте. Открывается из сводки, со страницы целей и с карточки на дашборде. Не истекает.
- **Ачивки** `goal:N` (категория `GOAL`, «Целеустремлённый»): 1, 5, 10, 25 выполненных целей — счётчик
  `goalsAchieved` в `getAchievementStats`; значок — `default`, пока нет своего.
- **Титул** `ach:goal:25` — «Человек слова».

## Интерфейс

### `/goals` — «Цели»

В боковом меню после «Ачивок» (иконка `Target`, `mobile: false`); на телефоне — в меню профиля и с карточки
дашборда.

- **Активные** (до 5): название (`goalTitle`: «Жим лёжа — 100 кг», «Жим лёжа — 1ПМ 110 кг», «Подтягивания —
  20 повторов», «50 тренировок», «Серия 12 недель», «30 часов в зале», «Вес тела — 80 кг ↓»), полоса прогресса,
  «87,5 / 100 кг · 72 %», срок «до 31 декабря · осталось 81 день», пометка «отстаёшь от темпа»; меню «⋯» —
  «Перенести срок» (тот же выбор даты, «без срока»), «Удалить» (подтверждение).
- **Выполненная с неоткрытым сундуком** — вверху списка, рамка `xp`, кнопка «Открыть сундук».
- **Кнопка «Новая цель»** — заметная; при 5 активных неактивна с подписью «Максимум 5 активных целей».
- **История**: выполненные (дата, «за 47 дней»), проваленные («пройдено 94 %», «Поставить снова» — диалог с теми
  же параметрами, без срока).
- **Пусто** — пояснение и до 3 подсказок `suggestGoals(stats)`, кнопка открывает диалог с заполненными полями:
  самое частое упражнение за 90 дней — рабочий вес +10 % (вверх до 2,5 кг); серия — текущая + 4 недели (нет —
  4); тренировки — 20 за 2 месяца.
- **Блок «Вес тела»**: «Записать вес сегодня» (повтор за день перезаписывает), график за 90 дней (recharts через
  `components/ui/chart.tsx`, скрытая таблица в `div.sr-only`, линия — `--series-1`, цель по весу — пунктир).
- `?again=<id>` — открыть диалог с параметрами проваленной цели.

### Диалог «Новая цель»

1. Плитки типа: Сила · Тренировки · Серия · Часы в зале · Вес тела.
2. Параметры:
   - сила — упражнение (поиск, как `ExercisePicker`), метрика (Рабочий вес / 1ПМ / Повторы; у своего веса —
     только повторы), цель; под полем «сейчас: 72,5 кг» и «+5 %» / «+10 %» / «+20 %» (вес — вверх до 2,5 кг,
     повторы — вверх до целого);
   - тренировки, часы — число; серия — недели, «сейчас: 3 недели»;
   - вес тела — цель; нет взвешиваний — поле «Текущий вес»;
   - срок — «1 мес» / «3 мес» / «До конца года» / дата / без срока.

Ошибки — у поля, тексты из `canCreate`/`goalSchema`.

### В других местах

- **Дашборд** — `GoalsCard`: неоткрытые сундуки целей, затем 1–2 активные с наибольшим прогрессом, ссылка на
  `/goals`; нет целей — «Поставь первую цель».
- **Сводка тренировки** — блок `GoalsReached` из `FinishMeta.goals`: «🎯 Цель достигнута: …» с кнопкой сундука и
  строки прироста «Жим лёжа — 100 кг: 72 → 78 %».
- **`/stats/exercises/[id]`** — пунктирная горизонтальная линия активной цели `STRENGTH` по этому упражнению на
  графике соответствующей метрики.
- **`/settings`** — поле веса тела становится «Записать вес» (тот же `logBodyWeightAction`); переключатель «Цели»
  в уведомлениях.
- **Тренер** — блок «Цели» на вкладке «Обзор» карточки клиента (`requireClientOf`): активные с прогрессом и
  последние 5 выполненных, только чтение.

## Лента друзей

`XpEvent WORKOUT_COMPLETED.meta.goals` (из `FinishMeta.goals`) → `FeedEntry.goals` в `toFeedEntry`:
«🎯 Цель: Жим лёжа — 100 кг». `BODY_WEIGHT` туда не попадает (выполняется не в тренировке). `hideWeights` —
у силовых целей по весу/1ПМ остаётся «🎯 Цель по упражнению «Жим лёжа» достигнута» без килограммов (на сервере).

## Тесты

**Unit** (Vitest, рядом с кодом):
- `goalProgress` по всем типам: вес вниз и вверх, старт на цели, перелёт за цель (1,0), старт не на пути (0);
- `isAchieved`, `deadlineEnd` в поясах с разным смещением, фора 24 ч;
- `paceStatus`: без срока, вровень, отстаёт;
- `canCreate`: лимит 5, вторая цель по весу, «уже достигнуто», своё упражнение — только повторы, `goalSchema` —
  границы;
- `suggestGoals`: нет истории, округление до 2,5 кг;
- `goalTitle`; `toFeedEntry` с `goals` (с `hideWeights` и без); лестница `goal:N` и титул `ach:goal:25`.

**e2e** (`e2e/goals.spec.ts`, desktop + mobile; хелперы `createGoal`, `goalOf`, `logWeight` в `e2e/db.ts`):
- создать силовую цель в диалоге → тренировка с рекордом ≥ цели → в сводке «Цель достигнута» → открыть сундук →
  XP вырос, цель в истории, ачивка «Целеустремлённый»;
- «Уже достигнуто» отклоняется; при 5 активных кнопка неактивна;
- цель по весу: записать вес на `/goals` → цель выполнена, уведомление в колокольчике;
- провал: цель со сроком в прошлом (SQL) → тик → «Срок вышел», «Поставить снова» открывает диалог;
- перенос срока и удаление;
- лента: друг видит «🎯 Цель», при `hideWeights` — без килограммов;
- тренер видит цели клиента на «Обзоре».

## Вне рамок

Цели по объёму и группам мышц, общие цели с друзьями или гильдией, цели от тренера клиенту (у тренера есть
задания), замеры и фото тела, XP за сложность цели.
