# Итоги недели — дизайн

Дата: 2026-10-08 · Ветка: `feat/weekly-recap` · Итоги года (Wrapped) — отдельная спецификация позже, поверх этой

## Зачем

Понедельничный ритуал: push «Итоги недели» с местом в лиге, приростом и лучшим подходом ведёт на страницу с полной
сводкой прошлой недели. Это повод вернуться в приложение в начале недели и начать новую «в ударе» (streak — 3+
тренировки в неделю). Итоги личные — видит только сам пользователь.

Успех: в понедельник утром у каждого, кто тренировался на прошлой неделе, ровно один push и готовая страница; цифры
совпадают с лигой и статистикой.

## Неделя и время

Неделя — пн 00:00 … вс 24:00 в `User.timeZone` (`safeTimeZone`), ключ — дата понедельника `"YYYY-MM-DD"`
(`weekKey`/`addWeeks` из `lib/progress/weekly-streak.ts`, как `StreakCoverWeek.week`). «Прошлая неделя» =
`addWeeks(weekKey(now, tz), -1)`.

Итоги создаются не раньше **понедельника 09:00** по местному времени (`RECAP_HOUR = 9`): у офлайн-тренировок,
сделанных в воскресенье вечером, есть ночь на синхронизацию. Созданные итоги — снимок: досинхронизированная позже
тренировка их не меняет.

## Данные (Prisma)

```prisma
/// Снимок итогов недели. data — RecapData (lib/recap/types.ts) с полем version.
model WeeklyRecap {
  id        String    @id @default(cuid())
  userId    String
  week      String    // понедельник недели "YYYY-MM-DD" в поясе пользователя
  data      Json
  createdAt DateTime  @default(now())
  pushedAt  DateTime? // push «Итоги недели» отправлен
  seenAt    DateTime? // пользователь открыл страницу итогов

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, week])
}
```

`User`: `notifyRecap Boolean @default(true)`, `recapNudgeWeek String?` (неделя, за которую уже ушёл push «новый
старт»). `NotificationType`: новое значение `RECAP`.

## Содержимое (`RecapData`)

Чистая функция `buildRecap(input): RecapData` (`lib/recap/build.ts`); входные данные собирает
`loadRecapInput(userId, week, tz)` (`lib/recap/queries.ts`) несколькими SQL по границам недели в поясе пользователя.
Блок без данных в `RecapData` не попадает (поле отсутствует) и не рендерится.

| Блок | Источник | Правило |
|---|---|---|
| `league` | как `getLeague` (XP `WORKOUT_COMPLETED` + `PERSONAL_RECORD`), но для заданной недели | Есть друзья → место из N, мой XP, строки: топ-3 + я + соседи (ник, XP, место). Нет друзей → процентиль (`percentile`, при < 10 атлетов — `null`). Нет ни того, ни другого → блока нет |
| `totals` | завершённые тренировки этой и прошлой недели | тренировки, время (мин), объём (кг), подходы — значение и предыдущее значение. Дельта считается при рендере; при пустой прошлой неделе дельт нет |
| `bestSet` | выполненные рабочие подходы недели (не разминка) | максимум оценки 1RM по Эпли (`вес × (1 + повторы/30)`); при равенстве — больший вес. Упражнения со своим весом — по повторам, только если весовых подходов не было. Поля: упражнение (id, имя), вес, повторы, e1RM, `isRecord` (подход дал PR) |
| `streak` | `XpEvent.meta.weekCount` последней тренировки недели, `User.currentStreak`, `StreakCoverWeek` | тренировок за неделю / `STREAK_WEEK_TARGET`, засчитана ли, серия в неделях, была ли неделя закрыта заморозкой |
| `records` | `XpEvent.meta.records` (события недели), `UserAchievement.earnedAt` в пределах недели, без `login:*`, `levelBefore` первой / `levelAfter` последней тренировки | список PR, ачивки (код, название), уровень «от → до» (если вырос) |
| `muscles` | выполненные подходы недели по основной группе мышц (как в статистике) | подходы по группам; `forgotten` — группа с 0 подходов 2 недели подряд, у которой был ≥ 1 подход за 4 предыдущие недели (одна, с наибольшим прошлым числом подходов) |
| `plan` | `expandPlans` + `matchPlans` за неделю | выполнено / запланировано; блока нет, если планов не было |

`version: 1`. Страница рендерит известные блоки; у старых снимков отсутствующие блоки просто не показываются.
`hideWeights` к собственным итогам не применяется (это приватность для друзей).

Неделя без завершённых тренировок → итогов нет.

## Генерация и push

Создание итогов и push разведены: итоги появляются в тике или на лету, push отправляет только тик, признак — `pushedAt`.

**Тик** — `processWeeklyRecaps(now)` в `runNotificationTick` (рядом с напоминаниями streak и планов):

1. **Создание.** Кандидаты одним SQL: местное время ≥ понедельник 09:00 текущей недели, за прошлую неделю есть
   завершённая тренировка, строки `WeeklyRecap` за неё нет. До 50 пользователей за тик (остальные — в следующих).
   Для каждого: `loadRecapInput` → `buildRecap` → `INSERT … ON CONFLICT ("userId", week) DO NOTHING`. Ошибка у
   одного пользователя логируется и не прерывает тик.
2. **Push.** Строки прошлой недели с `pushedAt IS NULL AND seenAt IS NULL`, у пользователя `notifyRecap`, и сейчас
   по местному времени понедельник ≥ 09:00 (решает чистая `shouldPushRecap`). В транзакции:
   `updateMany({ where: { id, pushedAt: null }, data: { pushedAt: now } })`, при `count = 1` —
   `notify(tx, …, { push: true })`: тип `RECAP`, заголовок «Итоги недели 📊», текст — `recapPushBody(data)`,
   url `/recap/<week>`. Пропущенный понедельник (воркер не работал) — итоги создаются, push не отправляется
   (`pushedAt` остаётся `null`, просто не подходит по дню).
3. **«Новый старт».** Понедельник ≥ 09:00, `notifyRecap`, прошлая неделя без тренировок, позапрошлая — с
   тренировками, `recapNudgeWeek ≠ прошлая неделя` → условное обновление `recapNudgeWeek` и `notify` (тип `RECAP`,
   «Новая неделя — новый старт 💪», текст про первую тренировку недели, url `/training`). Дальше пустые недели — тишина.

`recapPushBody(data)` — 2–3 факта по приоритету, через « · »: место в лиге (если есть друзья) → рост объёма или
тренировок (если положительный) → лучший подход («Жим лёжа 100×5») → засчитанная неделя streak. Пример:
«2-е место в лиге · объём +18% · лучший подход: Жим лёжа 100×5».

**На лету** — `getOrCreateRecap(userId, week, tz)`: страница итогов и дашборд. Если строки нет, неделя закончилась
и была не старше 8 недель назад, а тренировки были — строит и вставляет (уже с понедельника 00:00, раньше окна тика в 09:00 — человек сам открыл приложение) (`ON CONFLICT DO NOTHING`, затем чтение),
без push. Старше 8 недель — только существующие снимки (архив не запускает тяжёлых расчётов).

## UI

**Страница `/recap/[week]`** (`app/(app)/recap/[week]/page.tsx`). Чужая/несуществующая/некорректная неделя →
`notFound()`; неделя ещё не закончилась → редирект на `/recap`. Открытие ставит `seenAt` (если `null`).

Одна колонка на телефоне, сетка карточек на ПК (`lg`):

1. Шапка: «Итоги недели · 6–12 октября», стрелки к соседним существующим снимкам, ссылка «Все итоги».
2. Герой: 2–3 главных факта (тот же выбор, что `recapPushBody`), акцент токенами `xp`/`primary`.
3. Прирост: плитки «Тренировки / Время / Объём / Подходы» со значением и дельтой (▲/▼ + знак, не только цвет).
4. Лучший подход: упражнение, `100 кг × 5`, оценка 1RM, отметка «рекорд»; ссылка на `/stats/exercises/[id]`.
5. Лига: мини-таблица (топ-3 + я с соседями). Без друзей — процентиль или «Позвать друзей» → `/friends`.
6. Streak: «3/3 — неделя засчитана 🔥», серия, «спасено заморозкой».
7. Рекорды и ачивки: чипы PR, значки ачивок, «Уровень 7 → 9».
8. Группы мышц: горизонтальные бары подходов (recharts через `components/ui/chart.tsx`, одна шкала, скрытая таблица
   для скринридеров в `div.sr-only`) + подсказка про забытую группу.
9. План и факт: «Выполнено 3 из 4», ссылка `/calendar?date=<week>`.

Компоненты — `components/recap/*`, каждый блок получает свой кусок `RecapData`. Цвета — только семантические токены.

**Дашборд** — карточка «Итоги недели» с понедельника до конца недели, если есть итоги прошлой недели (`getOrCreateRecap`):
мини-герой (место, прирост) и ссылка-кнопка «Смотреть итоги» (`<Link className={buttonVariants()}>`). Непросмотренные —
акцентная рамка и метка «новое», просмотренные — компактный вид. Ниже кнопки «Начать тренировку».

**Архив `/recap`** — существующие снимки, новые сверху, по 20 на страницу (`?page=`): даты, тренировки, место в лиге,
дельта объёма. Вход — из шапки итогов и ссылкой «Итоги недель» на `/stats`; отдельного пункта навигации нет.

**Настройки** — в блоке уведомлений `/settings` переключатель «Итоги недели — в понедельник утром» (`notifyRecap`).
**Колокольчик** — иконка `BarChart3` и подпись для `RECAP` в маппингах типов.

## Тесты

Unit (Vitest):
- `lib/recap/build.test.ts` — лучший подход (Эпли, равенство, только свой вес), итоги при пустой прошлой неделе,
  лига (друзья / процентиль / ничего), забытая группа, план, отсутствие пустых блоков.
- `recapPushBody` — приоритет и число фактов.
- `shouldPushRecap` / выбор недели — пояса, граница понедельника 09:00, вторник (нет push), просмотренные итоги.

e2e (`e2e/recap.spec.ts`, desktop + mobile; история — SQL через `e2e/db.ts`, понедельник — `?now=` у
`/api/cron/notifications`):
1. Тренировки и друг на прошлой неделе → тик в пн 09:00 → уведомление «Итоги недели», страница показывает место,
   прирост, лучший подход; повторный тик второго уведомления не создаёт.
2. Дашборд до 09:00 → карточка «новое» → открыл итоги → тик в 09:00 push не создаёт.
3. Пустая неделя после активной → один «новый старт»; следующая пустая — тишина.
4. Push доходит до фейкового push-сервиса (`e2e/push-server.ts`).
5. `notifyRecap` выключен → итоги есть, уведомления нет.

## Вне объёма

Шаринг и картинки для соцсетей; итоги в ленте друзей; итоги года (Wrapped — отдельная спецификация, переиспользует
`RecapData` и компоненты); email; настройка дня/часа отправки; пересчёт и миграция истории (итоги — с первой недели
после выкатки, на лету — не старше 8 недель).
