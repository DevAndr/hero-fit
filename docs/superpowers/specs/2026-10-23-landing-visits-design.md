# Счётчик заходов на лендинг в админке

## Зачем

В админке видны только регистрации по источникам («Источники регистраций», «Рекламные метки»), но не сколько людей
пришло. Без знаменателя нельзя сравнить страницы входа, источники, блогеров и кампании Директа по конверсии.
Яндекс.Метрика остаётся, но она не связана с нашими таблицами и режется блокировщиками.

## Что считаем

1. **Новые посетители** — первый заход гостя: ровно тот момент, когда `proxy.ts` ставит cookie `hf_src`
   (`tagSource`: гость, GET документа, публичная страница или ссылка-приглашение, cookie ещё нет). Ключ — та же пара
   `landing × referrer`, что потом попадает в `User.signupLanding`/`signupReferrer`, поэтому конверсия
   «посетитель → регистрация» честная по каждой паре.
2. **Переходы с меткой** — каждый GET документа гостем с меткой (там же, где ставится `hf_utm`; `utmOf`, `yclid` →
   `yandex_direct`). Ключ — `utm_source × utm_campaign`, как у `User.signupUtmSource`/`signupUtmCampaign`.

Повторный заход с очищенными cookie или из другого браузера — новый посетитель (как в Метрике). Боты не считаются:
`isBot(userAgent)` — пустой UA или совпадение с `bot|crawl|spider|slurp|curl|wget|python|httpclient|headless|lighthouse|preview|monitor`
(без учёта регистра). Cookie боту ставится как и раньше — меняется только счётчик.

## Данные

Только агрегаты, без IP, UA и идентификаторов: персональных данных нет, «Мои данные» и удаление аккаунта не
затрагиваются, `/privacy` не меняется (cookie те же).

```prisma
/// Новые посетители (первая точка входа, cookie hf_src) — счётчик за час UTC; метрики админки.
model LandingVisit {
  hour     DateTime @db.Timestamptz(3) // начало часа UTC
  landing  String
  referrer String
  count    Int

  @@id([hour, landing, referrer])
}

/// Переходы гостей по ссылкам с меткой — счётчик за час UTC; campaign "" — без кампании.
model LandingUtmVisit {
  hour     DateTime @db.Timestamptz(3)
  source   String
  campaign String
  count    Int

  @@id([hour, source, campaign])
}
```

Час UTC (а не день) — чтобы группировать по дням в поясе админа, как остальные ряды (`localDay`). Строк мало
(≤ 24 × пар в сутки), чистки нет.

**Защита от мусора в метках:** значения уже чистит `cleanUtm` (≤ 64 символа). Новая пара `source × campaign` при
200+ разных парах за текущие сутки UTC пишется как `source = "(прочие)"`, `campaign = ""` — одним SQL
(`INSERT … SELECT CASE WHEN … ON CONFLICT DO UPDATE SET count = count + 1`).

## Запись

- `lib/analytics/visits.ts` (server-only): `recordFirstVisit(landing, referrer)`, `recordUtmVisit(utm)` — upsert
  `count + 1`, ошибки ловятся и пишутся в лог (страница не падает).
- `proxy.ts`: в `tagSource` при установке `hf_src` / `hf_utm` и `!isBot(ua)` — промис в `event.waitUntil(...)`
  (второй аргумент `proxy(req, event)`), ответ не ждёт БД. Проверки «гость, GET, не фоновый запрос» — общие с cookie.
- Чистая `isBot` — в `lib/analytics/bots.ts` с unit-тестами.

## Админка

- `getDailySeries` — новый ряд `visitors` (сумма `LandingVisit.count` по дню `localDay(hour, tz)`); карточка
  `BarCard` «Новые посетители» рядом с «Регистрациями» (сетка 2 колонки: посетители, регистрации, тренировки…).
- «Источники регистраций»: колонки «Посетители» и «Конверсия» (регистрации / посетители, %) — у итога по странице
  входа и у вложенных источников. Пары с посетителями, но без регистраций, тоже видны (регистрации 0). Сортировка —
  по регистрациям, затем по посетителям. «До учёта» (`null`) — посетители «—».
- «Рекламные метки»: колонки «Переходы» и «Конверсия» по `utm_source` и вложенным `utm_campaign` (`""` → «без
  кампании»).
- Чистая `mergeVisitors(groups, visits)` в `lib/admin/metrics.ts`: дополняет `SourceGroup` полями
  `visitors: number | null`, `conversionPct: number | null` (null при 0 посетителей) и добавляет группы/строки только
  с посетителями. Регистрация за период могла прийти от посетителя до периода (cookie 30 дней) — конверсия
  приблизительная, конверсия > 100 % показывается как есть.
- Под таблицами — «Посетители считаются с <дата первой строки LandingVisit>», пока она позже начала периода.

## Тесты

- Unit: `isBot`; `mergeVisitors` (слияние, группы без регистраций, null-группа, конверсия, сортировка).
- e2e `e2e/landing-visits.spec.ts` (desktop): гость открывает `/?utm_source=e2e_<rnd>&utm_campaign=c1` — в БД +1
  переход по паре (через `e2e/db.ts`); повторный заход того же контекста — посетитель не прибавился, переход
  прибавился; UA бота — счётчики без изменений; админ (`makeAdmin`) видит строку `e2e_<rnd>` с переходами в
  «Рекламных метках». Посетителей проверяем дельтой в БД (база общая для воркеров).

## Не делаем

Просмотры всех страниц, уникальных посетителей по своей cookie, время на сайте, воронку по шагам регистрации, флаг
(только админка; ошибка записи не влияет на страницу).
