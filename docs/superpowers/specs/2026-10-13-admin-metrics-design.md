# Метрики в админке — дизайн

Дата: 2026-10-13. Ветка: `feat/admin-metrics` (от `release/2026-11-versioning`).

## Цель

Админ видит здоровье продукта: рост (регистрации), активность (DAU/WAU/MAU), тренировки, удержание новичков по недельным когортам и использование ключевых фич. Без внешних сервисов, цифры — живым SQL при открытии страницы.

## Решения

- **Живой SQL**, без снимков и тиков: база маленькая, страницу смотрит один админ.
- **Журнал заходов** `UserVisit` — для честного DAU и когорт по заходам. История есть только с момента деплоя; до него активность видна по тренировкам.
- **Пояс** — `User.timeZone` админа: сутки, недели (с понедельника) и диапазоны графиков считаются в нём.
- **Активный** пользователь за период = есть запись `UserVisit` с днём в периоде **или** завершённая тренировка (`Workout.status = COMPLETED`). День активности — **местный день игрока** (`UserVisit.day` пишется в его поясе, день тренировки — по `User.timeZone`), иначе «зашёл и тренировался» у игрока в далёком поясе разъезжается на два дня; границы периодов — в поясе админа. Линия «Тренировались» — тоже по дню игрока, график «Тренировки» и плитки тренировок — по дню админа.
- Демо- и тестовые учётки не исключаются (на проде их нет: сид не создаёт демо при `NODE_ENV=production`).

## Модель

```prisma
/// День посещения кабинета (местный день пользователя) — для метрик активности.
model UserVisit {
  userId String
  day    DateTime @db.Date
  user   User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@id([userId, day])
  @@index([day])
}
```

Запись — в `recordDailyVisit` (`lib/achievements/daily-visit.ts`) внутри существующей транзакции, когда условный `updateMany` по `lastLoginDay` вернул `count === 1`: `tx.userVisit.createMany({ data: [{ userId, day }], skipDuplicates: true })`, `day` — тот же `today`. Каскад от `User` — удаление аккаунта убирает журнал. В выгрузку «Мои данные» не входит (служебные данные); в `/privacy` — строка о журнале дней посещения для статистики сервиса.

## Страница `/admin` — «Метрики»

`app/(app)/admin/page.tsx`, `requireAdmin` (не админу — 404). Пункт «Метрики» в меню профиля админа — первым среди админских (перед «Флагами»). Период графиков — `?range=30|90` (иное → 30).

### Плитки

| Плитка | Значение | Сравнение |
|---|---|---|
| Пользователей | всего | — |
| Новые | сегодня / 7 дн / 30 дн | 7 и 30 дн — с предыдущими 7 / 30 днями |
| Активные | DAU (сегодня) / WAU (7 дн) / MAU (30 дн) | WAU, MAU — с предыдущими периодами |
| Тренировок | всего / 7 дн / 30 дн | 7 и 30 дн |
| Часов в зале | 30 дн (сумма `durationSec`) | с предыдущими 30 дн |
| Средняя тренировка | минут за 30 дн | — |

Дельта — `deltaPercent(now, prev)`: `prev = 0` → `null` (показывается «—»), иначе округлённый процент со знаком.

### Графики (за `range` дней, по дням)

1. Регистрации.
2. Активные: две линии — «заходили» (`UserVisit`) и «тренировались» (различные пользователи с завершённой тренировкой).
3. Завершённые тренировки.

Recharts через `components/ui/chart.tsx`, токены `--series-*`/`chart-*`, у каждого графика скрытая таблица в `div.sr-only`. Одна метрика — одна ось.

### Когорты

Строки — 8 последних недель регистрации (с понедельника, пояс админа), столбцы — неделя 0…6 после недели регистрации. Ячейка — % пользователей когорты, активных в эту неделю (определение «активного» выше), и размер когорты в первой колонке. Неделя ещё не наступила — пустая ячейка; пустая когорта — строка с «0» и прочерками. Интенсивность — фон `primary` с прозрачностью по проценту (текст остаётся контрастным).

### Фичи (срез «сейчас»)

- Тренеры: с режимом тренера / с хотя бы одним активным клиентом; клиентов с активной связью.
- Telegram: уведомления (`telegramChatId`) / вход в Mini App (`telegramId`).
- Push: пользователей с подпиской.
- Гильдии: гильдий / игроков в гильдиях.
- Клубы: одобренных клубов / участников.
- Цели: пользователей с активной целью.
- Магазин: купивших хоть один предмет / монет на балансах (сумма `User.coins`).
- Онбординг: прошли экскурсию (`onboardedAt` не null) из всех.

## Код

- `lib/admin/metrics.ts` — чистые функции: `deltaPercent`, `fillDays(rows, from, to)` (пропуски → 0), `cohortGrid(cohorts, cells, currentWeek)` → сетка с `null` для будущих недель, `dayRange`/`weekStart` через существующие хелперы поясов. Тест — `lib/admin/metrics.test.ts`.
- `lib/admin/metrics-queries.ts` (server-only) — `getOverview(tz)`, `getDailySeries(tz, range)`, `getCohorts(tz)`, `getFeatureUsage()`; агрегаты `$queryRaw` с границами в поясе (как `lib/stats/queries.ts`). Страница зовёт их через `Promise.all`.
- `components/admin/metric-tiles.tsx`, `components/admin/metrics-charts.tsx` (клиентский), `components/admin/cohort-table.tsx`, `components/admin/feature-usage.tsx`.

## Ошибки

Страница только читает; сбой запроса — обычная страница ошибки. Отдельной обработки нет.

## Тесты

- Unit: `deltaPercent` (рост, падение, `prev = 0`), `fillDays` (пропуски, границы), `cohortGrid` (будущие ячейки, пустая когорта, проценты).
- e2e `e2e/admin-metrics.spec.ts` (только desktop, `makeAdmin`): не админ — 404; админ видит плитки, графики и таблицу когорт; заход свежего пользователя пишет строку журнала (хелпер `visitDays` в `e2e/db.ts`).
- `e2e/account-data.spec.ts`: после удаления аккаунта строк `UserVisit` нет.
