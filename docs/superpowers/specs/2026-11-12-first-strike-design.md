# «Первый удар»: мини-тренировка сразу после регистрации

Дата: 2026-11-12. Флаг: `first_strike`.

## Зачем

Срез прода на 2026-11-09 (252 регистрации с 21.10): первую тренировку завершили 15 %, 112 человек собрали черновик и не начали его. Новичок регистрируется не в зале и уходит, не увидев игрового цикла: удар по боссу, опыт, ачивка.

«Первый удар» даёт пройти этот цикл в первую минуту: один подход упражнения без инвентаря, удар по боссу недели, XP и ачивка. После удара приложение ведёт к настоящей тренировке.

Успех — доля ударивших, которые потом завершили настоящую тренировку, выше, чем доля завершивших среди неударивших той же когорты. Метрика «завершил первую тренировку» не меняется: удар тренировкой не считается.

## Не делаем

- Таймер, обратный отсчёт, «сколько успеешь за минуту».
- Свои упражнения и упражнения из каталога: только три фиксированных.
- Повторные удары, удар как ежедневная механика.
- Офлайн-очередь: без сети удар не наносится.
- Упоминание на лендинге и в FAQ, пока флаг не включён всем.
- Учёт удара в серии недель, счётчике тренировок, статистике, лиге, гильдии, клубе, рейде, целях, восстановлении мышц, итогах недели.

## Данные

Миграция:

- `User.firstStrikeAt DateTime?` — момент удара; `null` — удара не было.
- `XpReason.FIRST_STRIKE` — новое значение перечисления.

Удар пишет одну запись `XpEvent`: `reason = FIRST_STRIKE`, `amount = FIRST_STRIKE_XP`, `meta = { exercise, value }`, где `exercise` — `squat | pushup | plank`, `value` — повторы (у планки секунды).

Новых таблиц и связей с `User` нет. Удаление аккаунта уже удаляет `XpEvent` каскадом. Выгрузка «Мои данные»: журнал XP уже выгружается (причина и сумма), дополнительно в профиль выгрузки добавляется `firstStrikeAt`.

## Правила — `lib/first-strike/rules.ts` (чистые функции)

- `FIRST_STRIKE_DAMAGE = 100` — как один рабочий подход (`SET_DAMAGE`).
- `FIRST_STRIKE_XP = 30`.
- `STRIKE_EXERCISES`: `squat` «Приседания», `pushup` «Отжимания», `plank` «Планка» (единица — секунды).
- `canStrike({ flag, firstStrikeAt, completedWorkouts })` — `true`, если флаг включён, `firstStrikeAt = null` и завершённых тренировок 0. Растяжка (`stretchOnly`) завершённой тренировкой здесь не считается.
- `parseStrike(exercise, value)` — упражнение из списка; повторы целые 1–200, секунды планки целые 5–600. Иначе ошибка с текстом для формы.

Введённое число на награду не влияет.

## Сервер — `lib/first-strike/actions.ts`

`firstStrikeAction({ exercise, value })`:

1. `requireUser()`, проверка флага, `parseStrike`.
2. Транзакция:
   - проверка, что завершённых обычных тренировок нет;
   - `updateMany` по `User` с условием `firstStrikeAt = null` → `firstStrikeAt = now`. `count = 0` — ответ `{ ok: false, error: "Первый удар уже нанесён" }`, наград нет;
   - `XpEvent` и прибавка `User.xp`;
   - `getOrCreateBossWeek` текущей недели; если урон недели с ударом ≥ HP — победа тем же условным `updateMany` по `defeatedAt`, что в `finishWorkout` (при минимальном HP 3000 на практике недостижимо, но правило одно).
3. После транзакции — `evaluateAchievements` (ачивка) и `queueGoal("first_strike")`.
4. Ответ: `{ ok: true, xp, damage, boss: BossView, level до/после, achievement }` — всё, что нужно экрану результата (включая признак черновика и готовые программы). `revalidatePath` не вызывается: экран результата живёт в диалоге, страницу обновляет клиент при его закрытии.

Условное обновление делает удар идемпотентным: вторая вкладка и повторный запрос награду не получают.

## Урон боссу

`weekDamage` (урон одной недели) прибавляет `FIRST_STRIKE_DAMAGE`, если `User.firstStrikeAt` попадает в эту неделю в поясе `tz`. Так удар виден в `BossCard`, `BossBar`, сводке и при завершении тренировки (`applyBoss` считает через `weekDamage`).

`damageByWeek` не меняется, поэтому удар не входит в историю для расчёта HP будущих боссов (`getOrCreateBossWeek`) и в бестиарий. Расхождение бестиария с карточкой на 100 урона в неделю удара — принимаем.

## Ачивка

`firststrike:1` «Первый удар», категория — та же, что у босса, обычная награда ачивки младшего порога. В `AchievementStats` — поле `firstStrike: boolean` (из `User.firstStrikeAt`). Цель среди «ближайших ачивок» не показывается: у тех, кто уже тренируется, удара не будет никогда.

## Интерфейс

Компонент `components/first-strike/first-strike-dialog.tsx` — один диалог на оба входа.

**Экран 1 — удар.** Заголовок «Первый удар», строка «Сделай один подход прямо сейчас — и босс получит первый удар». Три кнопки-переключателя упражнения (по умолчанию «Приседания»), поле «Повторы» / «Секунды» (числовое, с `selectOnFocus`, по умолчанию 10 / 30), кнопка «Ударить». Ошибка сервера или сети — текст под кнопкой, диалог не закрывается.

**Экран 2 — результат.** Спрайт босса вздрагивает, всплывает «−100» (приём из `BossBar`, с учётом «уменьшить движение»), полоса HP, полоса XP (`XpBar`) с «+30 XP», плашка ачивки. Кнопки:

- главная — «Продолжить черновик» (ссылка на `/training`), если есть тренировка `PLANNED` или `IN_PROGRESS`; иначе список готовых программ `FirstWorkout` (тот же, что в финале экскурсии);
- «Позже» — закрывает диалог.

**Вход из экскурсии.** На шаге `boss` при `canStrike` рядом с «Дальше» — кнопка «Ударить сейчас». Она завершает экскурсию (`completeOnboardingAction("done")`) и открывает диалог. Выбор программы на экране результата заменяет финальный шаг экскурсии.

**Вход из кабинета.** Карточка «Первый удар» над героем недели при `canStrike`: спрайт босса, «Нанеси первый удар боссу — один подход без инвентаря, 2 минуты», кнопка «Ударить». Пока экскурсия не пройдена, карточка не показывается (её роль играет шаг экскурсии). После удара или первой завершённой тренировки карточка исчезает навсегда.

Данные для показа — `getStrikeOffer(user)`: `firstStrikeAt` добавляется в `requireUser()`, а счётчик завершённых тренировок запрашивается только у тех, у кого флаг включён и удара ещё не было.

Вход из экскурсии ведёт на `/dashboard?strike=1`: параметр открывает диалог сразу. Диалог и результат удара хранит клиентский хост на дашборде, поэтому обновление страницы после удара диалог не закрывает.

## Тесты

Unit: `canStrike`, `parseStrike`, реестр флагов, цель Метрики, выгрузка (`firstStrikeAt`).

E2e (`e2e/first-strike.spec.ts`, флаг включается пользователю по списку):

- удар из экскурсии: шаг босса → «Ударить сейчас» → результат «−100», «+30 XP», ачивка; экскурсия пройдена;
- удар с карточки кабинета; после удара карточки нет, у босса на 100 HP меньше;
- повтор из второй вкладки — «уже нанесён», в `XpEvent` одна запись `FIRST_STRIKE`;
- у пользователя с завершённой тренировкой карточки и кнопки в экскурсии нет;
- серия недель и счётчик тренировок после удара не изменились; ачивки `workouts:1` нет;
- неверный ввод (0, 201, пусто) — ошибка, удар не засчитан;
- без флага ничего не показывается;
- «Мои данные» содержат удар, удаление аккаунта проходит.
