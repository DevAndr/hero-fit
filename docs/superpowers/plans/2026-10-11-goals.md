# Цели — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Пользователь ставит цели (сила, тренировки, серия, часы, вес тела) со сроком или без, видит прогресс на `/goals`, получает сундук 100 XP за выполнение.

**Architecture:** `Goal` хранит условие и стартовое значение; текущее значение каждый раз считается из существующих данных (`PersonalRecord`, тренировки, `User.currentStreak`, `BodyWeightEntry`). Выполнение — в транзакции `finishWorkout`, при взвешивании и в фоновом тике (там же провал по сроку). Чистые правила — `lib/goals/rules.ts`, БД — `queries.ts`/`apply.ts`/`actions.ts`/`tick.ts`.

**Tech Stack:** Next.js 16, Prisma 7 (`@/generated/prisma/client`), Zod, Vitest, Playwright, shadcn/ui (Base UI), recharts.

**Spec:** `docs/superpowers/specs/2026-10-11-goals-design.md`

## Global Constraints

- Ветка `feat/goals` (от `release/2026-10-raids`); в конце — merge `--no-ff` в релизную ветку, ветку удалить.
- `GOALS_ACTIVE_MAX = 5`; цель `BODY_WEIGHT` — одна активная; `GOAL_CHEST_XP = 100`.
- Пределы цели: `STRENGTH` вес/1ПМ 1…500 кг (шаг 0,5), повторы 1…500 (целое); `WORKOUTS` 1…1000; `STREAK` 1…104; `HOURS` 1…2000; `BODY_WEIGHT` 30…300 (шаг 0,1); взвешивание 30…300.
- Срок — местная дата `"YYYY-MM-DD"` в `User.timeZone`: не раньше завтра, не позже 2 лет; конец срока — `localMidnight(день после срока, tz)` (`lib/progress/weekly-streak.ts`), провал тиком — с форой 12 ч.
- Тексты отказов дословно: «Максимум 5 активных целей», «Цель по весу уже есть», «Уже достигнуто», «Для упражнения со своим весом — только повторы».
- Ачивки `goal:1/5/10/25` «Целеустремлённый», категория `GOAL`; титул `ach:goal:25` — «Человек слова».
- Вес тела никогда не попадает в ленту; `hideWeights` убирает килограммы силовых целей на сервере. Тренеру `hideWeights` не применяется.
- Перевод статуса — только условный `updateMany … where { id, status: ACTIVE }`; сундук — условный по `chestOpenedAt: null`.
- Тип TS для строки цели — `GoalRow` (имя `Goal` уже занято в `lib/analytics/goals.ts`).
- Цвета — только семантические токены; ссылка-кнопка — `<Link className={buttonVariants()}>`; у графика — скрытая таблица в `div.sr-only`.
- e2e: даты — через `E2E_TZ`/`localAt`; сценарии с двумя контекстами — `--workers=8`.

## Review Focus

- Офлайн-тренировка, завершённая до срока, приходит после конца дня срока (в пределах 12 ч) — цель должна засчитаться, а не провалиться (тест в Task 4: тик не проваливает в форе; Task 3: `applyGoals` сравнивает с `workout.finishedAt`).
- Пояс пользователя восточнее/западнее UTC — срок кончается в местную полночь, не в UTC (тест `deadlineEnd` в Task 1 с `Asia/Tokyo` и `America/Los_Angeles`).
- Двойной клик «Открыть сундук» / две вкладки — XP начисляется один раз (e2e в Task 5: второй вызов действия возвращает отказ).
- Упражнение архивировано после постановки цели — страница целей не падает, цель показывает имя упражнения (запрос без фильтра `archivedAt`; тест в Task 2 `getCurrentValues` не зависит от архива — проверяется в e2e Task 5).
- Цель по весу, стартовый вес равен цели или взвешивание «перелетело» цель — отказ «Уже достигнуто» / выполнение, прогресс не больше 100 % (тесты `goalProgress`/`canCreate` в Task 1).
