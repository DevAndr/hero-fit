# Обратная связь — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** пользователь пишет админу (ошибка / идея / другое) на `/feedback`, админ разбирает на `/admin/feedback`, при «сделано»/«отклонено» пользователь получает уведомление.

**Architecture:** таблица `Feedback`, чистые правила и схемы в `lib/feedback/*`, server actions за `requireUser`/`requireAdmin`, уведомление — существующий `notify`, сигнал админам — общий `sendAdminTelegram`, выделенный из `lib/errors/notify.ts`.

**Tech Stack:** Next.js 16, Prisma 7, Zod, shadcn/ui (Base UI), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-18-feedback-design.md`

## Global Constraints

- Ветка `feat/feedback` от `release/2026-12-alerts`; в конце — `git merge --no-ff` в релизную ветку.
- Интерфейс по-русски; цвета — семантические токены; ссылка-кнопка — `<Link className={buttonVariants()}>`.
- `body` 10–2000 после `trim`; `adminNote` ≤ 1000; `userAgent` ≤ 300; `page` — путь `/…` (не `//`) ≤ 200 без query/hash.
- `FEEDBACK_DAILY_MAX = 5` за скользящие 24 ч; `FEEDBACK_ALERTS_HOURLY = 20`.
- Уведомление только при переходе в `DONE`/`REJECTED` из другого статуса; условное `updateMany({ where: { id, status: prev } })`.
- Telegram админам — без текста обращения и автора (152-ФЗ).
- Новая связь с `User`: «Мои данные» (раздел `feedback` без `adminNote`/`userAgent`/id) и удаление аккаунта (каскад) — `e2e/account-data.spec.ts`.
- Миграция: в SQL нет DROP частичных индексов `CoachLink_active_client`, `CoachComment_workout_general`, `CoachSignal_open`.

## Review Focus

- Текст с переводами строк и очень длинным словом — карточки не ломают вёрстку на 390 px (`break-words`, `whitespace-pre-line`) — проверка скриншотом в Task 2 и Task 3.
- `?from=` с внешним адресом или мусором — форма работает, `page` пустой — unit `cleanPage` в Task 1 и e2e в Task 2.
- Двойной клик «Отправить» — одно обращение (кнопка `disabled` в pending) — e2e в Task 2.
- Админ возвращает «Сделано» → «В работе» → «Сделано» — второе уведомление приходит (это осознанно: `prev !== next`) — unit `shouldNotify` в Task 1.
- Удалённый пользователь — его обращения исчезают из админки, страница не падает — e2e удаления в Task 1.
